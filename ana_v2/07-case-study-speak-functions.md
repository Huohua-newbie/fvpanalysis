# 07 · 案例：SPEAK 函数族分析

> **前置阅读**：[03 · VM 与指令集](./03-vm-and-opcodes.md)、[04 · Syscall 系统](./04-syscall-system.md)

本文以 `Sakura.hcb` 前半段的 SPEAK 函数族为例，演示如何读懂一段实际的 HCB 代码——这些函数控制文本框左侧的**说话人名显示**，是视觉小说剧情系统的核心组件之一。

---

## 什么是 SPEAK 函数？

`Sakura.hcb` 开头定义了 34 个结构相似的函数，分别对应不同角色的名字显示逻辑。每个函数负责：

1. 设置名字栏样式（颜色、字号、位置）
2. 根据参数决定显示"正常名字"还是"？？？（未知）"
3. 同步某些全局状态计数器
4. 写入特定全局变量，触发后续文本打印

---

## 函数签名统一模式

所有 SPEAK 函数都接收 **3 个参数**：

```lua
function SPEAK_CharacterName(a0, a1, a2)
```

推测含义（根据使用模式）：

- `a0`：未知（可能是调用来源标识）
- `a1`：与 `G[293]` 关联（可能是文本 buffer ID 或相关参数）
- `a2`：**名字显示模式**
  - `-1`：显示"？？？"（未知角色）
  - `0` 或其他：显示正常名字

---

## 典型 SPEAK 函数的四段式结构

以 `f_00000004`（クロ的名字显示函数）为例，拆解其执行流程。

### 第一段：设置样式编号，调用样式初始化函数

```lua
S0 = 1                     -- 样式编号
G[227] = S0                -- 写入全局变量 G[227]
S0 = G[227]
__ret = f_000019E0(S0)     -- 调用样式初始化函数
```

`G[227]` 存放的不是"名字字符串"，而是**名字栏样式类别编号**。`f_000019E0` 是一个配置函数，根据编号设置文本颜色、字号、输出方式（`TextColor` / `TextOutSize` 等 syscall）。

不同角色用不同编号：

| 角色 | 样式编号 (`G[227]`) |
|---|---:|
| クロ | 1 |
| ハル | 2 |
| 千和 | 3 |
| 姫織 | 4 |
| ましろ | 5 |
| 十夜 | 6 |
| … | … |

### 第二段：检查状态计数器，决定是否递增

```lua
S0 = G[2001]               -- 读取全局计数器
S1 = 0
S0 = (S0 == S1)            -- 判断是否为 0
S1 = G[2001]
S2 = 2
S1 = (S1 == S2)            -- 判断是否为 2
S0 = ((S0 ~= nil) or (S1 ~= nil))  -- or
-- ... （继续判断 4、6）
if __is_nil(S0) then goto next_block end

-- 若条件满足，递增计数器
S0 = G[2001]
S1 = 1
S0 = (S0 + S1)
G[2001] = S0
```

这段逻辑检查 `G[2001]` 是否等于 `{0, 2, 4, 6}` 中的任意一个，若是则递增 1。

推测：这是某种**剧情进度计数器**或**特定事件触发计数**。每个角色有自己的专属计数器（`G[2001]` 对应クロ，`G[2002]` 对应ハル，以此类推）。

### 第三段：根据 `a2` 决定显示什么名字

```lua
S0 = a2                    -- 读取第 3 个参数
S1 = 1
S1 = -S1                   -- S1 = -1
S0 = (S0 == S1)            -- 判断 a2 == -1
if __is_nil(S0) then goto show_normal_name end

-- 若 a2 == -1，显示 "？？？"
S0 = "　 ？？？ 　"        -- 原始名字（用于历史记录？）
S1 = "　？クロ　　"        -- 显示名字（带 ？）
__ret = f_0004CCDA(S0, S1)
S0 = G[227]
S1 = true
__ret = f_000977B8(S0, S1)
goto end_block

::show_normal_name::
S0 = "　　クロ　　"
S1 = nil
__ret = f_0004CCDA(S0, S1)
-- ... 再次检查计数器并可能递增
```

关键调用：

- **`f_0004CCDA(original_name, display_name)`**：疑似"设置名字栏文本"的函数，第一个参数可能是"完整名字"（用于历史记录），第二个参数是"当前显示名字"（带？或不带？）。
- **`f_000977B8(style_id, flag)`**：疑似"应用名字栏样式并显示"的函数。

### 第四段：写入全局变量，准备文本打印

```lua
S0 = 1
G[29] = S0                 -- 固定写 1，可能是"名字栏已准备"标志
S0 = a1
G[293] = S0                -- 写入 a1
S0 = a3                    -- ⚠️ 注意这里读的是 a3，但函数签名只有 a0/a1/a2
G[294] = S0
S0 = 1                     -- 角色 ID？
__ret = f_0008D409(S0)     -- 调用某个最终提交函数
S0 = __ret
G[295] = S0
```

推测：

- `G[29]`：名字栏就绪标志
- `G[293]` / `G[294]` / `G[295]`：与文本打印系统配合的参数传递槽
- `f_0008D409(character_id)`：最终提交函数，可能触发文本框布局、名字栏渲染等

---

## 34 个 SPEAK 函数的差异

所有 34 个函数结构几乎相同，只有以下几处不同：

1. **样式编号**（`G[227]` 写入的值）
2. **计数器变量**（`G[2001]`、`G[2002]`、……、`G[2011]`）
3. **名字字符串**（`"クロ"` / `"ハル"` / `"千和"` / …）
4. **传给 `f_0008D409` 的角色 ID**

这是典型的"模板函数"——用手工复制粘贴生成的重复代码，而不是用高级语言的参数化抽象。原始脚本语言很可能不支持动态字符串或高阶函数。

---

## 函数边界识别

所有这些函数都以 **`init_stack 3,0`** 开头：

```
01 03 00   init_stack args=3 locals=0
```

这正是 CFG 工具用 `init_stack` 做函数识别启发式的依据——在 FVP 里，函数边界非常规整。

---

## 调用点示例

假设剧情脚本中某处要显示クロ的台词：

```lua
-- 调用 SPEAK 函数
__ret = f_00000004(0, text_buffer_id, name_display_mode)

-- 然后打印台词
S0 = text_buffer_id
S1 = "今日も晴れだね"
__ret = __syscall("TextPrint", S0, S1)
```

流程：
1. SPEAK 函数设置名字栏样式和文本
2. `TextPrint` 打印台词本体
3. 线程进入 `TEXT_WAIT`，等待玩家点击

---

## 为什么要单独分析 SPEAK 函数？

1. **它们占了 HCB 开头很大一段空间**（34 个函数 × 200+ 字节，约 6.6 KB）；
2. **它们是理解 FVP 文本系统的关键入口**；
3. **它们的重复结构很适合用来验证反汇编工具的正确性**——34 个函数的字节码应该只有少数几处不同，其余一模一样。
