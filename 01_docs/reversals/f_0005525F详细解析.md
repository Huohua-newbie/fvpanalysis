# [`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 详细解析

## 1. 核心结论

[`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 是 Sakura.hcb 中的一个**音频停止/淡出时序包装器**。

它自身没有直接调用 Audio syscall，主体只有一次函数转发：

```lua
function stop_bgm_with_delay(base_time)
    f_0005522A(base_time)
end
```

真正的音频停止逻辑位于 [`f_0005522A()`](Sakura_hcb_ir/Sakura/f_0005522A.lua:1)：

```lua
function stop_current_audio(base_time)
    if base_time == nil then
        stop_time = 4500
    else
        stop_time = base_time + 2000
    end

    G[215] = 0
    AudioStop(G[214], stop_time)
    AudioStop(G[213], stop_time)
end
```

因此，最准确的功能标签是：

> **停止当前新旧两路音频槽，并清除当前 BGM 编号；唯一参数是音频停止时序的基准值。**

它不是播放函数、不是音量函数，也不是单独停止某一个 Audio 槽的底层 syscall。它会通过下游同时停止 [`G[214]`](Sakura_hcb_ir/Sakura/f_0005522A.lua:21) 和 [`G[213]`](Sakura_hcb_ir/Sakura/f_0005522A.lua:24) 对应的两路音频。

## 3. 原始反编译代码

[`f_0005525F.lua`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 的主体如下：

```lua
function f_0005525F(a0)
  local S0, S1, S2
  ::BB_0005525F:: -- block 0, succs=[]
  -- init_stack args=1 locals=0
  S0 = a1
  __ret = f_0005522A(S0)
  return
  ::BB_0005526A:: -- block 1, succs=[]
  return
end
```

逐条解释：

| 顺序 | 指令/IR | 含义 |
|---:|---|---|
| 1 | `init_stack args=1 locals=0` | 建立一个真实入参、无显式局部变量的栈帧 |
| 2 | `push_stack -2` | 读取唯一真实入参 |
| 3 | `call f_0005522A` | 将该参数原样传给音频停止核心 |
| 4 | `ret` | 返回，无业务返回值 |

该函数没有条件分支、没有循环、没有直接 syscall，也没有对参数进行任何修改。

## 4. 参数编号勘误

### 4.1 唯一真实参数不是导出文本中的 `a1`

函数头显示为：

```lua
function f_0005525F(a0)
```

但函数体读取：

```lua
S0 = a1
```

实际原始访问是负栈槽：

```text
push_stack -2
```

对于 `init_stack args=1` 的函数，正确映射为：

```text
push_stack -2 -> 唯一真实参数 a0
```

因此本文使用 `P1` 或 `base_time` 表示它，避免受到旧 Lua-like 导出器参数编号偏移影响。

| 真实参数 | 原始栈槽 | 导出器名称 | 推荐名称 |
|---|---:|---|---|
| `P1` | `-2` | `a1` | `base_time` |

### 4.2 不能把它理解为第二个隐藏参数

`f_0005525F()` 没有第二个真实入参。`a1` 只是导出器将第一个真实参数错误标成了 `a1`。

因此：

```lua
f_0005525F(6500)
```

的 `6500` 就是唯一参数，而不是某个后续调用的第二参数。

## 5. 下游 `f_0005522A()` 的完整逻辑

[`f_0005522A()`](Sakura_hcb_ir/Sakura/f_0005522A.lua:1) 的完整主体是：

```lua
function f_0005522A(base_time)
    if base_time == nil then
        stop_time = 4500
    else
        stop_time = base_time + 2000
    end

    G[215] = 0
    AudioStop(G[214], stop_time)
    AudioStop(G[213], stop_time)
end
```

对应反编译行：

```lua
if a1 == nil then
    a1 = 4500
else
    a1 = a1 + 2000
end
G[215] = 0
AudioStop(G[214], a1)
AudioStop(G[213], a1)
```

见 [`f_0005522A.lua`](Sakura_hcb_ir/Sakura/f_0005522A.lua:5-26)。

### 5.1 `nil` 分支

当调用：

```lua
f_0005525F(nil)
```

下游得到：

```text
stop_time = 4500
```

然后执行：

```text
AudioStop(G[214], 4500)
AudioStop(G[213], 4500)
```

所以 `nil` 不是“立即停止”，而是使用固定的 `4500` 停止时长。

### 5.2 非 `nil` 分支

当传入数值 `t` 时：

```text
stop_time = t + 2000
```

然后同样对两路音频槽执行 `AudioStop`。

例如：

| `f_0005525F()` 入参 | 下游实际停止时长 |
|---:|---:|
| `nil` | `4500` |
| `0` | `2000` |
| `950` | `2950` |
| `2950` | `4950` |
| `6500` | `8500` |
| `8950` | `10950` |
| `10450` | `12450` |

这点需要特别强调：

> **非 `nil` 参数不是直接的 `AudioStop` 时长，而是一个会在下游额外加 `2000` 的基准值。**

历史分析文档中曾将 `6500` 解释为最终 `8500` 之外的其它值；以当前反编译代码为准，准确公式是 `t + 2000`。

### 5.3 参数单位

从调用位置和它被传给 `AudioStop` 的方式看，`base_time` / `stop_time` 应按时间值理解，单位很可能是毫秒。

但需要区分：

- `f_0005525F()` 的入参：上层基准时间；
- `f_0005522A()` 计算出的 `stop_time`：实际传给 `AudioStop` 的停止/淡出时长。

最保守的命名是：

```text
base_time / stop_time_ms
```

不宜把 `f_0005525F()` 的参数直接命名为 `fadeout_ms`，因为它还会经过 `+2000` 转换。

## 6. 第一项实际副作用：清除 `G[215]`

下游在停止音频前执行：

```lua
G[215] = 0
```

对应 [`f_0005522A.lua`](Sakura_hcb_ir/Sakura/f_0005522A.lua:18-20)。

### 6.1 `G[215]` 的含义

在 BGM 播放核心 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:14-20) 中，`G[215]` 被用作当前 BGM 编号缓存：

```lua
if G[215] == track_id then
    return
end
G[215] = track_id
```

因此：

```text
G[215] = 当前已记录的 BGM 编号
```

[`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 通过下游将它清零，表示：

> **当前不再有有效的 BGM 编号记录。**

### 6.2 为什么必须清除 `G[215]`

如果不清除 `G[215]`，后续再次请求播放同一首 BGM 时，`f_0005511C()` 可能误判：

```lua
G[215] == track_id
```

然后直接返回，导致音频没有重新加载或播放。

所以音频收尾不只是停止声道，还必须同步清空“当前曲目编号”缓存。

### 6.3 `G[215] = 0` 不是停止某一个槽位

`G[215]` 是曲目编号状态，不是 Audio 槽编号。

实际停止槽位的是：

```lua
G[214]
G[213]
```

三者职责不同：

| 全局槽 | 作用 |
|---|---|
| `G[213]` | 当前/新 BGM 使用的 Audio 槽 |
| `G[214]` | 旧 BGM 使用的 Audio 槽 |
| `G[215]` | 当前 BGM 曲目编号缓存 |

## 7. 第二项实际副作用：停止两路 Audio 槽

下游连续执行：

```lua
AudioStop(G[214], stop_time)
AudioStop(G[213], stop_time)
```

对应 [`f_0005522A.lua`](Sakura_hcb_ir/Sakura/f_0005522A.lua:21-26)。

### 7.1 为什么要停止两路

[`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:40-54) 使用双槽交替机制：

```text
G[213] -> 新 BGM 槽
G[214] -> 旧 BGM 槽
```

切换 BGM 时，新旧曲目可能分别处于两个 Audio 槽中。只停止一个槽会留下残音或旧曲目继续播放。

因此 [`f_0005522A()`](Sakura_hcb_ir/Sakura/f_0005522A.lua:21-26) 不判断哪个槽当前有声音，而是对两路都执行停止：

```text
停止旧槽
停止新槽
```

这是一个面向全局 BGM 状态的统一收尾函数。

### 7.2 `AudioStop` 的参数含义

根据 Audio syscall 语义，形式是：

```lua
AudioStop(channel, fadeout)
```

第一个参数是 Audio 槽位号，第二个参数是停止/淡出相关的时间参数。

因此：

```lua
AudioStop(G[214], stop_time)
```

不能理解成：

```text
停止编号为 G[214] 的 BGM
```

而应理解为：

```text
停止 Audio 槽 G[214] 中的音频
```

## 8. `f_0005526B()`：立即收音包装器

相邻函数 [`f_0005526B()`](Sakura_hcb_ir/Sakura/f_0005526B.lua:1) 是：

```lua
function f_0005526B()
    f_0005522A(1)
end
```

它固定传入 `1`，所以实际停止时长为：

```text
1 + 2000 = 2001
```

这说明 `f_0005526B()` 不是调用 `f_0005525F(nil)` 的同义替代品：

| 函数 | 下游基准 | 实际停止时长 |
|---|---:|---:|
| `f_0005525F(nil)` | `nil` | `4500` |
| `f_0005526B()` | `1` | `2001` |

因此 `f_0005526B()` 更接近一个“较快停止”或“短停止窗口”的专用入口。

### 8.1 为什么不能把 `f_0005526B()` 叫成立即停止

实际时长仍为 `2001`，并非 0。因此更稳妥的名称是：

```text
short_audio_stop()
```

而不是：

```text
AudioStopImmediately()
```

## 9. 调用样本与时序语义

### 9.1 `nil` 调用：常规剧情收尾

大量主剧情 function 使用：

```lua
f_0005525F(nil)
```

例如 [`f_000A2981.lua`](Sakura_hcb_ir/Sakura/f_000A2981.lua:1270-1271) 和 [`f_000DB147.lua`](Sakura_hcb_ir/Sakura/f_000DB147.lua:882-883)。

这表示：

```text
清除当前 BGM 编号
-> 对新旧两路 Audio 槽使用固定 4500 的停止窗口
-> 后续继续剧情或其它清场流程
```

### 9.2 与 `f_000104E8()` 连续调用

常见结构：

```lua
f_0005525F(nil)
f_000104E8()
```

例如 [`f_0049F256收尾片段解析.md`](f_0049F256收尾片段解析.md:117-153) 所记录的结构。

这说明：

1. 先处理听觉层，停止 BGM；
2. 再进入 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1) 的重型画面清场和过渡准备。

因此 `f_0005525F()` 是收尾链中的“音频撤场层”，不负责画面清场。

### 9.3 传入计算值：根据演出时间安排停止

部分调用不是固定 `nil`，而是：

```lua
S0 = 6500
__ret = f_0005525F(S0)
```

或：

```lua
S0 = 6500
S1 = 1000
S0 = S0 + S1
__ret = f_0005525F(S0)
```

这种写法说明调用方会根据前一段演出、对白或等待时间动态构造基准值，然后由 `f_0005522A()` 再加 `2000`，形成最终 AudioStop 时长。

例如：

```text
演出基准 = 6500
下游补偿 = 2000
实际停止时长 = 8500
```

这更像是把音频停止安排到整个演出尾声之后，而不是简单地“淡出 6500 ms”。

### 9.4 与文本/演出结束的关系

从调用位置看，`f_0005525F()` 经常出现在：

- 一段较长文字之后；
- 一轮 CG/演出之后；
- [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1) 之前；
- [`f_00055D3D()`](Sakura_hcb_ir/Sakura/f_00055D3D.lua:1) 或其它 dissolve 之前。

因此其参数很可能用于让 BGM 在视觉过渡完成前后保持一段时间，再逐步停止。

但目前只能确认代码层面的计算关系，不能仅凭调用点断言每个数值都对应某个具体剧情动画的精确时长。

## 10. 与其它音频函数的分工

### 10.1 与 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1) 的关系

| 函数 | 作用 |
|---|---|
| [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1) | 播放/切换指定 BGM，加载资源、设置音量、播放新槽、安排旧槽停止 |
| [`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) | 停止当前新旧两路音频，并清除当前曲目编号 |
| [`f_0005522A()`](Sakura_hcb_ir/Sakura/f_0005522A.lua:1) | 执行真正的双槽 AudioStop 和 `G[215]` 清零 |
| [`f_0005526B()`](Sakura_hcb_ir/Sakura/f_0005526B.lua:1) | 以固定基准 `1` 调用停止核心 |

可以概括为：

```text
f_0005511C -> 建立/切换 BGM 状态
f_0005525F -> 拆除/结束 BGM 状态
```

### 10.2 与 [`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 的区别

[`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 主要清除环境声相关状态，例如 `G[273]`；而 `f_0005525F()` 处理的是主 BGM/长音频双槽和 `G[215]`。

因此：

```text
f_00055113 -> 环境声状态失效
f_0005525F -> 主 BGM 双槽停止
```

### 10.3 与 [`f_00055A57()`](Sakura_hcb_ir/Sakura/f_00055A57.lua:1) 的区别

已有收尾分析中常见：

```lua
f_0005525F(t)
f_00055A57(...)
```

前者负责 BGM/音频槽停止，后者属于其它过渡、声音或演出收束链。两者连续出现时，不应把它们合并成一个 AudioStop 函数。

## 12. 对新剧情注入的意义

### 12.1 想按原作方式停止 BGM

推荐直接调用：

```lua
f_0005525F(nil)
```

这样会：

- 清除 `G[215]`；
- 停止 `G[214]`；
- 停止 `G[213]`；
- 使用默认停止时长 `4500`。

### 12.2 想安排更长的停止窗口

如果希望实际停止时长为 `T`，应传入：

```text
base_time = T - 2000
```

例如希望实际 `8500`：

```lua
f_0005525F(6500)
```

因为：

```text
6500 + 2000 = 8500
```

### 12.3 想使用较短停止窗口

可以参考：

```lua
f_0005526B()
```

其实际时长约为：

```text
1 + 2000 = 2001
```

但这仍不是立即停止，是否适合具体演出要结合实机表现。

### 12.4 不要只调用一个 AudioStop

如果新剧情只执行：

```lua
AudioStop(G[213], t)
```

可能留下旧槽 `G[214]` 的残音。

如果只执行：

```lua
G[215] = 0
```

则只是清除了曲目缓存，不能真正停止音频。

原作包装器的完整收尾至少包含：

```lua
G[215] = 0
AudioStop(G[214], stop_time)
AudioStop(G[213], stop_time)
```

## 13. 最终结论

1. [`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 是一个单参数音频停止包装器。
2. 它自身不直接调用 Audio syscall，只把唯一参数转发给 [`f_0005522A()`](Sakura_hcb_ir/Sakura/f_0005522A.lua:1)。
3. 唯一真实参数来自原始栈槽 `-2`，导出文本中的 `a1` 是参数编号偏移，不是第二个参数。
4. 参数推荐命名为 `base_time`，而不是直接命名为 `volume` 或 `fadeout_ms`。
5. `base_time == nil` 时，实际停止时长固定为 `4500`。
6. `base_time != nil` 时，实际停止时长为 `base_time + 2000`。
7. 下游会把 `G[215]` 清零，表示当前 BGM 编号失效。
8. 下游会同时停止 `G[214]` 和 `G[213]` 两路 Audio 槽。
9. `G[213]` / `G[214]` 是双槽音频状态，`G[215]` 是当前曲目编号缓存，三者不能混淆。
10. `f_0005525F(nil)` 是常规 BGM 收尾入口，`f_0005526B()` 是固定短停止窗口入口。
11. 该函数常与 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1)、[`f_00055D3D()`](Sakura_hcb_ir/Sakura/f_00055D3D.lua:1) 等画面清场/过渡函数连续出现，承担听觉层撤场职责。
12. 它没有有意义的返回值，所有价值都体现在 BGM 状态清理和双槽停止的副作用上。

最准确的一句话概括是：

> **`f_0005525F(base_time)` 通过 `f_0005522A()` 清除当前 BGM 编号，并以 `4500` 或 `base_time+2000` 的停止时长同时收束新旧两路音频槽。**
