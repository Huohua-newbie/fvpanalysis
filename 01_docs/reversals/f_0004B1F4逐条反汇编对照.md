# [`f_0004B1F4()`](Sakura_hcb_ir/Sakura/f_0004B1F4.lua:1) 逐条反汇编与作用分析

## 1. 函数定位与总体结论

- 原始函数：[`f_0004B1F4.lua`](Sakura_hcb_ir/Sakura/f_0004B1F4.lua:1)
- HCB：[`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb)
- IR：[`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json)
- 函数地址范围：`0x0004B1F4–0x0004B21A`
- HCB 文件偏移：`307700–307738`
- 字节长度：`39` 字节
- 函数序言：`init_stack args=1, locals=0`
- 显式入参数量：`1`
- 局部变量数量：`0`
- 直接调用的内部函数：无
- 直接调用的 syscall：无

本函数不是文本绘制函数，也不是窗口创建函数。它是一个非常薄的**背景/场景装载模式全局变量设置器**：

1. 读取唯一入参；
2. 只接受 `0`、`1`、`2` 三个整数值；
3. 对 `nil`、负数以及大于等于 `3` 的值统一归一化为 `nil`；
4. 若归一化后仍非 `nil`，则写入 `G[1250]`；
5. 若归一化后为 `nil`，则不改写 `G[1250]`。

在原作的常见调用中，调用者传入 `0`：

```lua
f_0004B1F4(0)
```

这会产生：

```lua
G[1250] = 0
```

之后，背景装载函数例如 [`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:84) 会读取 `G[1250]`，并在特定差分判断中检查 `G[1250] >= 1`。因此，`G[1250]` 更适合命名为：

> **背景/场景装载模式或背景差分处理模式标志。**

目前还不能仅凭本函数确定 `0/1/2` 各自对应的最终业务名称，但可以确定它们是一个三值模式选择空间，而不是普通文本参数。

## 2. 参数说明

| 参数 | 当前含义 | 置信度 |
|---|---|---|
| `a0` | 背景/场景装载模式值。合法值为 `0`、`1`、`2`；`nil`、负数以及 `>=3` 的值会被清空，不会写入 `G[1250]`。 | 高 |

需要注意参数槽位映射：本函数有 1 个显式入参，原始指令中的 `push_stack -2` 对应 `a0`。不要把旧版 Lua-like 导出文本中可能出现的 `a1` 当作真实第二个参数；相关映射规则见 [`slot_name()`](../../02_tools/hcb_ir/hcb_ir_core.py:560)。

### 2.1 `a0 = 0`

这是当前已知的最常见调用方式：

```lua
f_0004B1F4(0)
```

结果是：

```lua
G[1250] = 0
```

在 [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:5) 的开头，函数正是这样调用的；在 [`f_000A1775()`](Sakura_hcb_ir/Sakura/f_000A1775.lua:30) 以及其他剧情入口中也可见同样调用。

### 2.2 `a0 = 1` 或 `a0 = 2`

函数本体允许这两个值通过检查，并分别写入：

```lua
G[1250] = 1
```

或：

```lua
G[1250] = 2
```

不过在目前已检索到的重点调用样本中，最常见的是 `0`。`1` 与 `2` 的准确业务含义应结合调用它们的场景函数、背景资源差分和运行时画面进一步验证。

### 2.3 非法值与 `nil`

以下输入会被写回 `nil`：

- `a0 == nil`
- `a0 <= -1`
- `a0 >= 3`

函数不会将这些非法值写入 `G[1250]`。严格来说，非法输入路径不是“设置模式”，而是“清除本次设置值”；由于清除发生在局部参数槽上，而函数随后检测到该槽为 `nil` 后直接返回，所以它通常表现为**保持原有 `G[1250]` 不变**。

## 3. 与调用者的关系

该调用发生在后续背景初始化、BGM 设置、转场和正文显示之前。因此这里的作用不是直接显示画面，而是先为后续场景背景装载链写入一个统一模式值：

## 4. `G[1250]` 的下游使用

### 4.1 [`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:84)

[`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:1) 是一个背景资源导入与差分切换函数。其内部多次读取 `G[1250]`：

```lua
S0 = G[1250]
S1 = 1
S0 = (S0 >= S1)
```

该条件会参与判断背景资源名，例如：

```lua
G[63] = "BG001_000"
```

或：

```lua
G[63] = "BG001_010"
```

[`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:1) 随后将 `G[63]` 交给背景装载函数，引入普通背景层和可能的 `b` 差分层。相关背景图像装载机制可参阅 [`BGimageLoading函数共性总结.md`](BGimageLoading函数共性总结.md:1) 和 [`10_Graph.md`](../syscalls/10_Graph.md:71)。

因此，目前最可靠的下游语义是：

```text
f_0004B1F4(a0)
    -> 合法化 a0
    -> 若有效则 G[1250] = a0
    -> 背景函数读取 G[1250]
    -> 影响背景差分/场景装载分支
```

### 4.2 不是直接的 `GraphLoad` 调用

本函数自身没有调用 [`GraphLoad`](../syscalls/10_Graph.md:71)，也没有调用 [`PrimSetSprt`](../syscalls/21_Prim.md:1)、[`PrimSetDraw`](../syscalls/21_Prim.md:1) 或其他显示 syscall。

真正的资源装载发生在下游背景函数中。因此不能把 [`f_0004B1F4()`](Sakura_hcb_ir/Sakura/f_0004B1F4.lua:1) 直接称作“背景加载函数”；更准确的名称是：

> **背景装载模式状态设置函数。**

## 6. 等价伪代码

```lua
function f_0004B1F4(a0)
    if a0 <= -1 or a0 >= 3 then
        a0 = nil
    end

    if a0 ~= nil then
        G[1250] = a0
    end
end
```

由于 FVP 的空值语义是 `nil`，并且当前函数只接受整数 `0/1/2`，也可以写成：

```lua
function f_0004B1F4(a0)
    if a0 == 0 or a0 == 1 or a0 == 2 then
        G[1250] = a0
    end
end
```

这两个版本在本函数的可观察效果上等价：非法值不会导致 `G[1250]` 被写入。

## 7. 最终作用判断

### 高置信度结论

1. [`f_0004B1F4()`](Sakura_hcb_ir/Sakura/f_0004B1F4.lua:1) 是叶子函数；没有下游 function，也没有 syscall。
2. 它只读取一个入参，并对该入参执行 `-1` 和 `3` 两个边界检查。
3. 合法范围是 `0..2`。
4. 合法值会写入 `G[1250]`；非法值和 `nil` 不会改写该全局槽。
5. `G[1250]` 被背景/场景函数读取，并参与背景差分选择。

### 中等置信度结论

- `G[1250]` 是背景装载模式、背景差分模式或场景切换模式标志。
- 原作开场传入 `0`，表示标准背景装载链的默认模式。
- `1`、`2` 可能代表其他背景差分/场景装载模式，但具体名称尚未从本函数本体中确定。

### 低置信度或暂不能确定的部分

- `0`、`1`、`2` 是否分别对应“普通背景”“特殊差分”“另一类背景模式”；
- `G[1250]` 与某个具体资源后缀之间的一一对应关系；
- 非法输入不改写旧的 `G[1250]` 是否被剧情脚本有意用作“保持上一模式”。

## 8. 建议的后续验证

1. 统计所有对 [`f_0004B1F4()`](Sakura_hcb_ir/Sakura/f_0004B1F4.lua:1) 的调用，确认 `1` 和 `2` 是否真的在原作剧情中出现。
2. 对每个 `f_0004B1F4(0/1/2)` 调用点，追踪其后紧邻的背景函数，例如 [`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:1)、[`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:1) 或其他同族函数。
3. 对照这些背景函数最终写入的 `G[63]` 资源名，建立 `G[1250]` 与 `BGxxx_yyy` 差分之间的对应表。
4. 运行时分别强制将 `G[1250]` 设为 `0`、`1`、`2`，记录背景资源名和画面差分变化。

> 因此，原先把 [`f_0004B1F4()`](Sakura_hcb_ir/Sakura/f_0004B1F4.lua:1) 称为“文本/窗口初始化前的通用状态设置包装函数”并不准确。更准确的名称应为：**背景/场景装载模式 `G[1250]` 设置函数**。
