# [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 详细解析

## 1. 函数结论

[`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 是一个**无参数的重型场景/画面状态重置与过渡准备函数**。

它不是单独控制某一个图元、声音或线程的函数，而是将多个公共子系统按固定顺序串起来，形成一轮完整的“旧状态清理 → UI/过渡状态复位 → 音效状态刷新 → 特效槽位重建 → 旧线程清理 → 新过渡模式准备”流程。

可用伪代码概括为：

```lua
function f_0001052C()
    G[1255] = 1

    -- 清理旧过渡图层/overlay 状态
    f_0005073F()

    -- 将消息框/附加 UI 复位到标准状态
    f_0004A608(nil, nil, nil, nil)

    -- 让出一帧，使前面的状态改变提交并推进
    f_0003769F()

    -- 重置图片过渡与舞台坐标缓存
    f_000519B0(nil)

    -- 刷新四路环境音/环境声状态
    f_000172A9()

    -- 重建/清理多路画面特效槽位
    f_00060462(0)

    -- 结束指定后台脚本线程并清理相关图元
    f_000160B6()

    -- 以模式 -2 准备下一轮过渡
    f_00050EDB(nil, 1, -2, nil, nil, nil, nil, nil)
end
```

最合适的工作名称是：

> **重型场景过渡准备函数（模式 -2 变体）**

或：

> **全局画面/UI/音效状态复位函数**

## 2. 基本信息

- 函数地址：`0x0001052C`。
- IR 起始地址：`66860`，见 [`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json:228907)。
- 函数参数：`0`。
- 局部变量：`0`。
- 主体范围：`0x0001052C–0x0001056F`。
- 主 CFG block 为线性流程，没有条件分支；末尾的 `0x0001056F` 是相邻的冗余返回入口，见 [`Sakura.cfg.json`](../../03_data/cfg/Sakura.cfg.json:50961)。

因此该函数的执行结果不依赖自身入参，而取决于调用前各全局状态、当前图元状态、音频状态和特效槽位状态。

## 4. 逐条反汇编

### 4.1 初始化并设置过渡标志

| 地址 | 原始字节 | 指令 | 作用 |
|---|---|---|---|
| `0x0001052C` | `01 00 00` | `init_stack args=0, locals=0` | 建立无参数、无局部变量的栈帧。 |
| `0x0001052F` | `0C 01` | `push_i8 1` | 压入整数 `1`。 |
| `0x00010531` | `15 E7 04` | `pop_global 1255` | 设置 `G[1255] = 1`。 |

`G[1255]` 在多个背景/过渡函数中作为模式归一化或过渡状态标志使用。它不是某个资源编号，也不是直接的显示开关。

这里的含义是：

> 告知后续过渡、背景和图层处理逻辑：当前正在进行一轮特定类型的场景/画面初始化。

该写入与 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:5-7) 和 [`f_00010570()`](Sakura_hcb_ir/Sakura/f_00010570.lua:5-7) 相同。

[`f_0005073F()`](Sakura_hcb_ir/Sakura/f_0005073F.lua:1) 本身只有一条有效业务指令：

```lua
f_00049EC9(0, nil)
```

[`f_00049EC9()`](Sakura_hcb_ir/Sakura/f_00049EC9.lua:1) 会处理与旧画面过渡有关的图元和状态，主要涉及：

- `G[54]`；
- `G[29]`；
- alpha/运动残留；
- overlay 或过渡辅助图层。

因此第一步不是普通初始化，而是：

> **回收上一轮画面过渡残留的 overlay、alpha 动作和辅助图元状态。**

### 4.3 复位消息框和附加 UI

| 地址 | 原始字节 | 指令 | 作用 |
|---|---|---|---|
| `0x00010539` | `08` | `push_nil` | 第 1 个参数：`nil`。 |

| `0x0001053B` | `08` | `push_nil` | 第 3 个参数：`nil`。 |

[`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1) 是一套较重的 overlay/UI 过渡控制器。其关键行为包括：

- 若 `G[126] == true`，可能直接返回；
- 调用 [`f_00058B54()`](Sakura_hcb_ir/Sakura/f_00058B54.lua:1)；
- 规范化内部位置、alpha 和时长参数；
- 设置 `G[116] = true` 表示 UI/过渡刷新进行中；
- 根据状态处理 prim `345`、`346`、`513`、`514` 等；
- 通过 [`f_0004F0AD()`](Sakura_hcb_ir/Sakura/f_0004F0AD.lua:1)、[`f_0004AC7E()`](Sakura_hcb_ir/Sakura/f_0004AC7E.lua:1) 刷新功能栏与附加控件；
- 必要时轮询 `MotionAlphaTest`；
- 以 [`DissolveWait(true)`](../syscalls/06_Dissolve.md:1) 等待过渡收束；
- 最终清理 `G[66]`、`G[67]`、`G[116]`。

因此，这一步的业务含义可以写成：

> **将消息框、侧边控件和附加 overlay 重新对齐到标准显示状态。**

四个 `nil` 表明本函数不指定特殊的覆盖参数，而是要求 [`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1) 走默认复位路径。

### 4.4 让出一帧

| 地址 | 原始字节 | 指令 | 作用 |
|---|---|---|---|
| `0x00010542` | `02 9F 76 03 00` | `call 0x0003769F` | 调用 [`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1)。 |

[`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1) 是 [`ThreadNext()`](../syscalls/27_Thread.md:188) 包装器。

它不代表等待固定时间，也不代表线程退出，而是：

> **让当前脚本 context 结束本轮调度，使之前启动的 alpha/motion/dissolve 和 UI 状态变化先推进一帧。**

把它放在 [`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1) 之后，说明脚本有意在“UI 复位”和“后续缓存重建”之间插入帧同步点。

它不是删除主舞台资源，而是把下一轮舞台运动使用的“初始参数记忆”清零/归一化。

因此该步骤不是播放某一个剧情 BGM，而是：

### 4.7 重建多路画面特效槽位

| 地址 | 原始字节 | 指令 | 作用 |
|---|---|---|---|
| `0x00010552` | `0C 00` | `push_i8 0` | 压入参数 `0`。 |
| `0x00010554` | `02 62 04 06 00` | `call 0x00060462` | 调用 [`f_00060462(0)`](Sakura_hcb_ir/Sakura/f_00060462.lua:1)。 |

[`f_00060462()`](Sakura_hcb_ir/Sakura/f_00060462.lua:1) 是一个大型的特效/状态槽位重建器。它会：

1. 检查 `G[244]`；如果总开关不满足，可能直接返回；
2. 扫描 `G[311]` 到 `G[334]` 的 24 个槽位/编号；
3. 对每个有效槽位调用 [`f_0005FE1E()`](Sakura_hcb_ir/Sakura/f_0005FE1E.lua:1)；
4. 必要时设置 `G[308] = true`；
5. 调用 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 与 [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1)；
6. 重建 `G[945]` 至 `G[1169]` 等大范围画面特效布局/坐标表；
7. 处理多路屏幕特效的启用、位置、时长和关联状态。

这里传入的 `0` 是模式/编号参数。结合它在其他调用点中的使用，更适合称为：

> **以默认模式重建当前场景的多路画面特效与槽位布局。**

该调用不是普通的“清屏”，而是尽量保留有效槽位信息并重新同步其运行状态。

### 4.8 结束后台演出线程并清理相关图元

| 地址 | 原始字节 | 指令 | 作用 |
|---|---|---|---|
| `0x00010559` | `02 B6 60 01 00` | `call 0x000160B6` | 调用 [`f_000160B6()`](Sakura_hcb_ir/Sakura/f_000160B6.lua:1)。 |

[`f_000160B6()`](Sakura_hcb_ir/Sakura/f_000160B6.lua:1) 执行：

```lua
ThreadExit(10)
f_00037421(240)
f_00037421(241)
f_00037421(242)
f_00016E4F(0, nil, nil, nil, nil)
```

其中：

- [`ThreadExit(10)`](../syscalls/27_Thread.md:135) 请求结束 context/thread 10；
- [`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1) 对 prim `240/241/242` 做统一清理；
- [`f_00016E4F()`](Sakura_hcb_ir/Sakura/f_00016E4F.lua:1) 继续处理一组与后台演出相关的资源或状态。

所以这一步的实际作用是：

> **停止指定的后台演出线程，并清理其使用的辅助图元。**

它说明 [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 不只负责前台画面，还要确保并行演出 context 不会把上一场景的状态带入下一场景。

注意，`f_00050EDB()` 的实际参数编号同样受当前导出器参数槽偏移影响。这里最重要的事实是：


[`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 会：

- 清理 prim `188/189/1590/1591`；

- 在 `G[68]` 有效时执行 [`DissolveWait(true)`](../syscalls/06_Dissolve.md:1)。

因此最后一步不是普通清理，而是：

> **在所有旧状态复位后，以过渡模式 `-2` 重建/准备下一套画面过渡图层。**

## 5. 与相邻函数的比较

### 5.1 与 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1)

两者结构几乎完全一致：

| 阶段 | `f_000104E8()` | `f_0001052C()` |
|---|---|---|
| `G[1255] = 1` | 相同 | 相同 |
| 清理旧 overlay | `f_0005073F()` | `f_0005073F()` |
| UI/消息框复位 | `f_0004A608(nil,nil,nil,nil)` | 相同 |
| 帧同步 | `f_0003769F()` | 相同 |
| 过渡缓存复位 | `f_000519B0(nil)` | 相同 |
| 环境音刷新 | `f_000172A9()` | 相同 |
| 特效槽重建 | `f_00060462(0)` | 相同 |
| 后台线程清理 | `f_000160B6()` | 相同 |
| 最后模式 | `f_00050EDB(nil,1,-1,...)` | `f_00050EDB(nil,1,-2,...)` |

因此可以确定：

> [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 不是另一套完全不同的功能，而是同一“重型过渡准备函数族”中的 `-2` 模式变体。

### 5.2 与 [`f_00010570()`](Sakura_hcb_ir/Sakura/f_00010570.lua:1)

[`f_00010570()`](Sakura_hcb_ir/Sakura/f_00010570.lua:1) 也具有同样的前置清理骨架，但最终使用 `-3`：

```lua
f_00050EDB(nil, 1, -3, nil, nil, nil, nil, nil)
```

这说明 `-1/-2/-3` 很可能是同一过渡入口的不同模式编号。当前可以可靠确认它们选择不同的过渡行为，但仅凭 [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 本身，还不能把 `-2` 命名成某种确定的淡入、淡出、滑入或遮罩方向。

## 6. 调用上下文与业务位置

[`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 的调用者包括：

- [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:474)：开场/特殊演出流程；
- [`f_000977CB()`](Sakura_hcb_ir/Sakura/f_000977CB.lua:21)：过渡或场景切换流程；
- [`f_000A1977()`](Sakura_hcb_ir/Sakura/f_000A1977.lua:16)：状态切换流程；
- [`f_00055659()`](Sakura_hcb_ir/Sakura/f_00055659.lua:123)：媒体/演出流程；
- [`f_00055A57()`](Sakura_hcb_ir/Sakura/f_00055A57.lua:90)：过渡控制链；
- 多个主剧情 function：在正文、演出、场景切换前后调用。

它既可能出现在正文调用后，也可能出现在背景、音效或 dissolve 操作后。这种调用位置说明其职责不是“显示一条台词”，而是：

> **在场景切换或演出段落切换时，将整个显示环境重新建立到可预测的基线。**

| prim `186/187/188/189/1590/1591` | 为模式 `-2` 的下一轮过渡做准备。 |

## 8. 最终判断

[`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 的整体作用不是：

- 单独显示背景；
- 单独执行 dissolve；
- 单独重置消息框；
- 单独播放音效；
- 单独结束线程。

而是将上述多个动作组合成一个固定的系统级流程：

```text
设置过渡模式标志
→ 清理旧 overlay/过渡图层
→ 复位消息框与附属 UI
→ 让出一帧
→ 清零主舞台运动/过渡缓存
→ 刷新四路环境音
→ 重建多路画面特效槽位
→ 结束后台演出线程并清理辅助图元
→ 以 -2 模式准备下一轮过渡
```

最终可高置信度表述为：

> [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 是 Sakura 引擎中用于场景/演出切换的重型状态复位器。它先清理当前画面、UI、舞台运动缓存、环境音、特效槽位和后台演出线程，再通过 [`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 的模式 `-2` 建立下一轮过渡环境。

其中 `-2` 的具体视觉模式仍应继续通过 [`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 的各模式实机对比来命名；但 `f_0001052C()` 自身的职责已经可以确定为**系统级场景过渡准备，而非单一图元操作**。
