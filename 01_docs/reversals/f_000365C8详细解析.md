# [`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 详细解析

## 1. 核心结论

[`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 是 Sakura.hcb 中一组连续 BGM 包装函数之一。

它的功能可以准确还原为：

```lua
function play_bgm_12(volume)
    G[2039] = true
    f_0005511C(12, nil, nil, volume, nil)
end
```

也就是说，它同时完成两件事：

1. 设置 [`G[2039]`](Sakura_hcb_ir/Sakura/f_000365C8.lua:6) 为 `true`，表示 BGM 编号 12 已启用/已解锁/可在曲目列表中登记；
2. 调用 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)，固定切换到 `BGM/012`，唯一可变参数是音量。

最准确的功能标签是：

> **BGM 12 的解锁标记设置与播放/切换包装器。**

它不是通用的 BGM 播放函数，也不允许调用方选择任意 BGM 编号。BGM 编号 `12` 在函数体内固定写死；函数的唯一真实入参是音量。

## 4. 参数编号勘误

### 4.1 函数实际只有一个参数

函数序言明确写着：

```text
init_stack args=1 locals=0
```

因此它只有一个真实外部参数。

但 Lua-like 导出文本的函数头是：

```lua
function f_000365C8(a0)
```

函数体却读取：

```lua
S3 = a1
```

这不是隐藏的第二个参数，而是旧版 Lua-like 导出器的负栈索引命名偏移问题。原始指令读取的是：

```text
push_stack -2
```

按照项目已有的参数映射规则，单参数函数中：

```text
push_stack -2 -> 唯一真实参数 a0
```

因此本文将这个真实参数命名为 `volume` 或 `P1`，而不采用导出文本中误导性的 `a1`。

相关勘误见 [`HCB Lua-like参数编号偏移错误说明.md`](HCB%20Lua-like参数编号偏移错误说明.md:1)。

### 4.2 唯一真实参数的映射

| 真实参数 | 原始栈槽 | Lua-like 导出名称 | 推荐名称 | 用途 |
|---|---:|---|---|---|
| `P1` | `-2` | `a1` | `volume` | 传给 `f_0005511C` 的第 4 个参数，最终用于 `AudioVol` |

所以：

```lua
f_000365C8(50)
```

不是播放 BGM 50，而是：

```text
播放固定 BGM 12，目标音量为 50%
```

同样：

```lua
f_000365C8(nil)
```

表示播放固定 BGM 12，音量交由下游默认处理。

## 5. 第一项作用：设置 `G[2039] = true`

函数开头执行：

```lua
G[2039] = true
```

对应 [`f_000365C8.lua`](Sakura_hcb_ir/Sakura/f_000365C8.lua:5-6)。

### 5.1 `G[2039]` 的读取点

当前工程中，`G[2039]` 的明确读取点位于 [`f_000452A0()`](Sakura_hcb_ir/Sakura/f_000452A0.lua:129-138)：

```lua
S0 = nil
S1 = 12
S2 = G[2039]
S3 = 2505
S4 = "a_sndt_012"
S5 = 0
S6 = 275
S7 = nil
S8 = nil
S9 = nil
__ret = f_0008F8F6(S0, S1, S2, S3, S4, S5, S6, S7, S8, S9)
```

这里可以观察到非常规则的结构：

```text

启用标志 G[2039]
资源/条目编号 2505
曲目名 a_sndt_012
列表偏移 275
```

这说明 `G[2039]` 与 BGM 12 的条目状态绑定，而不是一个普通的播放临时变量。

### 5.2 与同族全局槽的关系

[`f_000452A0()`](Sakura_hcb_ir/Sakura/f_000452A0.lua:19-160) 连续登记多首音频条目：

| 曲目编号 | 状态槽 | 条目名 |
|---:|---:|---|
| 1 | `G[2028]` | `a_sndt_001` |
| 2 | `G[2029]` | `a_sndt_002` |
| 3 | `G[2030]` | `a_sndt_003` |
| 4 | `G[2031]` | `a_sndt_004` |
| 5 | `G[2032]` | `a_sndt_005` |
| 6 | `G[2033]` | `a_sndt_006` |
| 7 | `G[2034]` | `a_sndt_007` |
| 8 | `G[2035]` | `a_sndt_008` |
| 9 | `G[2036]` | `a_sndt_009` |
| 10 | `G[2037]` | `a_sndt_010` |
| 11 | `G[2038]` | `a_sndt_011` |
| 12 | `G[2039]` | `a_sndt_012` |
| 13 | `G[2040]` | `a_sndt_013` |
| 14 | `G[2041]` | `a_sndt_014` |

同族包装器的规律是：

```text
f_000365A0 -> G[2037]=true -> BGM 10
f_000365B4 -> G[2038]=true -> BGM 11
f_000365C8 -> G[2039]=true -> BGM 12
f_000365DC -> G[2040]=true -> BGM 13
f_000365F0 -> G[2041]=true -> BGM 14
```

因此可以高置信度地断定：

> `G[2039]` 是 BGM 12 对应的条目状态槽，`true` 表示该曲目已经被剧情流程激活，随后音频列表/试听系统可以将它登记为可用条目。

### 5.3 “解锁”与“播放”的关系

从当前证据可以确认 `G[2039]` 是音频列表登记函数使用的状态输入，但“解锁”一词需要稍微保守：

- 高置信度：`G[2039]=true` 表示 BGM 12 已启用或已登记为有效条目；
- 中高置信度：这对应音乐鉴赏/音频列表中的解锁状态；
- 当前尚不能确认：游戏界面是否直接显示“已解锁”文字，或者它是否还参与其它存档逻辑。

因此文档中推荐称为：

> **BGM 12 的启用/解锁状态标志。**

## 6. 第二项作用：调用 `f_0005511C(12,nil,nil,volume,nil)`

函数随后固定构造：

```lua
f_0005511C(12, nil, nil, volume, nil)
```

对应 [`f_000365C8.lua`](Sakura_hcb_ir/Sakura/f_000365C8.lua:7-12)。

[`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1) 的 5 个真实参数可以解释为：

| 下游参数 | 传入值 | 语义 |
|---:|---|---|
| 第 1 参数 | `12` | BGM 编号，固定为 12 |
| 第 2 参数 | `nil` | 旧音频槽停止时序参数，使用默认值 |
| 第 3 参数 | `nil` | 播放模式参数，走普通循环播放路径 |
| 第 4 参数 | `volume` | 音量，`nil` 时下游默认为 100 |
| 第 5 参数 | `nil` | 目录选择参数，使用 `BGM/` 而不是 `BGM2/` |

所以函数的语义化等价形式是：

```lua
function play_bgm_12(volume)
    G[2039] = true
    f_0005511C(
        12,       -- 固定 BGM 编号
        nil,      -- 默认旧槽停止时序
        nil,      -- 普通循环播放模式
        volume,   -- 目标音量
        nil       -- 使用 BGM/ 目录
    )
end
```

## 7. 下游 BGM 核心函数的实际流程

### 7.1 音量默认值

[`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:5-12) 首先对其第 4 个真实参数做默认值处理：

```lua
if volume == nil then
    volume = 100
end
```

因此：

```lua
f_000365C8(nil)
```

等价于目标音量 `100`。

如果传入数值：

```lua
f_000365C8(50)
```

则下游执行：

```lua
AudioVol(new_channel, 50, nil)
```

Audio 组文档确认脚本音量通常是 `0..100` 的百分比整数，见 [`01_Audio.md`](../syscalls/01_Audio.md:59-65)。

### 7.2 当前 BGM 相同时可能直接返回

[`f_0005511C()`](Sakura_hcb_ir/Sakura_hcb_ir/Sakura/f_0005511C.lua:14-20) 会把当前 BGM 编号与 [`G[215]`](Sakura_hcb_ir/Sakura/f_0005511C.lua:14-20) 比较：

```lua
if G[215] == track_id then
    return
end
G[215] = track_id
```

因此，当当前记录的 BGM 已经是 `12` 时，再调用 [`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 可能不会重新加载或重播音频。

但是要注意：

```lua
G[2039] = true
```

位于比较之前，因为它在包装函数中先执行。因此即使 BGM 12 已经正在播放，重复调用仍然会先确保曲目状态槽为 `true`。

这说明该包装器的两个动作具有不同的生命周期：

```text
G[2039] = true -> 每次调用都执行
BGM 切换       -> 只有当前 BGM 不是 12 时才真正执行
```

### 7.3 构造资源路径

[`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:21-39) 根据第 5 参数选择前缀：

```lua
if directory_mode ~= 2 then
    prefix = "BGM/"
else
    prefix = "BGM2/"
end
```

本函数第 5 参数固定为 `nil`，所以选择：

```text
BGM/
```

随后将编号 `12` 格式化为三位字符串：

```lua
IntToText(12, 3) -> "012"
```

最终资源逻辑路径为：

```text
BGM/012
```

扩展名和具体封装格式由音频资源层处理，本函数本身不包含扩展名。

### 7.4 双槽交替

[`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:40-54) 使用 [`G[213]`](Sakura_hcb_ir/Sakura/f_0005511C.lua:40-54) 和 [`G[214]`](Sakura_hcb_ir/Sakura/f_0005511C.lua:40-54) 管理新旧音频槽：

```text
G[213] -> 本次新 BGM 使用的槽
G[214] -> 上一次 BGM 使用的槽
```

两路槽位交替，可以让新旧 BGM 在切换期间并存，从而停止旧槽并启动新槽。

### 7.5 实际 Audio 调用顺序

典型切换过程是：

```lua
AudioStop(new_channel, 100)
AudioType(new_channel, 1)
AudioLoad(new_channel, "BGM/012")
AudioVol(new_channel, volume, nil)
AudioPlay(new_channel, true)
AudioStop(old_channel, fadeout_time)
```

其中 `AudioPlay(..., true)` 来自本函数固定传入的第三个下游参数 `nil`：

```lua
if play_mode == 1 or play_mode == nil then
    AudioPlay(channel, true)
else
    AudioPlay(channel, nil)
end
```

所以 [`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 播放的是循环 BGM，而不是一次性音效。

## 8. 唯一入参 `volume` 的具体含义

### 8.1 `nil`

```lua
f_000365C8(nil)
```

处理结果：

```text
G[2039] = true
BGM 编号 = 12
路径 = BGM/012
音量 = 100
播放 = 循环
```

这是剧情中最常见、也最符合固定 BGM 包装器设计的调用方式。

### 8.2 数值

```lua
f_000365C8(50)
```

处理结果：

```text
G[2039] = true
BGM 编号 = 12
路径 = BGM/012
音量 = 50%
播放 = 循环
```

Audio 层通常把 `0..100` 的脚本整数转换为 `0.0..1.0` 的实际音量比例，见 [`01_Audio.md`](../syscalls/01_Audio.md:59-65)。

### 8.3 越界或非标准类型

[`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 自身不检查音量范围，校验交给 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:65-76) 及底层 `AudioVol`。

已确认下游会把非正值处理为 0：

```lua
if volume <= 0 then
    volume = 0
end
```

具体越界值在不同实现中可能还会由 Audio 层继续限制，因此注入时应优先使用：

```text
0..100
```

### 8.4 它不是以下参数

唯一入参不是：

- BGM 编号；
- Audio 槽编号；
- 播放/停止模式；
- 循环标志；
- 渐入时长；
- 旧 BGM 的淡出时间。

这些值在本函数中都被固定或交给下游默认化。

## 11. 与音乐鉴赏/音频列表初始化的关系

[`f_000452A0()`](Sakura_hcb_ir/Sakura/f_000452A0.lua:1) 会集中建立音频列表条目。第 12 项明确使用：

```lua
S1 = 12
S2 = G[2039]
S3 = 2505
S4 = "a_sndt_012"
S5 = 0
S6 = 275
...
f_0008F8F6(...)
```

[`f_0008F8F6()`](Sakura_hcb_ir/Sakura/f_0008F8F6.lua:1) 会把这些参数写入多个全局表 `GT[1765..1774]`，并为下一项索引初始化默认值 `255`。

从 `f_0008F8F6` 的结构可以确认，它是一个**音频条目/试听列表记录器**，而不是普通的 BGM 播放器：

- 参数按曲目编号写入表格；
- 保存曲目状态、资源编号、条目名、位置/偏移等元数据；
- 后续界面或音频测试流程可以读取这些记录。

因此 `f_000365C8()` 中的：

```lua
G[2039] = true
```

具有超出当前播放动作的长期效果：

```text
剧情首次播放 BGM 12
    -> G[2039] 变为 true
    -> 音频列表登记 BGM 12 时读到 true
    -> BGM 12 被视为启用/可用条目
```

这也是本函数不能简单命名为 `play_bgm_12` 的原因。更完整的名字应包含“启用/解锁”语义。

## 12. 返回值与副作用

### 12.1 返回值

本函数没有显式业务返回值：

```lua
__ret = f_0005511C(...)
return
```

下游 `f_0005511C()` 和 Audio 控制 syscall 也不产生可供剧情逻辑使用的返回值。因此调用方不能通过返回值判断播放是否成功。

### 12.2 全局状态副作用

直接副作用：

```lua
G[2039] = true
```

间接副作用来自 `f_0005511C()`：

- `G[215]` 更新为当前 BGM 编号 `12`；
- `G[213]` / `G[214]` 交替更新音频槽；
- 音频资源 `BGM/012` 被加载；
- 音频类型设置为 BGM 类型 `1`；
- 音量设置为指定值或默认值；
- 新音频循环播放；
- 旧音频槽按默认时间停止。

### 12.3 重复调用

重复调用的行为分两层：

```text
G[2039] = true       -> 每次都会执行
f_0005511C(12,...)   -> 若 G[215] 已为 12，可能直接返回
```

所以重复调用通常不会反复重载同一首 BGM，但会重复确保曲目解锁状态成立。

## 13. 推荐等价实现

### 13.1 高层语义等价

```lua
function enable_and_play_bgm_12(volume)
    G[2039] = true
    f_0005511C(12, nil, nil, volume, nil)
end
```

### 13.2 结合下游后的近似实现

```lua
function enable_and_play_bgm_12(volume)
    G[2039] = true

    if volume == nil then
        volume = 100
    end

    -- 如果当前已经是 BGM 12，核心函数可能直接返回
    if G[215] == 12 then
        return
    end

    G[215] = 12

    local new_channel
    local old_channel
    if G[213] == 0 then
        new_channel = 1
        old_channel = 0
    else
        new_channel = 0
        old_channel = 1
    end
    G[213] = new_channel
    G[214] = old_channel

    AudioStop(new_channel, 100)
    AudioType(new_channel, 1)
    AudioLoad(new_channel, "BGM/012")
    AudioVol(new_channel, volume, nil)
    AudioPlay(new_channel, true)

    -- 第二参数为 nil 时，由下游产生默认旧槽停止时序
    StopOldBgm(old_channel)
end
```

其中 `StopOldBgm` 的具体时间由 [`f_00055202()`](Sakura_hcb_ir/Sakura/f_00055202.lua:1) 的下游规则决定，不能把它误认为本函数的入参。

## 14. 对剧情注入和复用的意义

如果新剧情需要播放 BGM 12，直接复用：

```lua
f_000365C8(nil)
```

比手写：

```lua
f_0005511C(12, nil, nil, nil, nil)
```

多做了一件事：

```lua
G[2039] = true
```

这可能影响之后的音乐鉴赏/试听列表状态。因此：

- 只想临时播放 BGM 12：可以直接调用下游核心函数，但不会自动设置解锁标志；
- 想保持原作行为：应调用 [`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1)；
- 想播放 BGM 12 但不解锁鉴赏条目：不要调用该包装器，改为直接调用 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)，并确认这样做不会破坏剧情预期。

对于原作兼容性，推荐：

```lua
f_000365C8(nil)
```

因为它会同时维护播放和曲目状态。

## 15. 最终结论

1. [`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 只有一个真实入参。
2. 该入参来自原始 `push_stack -2`，是唯一参数，不是隐藏的第二参数。
3. 唯一入参位于 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1) 的第 4 参数位置，语义是目标音量。
4. BGM 编号 `12` 在本函数中固定写入，不由调用者传入。
5. 函数固定调用：

   ```lua
   f_0005511C(12, nil, nil, volume, nil)
   ```

6. 下游使用 `BGM/012` 路径。
7. 第 3 个下游参数固定为 `nil`，因此走循环 BGM 播放路径。
8. 第 5 个下游参数固定为 `nil`，因此使用 `BGM/` 而非 `BGM2/`。
9. 第 2 个下游参数固定为 `nil`，因此使用默认旧 BGM 停止时序。
10. 函数先设置 `G[2039]=true`，该槽在 [`f_000452A0()`](Sakura_hcb_ir/Sakura/f_000452A0.lua:129-138) 中作为 BGM 12 条目的启用/解锁状态使用。
11. `G[2039]=true` 与实际 BGM 切换是两个不同层面的副作用：前者每次执行，后者可能因当前 BGM 已经是 12 而被下游抑制。
12. 本函数没有有意义的返回值。
13. 最准确的功能标签是：

> **设置 BGM 12 的启用/解锁状态，并以指定音量播放或切换 BGM 12 的固定包装器。**
