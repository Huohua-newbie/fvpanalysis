# [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) 详细解析

## 1. 核心结论

[`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) 是 Sakura.hcb 中一个非常重要的**全局 V3D 运动调度器 / 三维场景切换控制器**。

它并不是简单地把几个参数直接转发给 [`V3DMotion`](../syscalls/31_V3D.md:108)，而是在真正启动三维运动之前，统一完成以下工作：

1. 根据 [`G[310]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:5) 判断是否处于“运动初始化/重入保护”状态；
2. 在特定状态下走一个短路重置路径，调用 [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 后立即返回；
3. 设置 [`G[17]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:22) 与 [`G[18]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:24)，标记 V3D/场景运动正在处理；
4. 规范化 V3D 目标坐标、运动时长、运动类型、等待开关等参数；
5. 根据若干全局状态修正运动时长，并在必要时发出 [`ControlPulse`](../syscalls/03_Control.md:49)；
6. 把规范化后的坐标写入 [`G[1176]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:232)、[`G[1177]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:234)、[`G[1178]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:236)，作为下一次缺省参数的缓存；
7. 在模糊/辅助层启用时调用 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 处理 prim 187；
8. 在特定参数下刷新一组场景/UI 状态；
9. 启动全局 [`V3DMotion(dst_x,dst_y,dst_z,duration,type,reverse)`](../syscalls/31_V3D.md:112)；
10. 根据等待开关选择是否轮询 [`V3DMotionTest()`](../syscalls/31_V3D.md:266)，并通过 [`ThreadNext`](../syscalls/27_Thread.md:1) 逐帧等待运动结束；
11. 最后清除 [`G[17]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:255)，结束本轮 V3D 运动调度。

因此，最准确的功能标签是：

> **带有状态保护、默认值归一化、辅助图层同步和可选阻塞等待的全局 V3D 运动入口。**

它的主要视觉用途是让具有 V3D 投影属性的场景图元随全局三维坐标发生推移、缩放或镜头式变化。V3D 本身是全局坐标/投影状态，而不是某个单独 prim 的位置，详见 [`31_V3D.md`](../syscalls/31_V3D.md:27)。

## 3. 参数编号勘误：必须以真实栈槽为准

### 3.1 导出器存在整体偏移

当前 Lua-like 文件显示的函数头是：

```lua
function f_000526A3(a0, a1, a2, a3, a4, a5, a6, a7, a8, a9, a10, a11)
```

但函数体读取到了 `a12`，例如：

```lua
S0 = a12
```

这不是函数真的有第 13 个参数，而是旧版 Lua-like 导出器的参数命名整体右移了一位。相关问题已经在 [`HCB Lua-like参数编号偏移错误说明.md`](./HCB Lua-like参数编号偏移错误说明.md:1) 中说明。

对于 `init_stack args=12` 的函数，正确的真实参数对应关系是：

| 真实参数 | 原始负栈槽 | 导出器旧名称 | 本文名称 | 实际用途 |
|---|---:|---|---|---|
| `P0` | `-13` | `a1` | `P0` | V3D 目标 X |
| `P1` | `-12` | `a2` | `P1` | V3D 目标 Y |
| `P2` | `-11` | `a3` | `P2` | V3D 目标 Z |
| `P3` | `-10` | `a4` | `P3` | 运动时长，随后会被修正 |
| `P4` | `-9` | `a5` | `P4` | V3D 运动类型，默认 `3` |
| `P5` | `-8` | `a6` | `P5` | 传给 V3DMotion 的 reverse 参数；本体不直接判断 |
| `P6` | `-7` | `a7` | `P6` | 是否等待 V3D motion 完成，`1` 时等待 |
| `P7` | `-6` | `a8` | `P7` | 辅助/UI 刷新开关，`nil` 时为 `1` |
| `P8` | `-5` | `a9` | `P8` | 辅助 prim 187 处理开关，`nil` 时为 `1` |
| `P9` | `-4` | `a10` | `P9` | 控制 [`G[28]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:81) 的模式值，`nil` 时为 `1` |
| `P10` | `-3` | `a11` | `P10` | 传给 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 的辅助层参数，`nil` 保持默认路径 |
| `P11` | `-2` | `a12` | `P11` | 快速路径判断值；`-1` 表示特殊短路条件 |

后续所有语义分析均使用 `P0..P11`，不再直接使用导出文本中的 `a1..a12`。

### 3.2 调用样本验证

剧情中常见调用形式如下：

```lua
f_000526A3(0, 200, 300, 900, nil, nil, nil, nil, nil, nil, nil, nil)
```

例如 [`f_000A2981.lua`](Sakura_hcb_ir/Sakura/f_000A2981.lua:1325) 中的调用：

```lua
S0 = 0
S1 = 200
S2 = 300
S3 = 900
S4 = nil
...
__ret = f_000526A3(S0, S1, S2, S3, ...)
```

这与“把全局 V3D 坐标移动到 `(0,200,300)`，运动时长约为 `900 ms`，其余选项使用默认值”的解释完全一致。

另一个样本是 [`f_00498F00.lua`](Sakura_hcb_ir/Sakura/f_00498F00.lua:203)，其调用中使用了负 Y 坐标和 `1000` 时长，说明前三个参数确实是三维目标坐标，而不是 prim 编号或普通二维屏幕坐标。

## 4. 完整控制流概览

可以将函数压缩成以下伪代码：

```lua
function V3DMotionController(
    dst_x, dst_y, dst_z,
    duration,
    motion_type,
    reverse,
    wait_motion,
    refresh_ui,
    process_aux_layer,
    mode,
    aux_arg,
    special_mode
)
    if G[310] == 1 then
        G[310] = 0
        f_0005261B(dst_x, dst_y, dst_z, aux_layer_enable)
        return
    end

    G[310] = 0
    G[17] = true
    G[18] = true

    if special_mode ~= -1 then
        f_00037F11(1, nil)
    end

    refresh_ui = refresh_ui or 0
    process_aux_layer = process_aux_layer or 1
    mode = mode or 1
    aux_arg = aux_arg or nil

    if mode == 0 then
        G[28] = 0
    else
        G[28] = 1
    end

    duration = normalize_duration(duration)
    motion_type = motion_type or 3

    dst_x = dst_x or G[1176]
    dst_y = dst_y or G[1177]
    dst_z = dst_z or G[1178]

    adjust_duration_by_global_state()

    G[88] = duration
    G[89] = duration

    if G[1973] == true and process_aux_layer ~= 0 then
        f_00052882(dst_z, duration, aux_arg)
    end

    if refresh_ui == 0 or refresh_ui == 1 then
        f_0005073F()
        f_0004A5DE(nil, nil, nil, nil)
    end

    V3DMotion(dst_x, dst_y, dst_z, duration, motion_type, reverse)

    G[1176] = dst_x
    G[1177] = dst_y
    G[1178] = dst_z

    if wait_motion == 1 then
        repeat
            ThreadNext()
        until not V3DMotionTest() or duration <= 1
    end

    G[17] = nil
end
```

上面是语义化伪代码，不是可直接重新组装的 HCB 源码。尤其是 `duration` 的具体归一化和全局状态分支，必须按下面的逐段说明理解。

## 5. 第一阶段：[`G[310]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:5) 重入保护与短路路径

函数入口首先执行：

```lua
if G[310] == 1 then
    G[310] = 0
    f_0005261B(P0, P1, P2, P8)
    return
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:5-17)。

### 5.1 `G[310]` 的作用

`G[310]` 是本函数使用的一个**运动流程状态/重入保护标志**。当它为 `1` 时，本次调用不再走完整的复杂流程，而是：

1. 清除 `G[310]`；
2. 调用 [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1)；
3. 立即返回。

这说明 `G[310]` 不是 V3D 坐标本身，而是用于区分某种“正在初始化、正在恢复或需要快速收束”的状态。

### 5.2 短路调用 [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1)

[`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 的主体会：

- 清除 `G[310]`；
- 设置 `G[17] = true`；
- 把 `G[71]` 清零；
- 对缺省的 X/Y/Z 使用 `G[1176..1178]`；
- 必要时处理 prim 187；
- 调用一次固定参数的 [`V3DMotion`](../syscalls/31_V3D.md:108)；
- 更新 `G[1176..1178]`；
- 清除 `G[17]`。

因此，`f_0005261B` 更像是“简化的 V3D 复位/立即重启动作”，而 `f_000526A3` 是“完整的、可配置的 V3D 运动流程”。

需要注意：短路路径不会继续执行 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:18) 后面的时长修正、辅助层处理和等待循环。

## 6. 第二阶段：建立全局运动状态

完整路径首先执行：

```lua
G[310] = 0
G[17] = true
G[18] = true
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:18-24)。

### 6.1 `G[17]`

`G[17]` 在函数运行期间被置为 `true`，函数正常结束时清为 `nil`：

```lua
G[17] = true
...
G[17] = nil
```

因此它可以高置信度地解释为：

> **当前正在执行 V3D/场景运动调度。**

其他函数可能通过它判断当前是否处于运动、切换或演出临界区。

### 6.2 `G[18]`

`G[18]` 只在完整路径开头被置为 `true`，本函数没有在末尾清除它。因此它更像是一个被后续流程消费的“运动发生过/运动初始化完成”标志，而不是严格意义上的临时锁。

仅凭本函数无法确定 `G[18]` 的完整业务名称，但可以确认它与完整 V3D 运动路径同步建立。

## 7. 第三阶段：特殊模式下刷新场景/UI 状态

函数检查：

```lua
if P11 ~= -1 then
    f_00037F11(1, nil)
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:25-33)。

### 7.1 `P11` 的语义

`P11` 是最后一个真实参数，来自原始栈槽 `-2`。当它不等于 `-1` 时，函数调用 [`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1)。

因此可以确认：

- `P11 == -1`：跳过该场景/UI 刷新步骤；
- `P11 != -1`：执行该刷新步骤。

从调用样本看，`P11` 通常是 `nil`，因此默认会进入 [`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1) 路径。

### 7.2 [`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1) 的下游作用

[`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1) 会：

1. 在特定值下设置 [`G[296]`](Sakura_hcb_ir/Sakura/f_00037F11.lua:11)；
2. 在另一个分支调用 [`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:1)；
3. 最终调用 [`f_00037E76()`](Sakura_hcb_ir/Sakura/f_00037E76.lua:1)。

而 [`f_00037E76()`](Sakura_hcb_ir/Sakura/f_00037E76.lua:1) 会处理 prim 291、293 的建立、透明度和销毁状态。因此，这一步不是 V3D 坐标计算，而是：

> **在进入三维运动前，将与场景/UI 或辅助显示有关的图元状态刷新到适合运动的状态。**

`P11` 更准确的名称应是 `skip_scene_ui_prepare` 或 `scene_prepare_mode`，目前不宜直接命名成“动画类型”。

## 8. 第四阶段：参数默认值

### 8.1 `P6`：等待开关

```lua
if P6 == nil then
    P6 = 0
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:34-41)。

其语义是：

| `P6` | 行为 |
|---:|---|
| `nil` | 默认变为 `0`，不等待 V3D motion 结束 |
| `0` | 不进入等待循环 |
| `1` | 启动运动后轮询 `V3DMotionTest()` |

这是本函数最明确的同步控制参数。

### 8.2 `P7`：UI/辅助刷新开关

```lua
if P7 == nil then
    P7 = 1
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:42-49)。

本函数后面只判断 `P7 == 1 or P7 == 0`，两种值都会进入刷新分支。因此它不是简单的“0 关闭、1 开启”布尔开关，更接近：

> **是否采用标准场景/UI 准备流程的模式值。**

当前可确认的范围是：

- `nil` 会被归一化为 `1`；
- `0` 和 `1` 都会触发 [`f_0005073F()`](Sakura_hcb_ir/Sakura/f_0005073F.lua:1) 与 [`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:1)；
- 其他数值会跳过该特定刷新分支。

### 8.3 `P8`：prim 187 辅助层处理开关

```lua
if P8 == nil then
    P8 = 1
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:50-57)。

后面只有在 `P8 != 0` 时，才可能调用 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1)。所以它可以命名为：

> **是否处理辅助/模糊层 prim 187。**

默认值是 `1`，说明普通场景运动默认会保留该辅助层同步逻辑。

### 8.4 `P9`：模式标志

```lua
if P9 == nil then
    P9 = 1
end
```

对应 [`f_000526A3.lua`](fvp_analysis/result/hcbtool_test/Sakura_hcb_ir/Sakura/f_000526A3.lua:58-65)。

随后：

```lua
if P9 == 0 then
    G[28] = 0
else
    G[28] = 1
end
```

对应 [`f_000526A3.lua`](fvp_analysis/result/hcbtool_test/Sakura_hcb_ir/Sakura/f_000526A3.lua:74-85)。

因此 `P9` 的稳定语义是：

> **控制全局状态 `G[28]` 的模式参数。**

它不是直接传给 `V3DMotion` 的参数，也不直接表示 easing 类型。

### 8.5 `P10`：辅助层参数

```lua
if P10 == nil then
    P10 = nil
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:66-73)。

这一段看似没有变化，实际作用是明确地将该参数规范化为“缺省为 nil”。它随后被作为第三参数传给 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1)。

## 9. 第五阶段：运动时长 `P3` 的归一化与修正

这是本函数较容易误读的一段。

### 9.1 缺省值

```lua
if P3 == nil then
    P3 = 495
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:86-93)。

所以 `P3` 的默认原始值是 `495`，不是 V3D syscall 的默认值。它是该上层控制器自己定义的默认运动时长。

### 9.2 小于等于 24 的值

```lua
if P3 <= 24 then
    P3 = 1
else
    P3 = P3 - 25
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:94-107)。

因此：

| 原始 `P3` | 传给 V3DMotion 前的值 |
|---:|---:|
| `nil` | 先变为 `495`，再变为 `470` |
| `0..24` | `1` |
| `25` | `0` |
| `900` | `875` |
| `1000` | `975` |

这个规则非常重要，因为剧情调用中经常出现 `900`、`950`、`1000` 等数值。它们并不会原样传给 [`V3DMotion`](../syscalls/31_V3D.md:108)，而是先减去 `25`。

### 9.3 为什么存在 `-25`

从调用样本可以看出，调用方仍然使用接近实际演出时长的数值，例如：

```lua
f_000526A3(0, 200, 300, 900, ...)
```

但函数内部把它变成 `875`。这很可能是为了补偿：

- 场景/UI 准备阶段的固定开销；
- 运动开始前的一小段同步时间；
- 引擎帧更新和演出时序的固定偏移；
- 或原始脚本设计中的“外部时长”与“V3D 实际时长”差值。

高置信度结论只能写成：

> `P3` 是调用方提供的上层时长参数，函数会将其转换成实际交给 V3DMotion 的 duration；常规正数路径为 `P3 - 25`，小值则压缩为 `1`。

不能仅凭此函数断言 `25 ms` 一定对应某个具体动画阶段。

## 10. 第六阶段：运动类型 `P4`

```lua
if P4 == nil then
    P4 = 3
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:108-115)。

随后 `P4` 作为第五个参数传给：

```lua
V3DMotion(P0, P1, P2, P3, P4, P5)
```

根据 [`31_V3D.md`](../syscalls/31_V3D.md:117) 的 syscall 语义，`V3DMotion` 的第五参数是 motion type：

| 数值 | V3D 类型 |
|---:|---|
| `1` | Linear |
| `2` | Accelerate |
| `3` | Decelerate |
| `4` | Rebound |
| `5` | Bounce |

因此本函数的默认运动类型是：

> **`3`，即 Decelerate / 减速型运动。**

这与普通剧情镜头运动的视觉需求相符：开始移动较快，接近目标时减速停止。

注意：这里的 `P4` 不是 `P3` 的“时长模式”，也不是 `P9` 的场景模式；它是直接传给 V3D motion 层的 easing/type 参数。

## 11. 第七阶段：使用上一帧状态补齐目标坐标

函数对前三个目标坐标分别做缺省处理：

```lua
if P0 == nil then
    P0 = G[1176]
end

if P1 == nil then
    P1 = G[1177]
end

if P2 == nil then
    P2 = G[1178]
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:116-139)。

因此：

| 参数 | 缺省来源 | 语义 |
|---|---|---|
| `P0` | `G[1176]` | 目标 X |
| `P1` | `G[1177]` | 目标 Y |
| `P2` | `G[1178]` | 目标 Z |

这说明 `G[1176..1178]` 是本函数维护的**最近一次 V3D 目标坐标缓存**。

### 11.1 为什么需要坐标缓存

V3D syscall 允许目标坐标使用 `nil` 表示“保留当前坐标”，但在这个上层包装器中，脚本还需要在以下地方使用目标值：

- 辅助层 prim 187 的同步处理；
- 后续全局状态记录；
- 对下一次调用提供默认坐标。

因此，`f_000526A3` 先把 `nil` 坐标转换成缓存值，再统一向下游传递。

### 11.2 与 [`V3DSet`](../syscalls/31_V3D.md:68) 的区别

`G[1176..1178]` 不是 V3D 引擎内部的当前坐标本身，而是脚本层缓存。真正的全局 V3D 当前坐标由引擎的 V3D motion 容器维护，详见 [`31_V3D.md`](../../03_data/syscall_db/syscall_spec.json:7722)。

## 12. 第八阶段：特殊全局状态下修正运动时长

### 12.1 `G[1949] == 0` 且 `G[250] == nil`

函数检查：

```lua
if G[1949] == 0 and G[250] == nil then
    P3 = 1
    ControlPulse()
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:140-152)。

这表示在某个特殊场景状态下，本次 V3D 运动会被强制压缩为 `1 ms`，并发出一个 [`ControlPulse`](../syscalls/03_Control.md:49)。

结合 [`ControlPulse`](../syscalls/03_Control.md:96) 的语义，它相当于：

> **让当前演出进入快进/立即推进状态，避免在某种控制状态下继续执行完整时长的镜头运动。**

### 12.2 `G[1972] == 0` 且 `G[250] == nil`

函数再次检查：

```lua
if G[1972] == 0 and G[250] == nil then
    P3 = 1
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:153-164)。

这一分支同样将时长强制为 `1`，但不再发出第二次 `ControlPulse`。

### 12.3 `G[1972] == 1` 且 `G[250] == nil`

```lua
if G[1972] == 1 and G[250] == nil then
    P3 = (P3 / 3) * 2
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:165-180)。

也就是把时长缩短为原来的三分之二：

```text
P3' = P3 × 2 / 3
```

这说明 `G[1972]` 参与某种全局演出速度/跳过模式控制：

- `G[1972] == 0`：直接压缩到近似立即完成；
- `G[1972] == 1`：时长缩短为 `2/3`；
- 其他值：保持前面归一化得到的时长。

### 12.4 `G[250]` 的作用

上述三个分支都要求 `G[250] == nil`。因此 `G[250]` 可以看作一个**特殊演出占用/控制锁/手动过渡状态标志**：当它存在时，上述自动快进或时长缩短逻辑不会执行。

仅凭本函数无法确定 `G[250]` 的正式业务名称，但可以确定它是这些时长修正分支的共同抑制条件。

## 13. 第九阶段：记录时长并再次触发快进脉冲

经过上述处理后：

```lua
G[88] = P3
G[89] = G[88]
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:181-185)。

因此：

- `G[88]` 保存本次最终运动时长；
- `G[89]` 保存同一个值，可能供两个不同的下游流程读取。

接着：

```lua
if G[36] == true then
    ControlPulse()
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:186-191)。

这表明 `G[36]` 是另一个“当前需要快进/立即推进”的全局标志。当它为真时，本函数在真正启动 V3D motion 前发出一次快进脉冲。

综合起来，`ControlPulse` 可能在三类情况下出现：

1. [`G[1949] == 0`](Sakura_hcb_ir/Sakura/f_000526A3.lua:141) 且 [`G[250] == nil`](Sakura_hcb_ir/Sakura/f_000526A3.lua:144)；
2. [`G[36] == true`](Sakura_hcb_ir/Sakura/f_000526A3.lua:186)；
3. 其他上层剧情/菜单状态机主动触发。

因此，本函数会把“用户快进、场景特殊模式和三维运动”统一接入 FVP 的快进机制。

## 14. 第十阶段：辅助图层 prim 187 的同步处理

函数判断：

```lua
if G[1973] == true and P8 ~= 0 then
    f_00052882(P2, P3, P10)
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:192-206)。

### 14.1 `G[1973]`

已有 [`BGimageLoading函数共性总结.md`](BGimageLoading函数共性总结.md:258) 和 [`f_00015543详细解析.md`](./f_00015543详细解析.md:302) 表明，`G[1973]` 控制背景的辅助/模糊层资源是否参与流程，相关图元包括 prim 187。

因此这里的逻辑可以表述为：

> 当背景辅助层功能启用，且调用方没有通过 `P8 == 0` 禁止时，对 prim 187 执行与当前 V3D 运动同步的透明度/演出处理。

### 14.2 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 的具体行为

[`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 接收：

```lua
f_00052882(P2, P3, P10)
```

其主体会：

1. 以传入的第二个值减去 `250`；
2. 把结果限制在 `0..255`；
3. 读取并更新 [`G[71]`](Sakura_hcb_ir/Sakura/f_00052882.lua:26)；
4. 如果第三参数为 `nil`，直接对 prim 187 执行 [`PrimSetAlpha`](../syscalls/21_Prim.md:1)；
5. 如果第三参数非 `nil`，则调用 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 执行更复杂的图元运动/透明度处理。

所以 `P10` 不是 V3D motion type，也不是普通等待时间，而是：

> **控制辅助层 prim 187 采用直接设 alpha 还是采用完整运动包装的附加参数。**

### 14.3 为什么传入 `P2` 和 `P3`

这里传入的是：

- `P2`：V3D Z 目标值；
- `P3`：最终运动时长。

这说明辅助层的透明度/深度表现可能与三维 Z 位置和镜头运动时长同步。prim 187 并不是独立于 V3D 的普通背景图，而是参与三维场景切换的辅助视觉层。

## 15. 第十一阶段：标准 UI/场景刷新流程

函数判断：

```lua
if P7 == 1 or P7 == 0 then
    f_0005073F()
    f_0004A5DE(nil, nil, nil, nil)
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:207-222)。

### 15.1 [`f_0005073F()`](Sakura_hcb_ir/Sakura/f_0005073F.lua:1)

该函数只是调用：

```lua
f_00049EC9(0, nil)
```

因此它是一个很薄的场景/UI 状态包装器，可能负责关闭、重置或刷新某一组过渡状态。

### 15.2 [`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:1)

[`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:1) 会：

1. 调用 [`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1)；
2. 读取 [`InputGetState`](../syscalls/12_Input.md:1)；
3. 根据输入和 [`G[1964]`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:14) 判断是否提前返回。

而 [`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1) 是一个复杂的场景文本/UI 状态处理函数，会根据当前文本模式、对话框状态、过渡状态和若干全局变量刷新多个 UI prim。

因此，`P7` 的实际作用不是“是否执行 V3D”，而是：

> **是否在三维运动启动前，执行标准的场景/UI 状态准备链。**

需要特别注意：默认 `P7` 会被设为 `0`，而 `0` 仍然进入该刷新分支。因此“默认值为 0”并不等于“默认跳过 UI 刷新”。

## 16. 第十二阶段：真正启动全局 V3D motion

核心 syscall 为：

```lua
V3DMotion(P0, P1, P2, P3, P4, P5)
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:223-230)。

根据 [`31_V3D.md`](../syscalls/31_V3D.md:108)，六个参数是：

| 本函数参数 | V3DMotion 参数 | 语义 |
|---|---|---|
| `P0` | `dst_x` | 目标全局 V3D X |
| `P1` | `dst_y` | 目标全局 V3D Y |
| `P2` | `dst_z` | 目标全局 V3D Z |
| `P3` | `duration` | 最终运动时长，单位毫秒 |
| `P4` | `typ` | easing/运动类型，默认 `3` |
| `P5` | `reverse` | reverse 标志；非 nil 通常表示启用 |

### 16.1 它不是 prim 运动

[`V3DMotion`](../syscalls/31_V3D.md:108) 不接受 prim ID，也不直接改变某个图元的二维位置。它操作的是全局 V3D 坐标。

具有 V3D 投影属性的 prim 会在渲染时使用这些全局坐标，最终产生：

- 视角/相机偏移；
- 深度变化；
- 透视缩放；
- 与 prim 自身 Z 值结合后的三维投影效果。

因此，把 `f_000526A3` 称为“移动背景 prim 186”是不准确的。更准确的说法是：

> **它移动全局三维投影状态，多个启用 V3D 投影的 prim 会共同响应。**

### 16.2 返回值

[`V3DMotion`](../syscalls/31_V3D.md:112) 返回 `Nil`。因此 `f_000526A3` 不产生有意义的业务返回值，调用方通常只关心其副作用和是否阻塞等待。

## 17. 第十三阶段：更新 V3D 目标缓存

启动 motion 后，函数立即执行：

```lua
G[1176] = P0
G[1177] = P1
G[1178] = P2
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:231-236)。

这里保存的是本次调用提交的目标值，而不是每一帧的实时插值值。

例如调用：

```lua
f_000526A3(0, 200, 300, 900, ...)
```

执行后：

```lua
G[1176] = 0
G[1177] = 200
G[1178] = 300
```

下一次如果调用：

```lua
f_000526A3(nil, nil, 350, 500, ...)
```

则会被补齐为：

```lua
V3DMotion(0, 200, 350, 475, ...)
```

这正是该缓存设计的用途。

## 18. 第十四阶段：可选等待循环

最后，函数根据 `P6` 判断是否等待：

```lua
if P6 == 1 then
    while true do
        if not V3DMotionTest() then
            break
        end
        if P3 <= 1 then
            break
        end
        ThreadNext()
    end
end
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:237-253)。

### 18.1 `P6 == 1`

当 `P6 == 1` 时，函数不会在发出 [`V3DMotion`](../syscalls/31_V3D.md:108) 后立即返回，而是：

1. 调用 [`V3DMotionTest()`](../syscalls/31_V3D.md:266)；
2. 如果仍在运动，则调用 [`ThreadNext`](../syscalls/27_Thread.md:1) 让出当前帧；
3. 下一帧继续检查；
4. 直到运动结束或 `P3 <= 1`。

### 18.2 `V3DMotionTest()` 的准确含义

[`V3DMotionTest()`](../syscalls/31_V3D.md:266) 只返回：

- `True`：全局 V3D motion 仍在运行；
- `Nil`：没有正在运行的 V3D motion。

它不返回当前坐标，也不返回剩余时间。

### 18.3 `ThreadNext()` 的作用

[`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1) 只是对 [`ThreadNext`](../syscalls/27_Thread.md:1) 的包装。这里通过它让出一帧，等待引擎帧循环推进 V3D motion。

因此 `P6 == 1` 的行为可以准确称为：

> **同步等待全局 V3D motion 完成。**

而 `P6 == 0` 则是：

> **异步启动 V3D motion，函数本身不等待。**

### 18.4 为什么同时检查 `P3 <= 1`

当时长已经被前面的特殊状态压缩为 `1` 时，再进入等待循环没有意义。因此该判断可以避免在“立即完成”路径中执行无效轮询。

## 19. 最终收尾：清除 `G[17]`

函数正常结束时执行：

```lua
G[17] = nil
return
```

对应 [`f_000526A3.lua`](Sakura_hcb_ir/Sakura/f_000526A3.lua:254-257)。

这表示本轮 V3D 调度已经完成。需要区分：

- `G[17]`：本函数执行期间的临时“正在处理”标志，结束时清除；
- `G[18]`：完整路径开头设置，但本函数不清除，属于较长期的场景/运动状态；
- `G[1176..1178]`：最近一次目标坐标缓存；
- `G[88]/G[89]`：最近一次最终运动时长缓存；
- `G[310]`：重入/短路路径状态标志。

## 21. 常见调用的语义还原

### 21.1 普通异步镜头移动

```lua
f_000526A3(0, 200, 300, 900, nil, nil, nil, nil, nil, nil, nil, nil)
```

等价于近似：

```lua
V3DMotion(
    0,       -- 目标 X
    200,     -- 目标 Y
    300,     -- 目标 Z
    875,     -- 900 - 25
    3,       -- Decelerate
    nil      -- reverse 关闭
)
```

并且：

- `P6=nil -> 0`，不等待；
- `P7=nil -> 0`，执行标准场景/UI 刷新；
- `P8=nil -> 1`，允许 prim 187 辅助层处理；
- `P9=nil -> 1`，设置 `G[28]=1`；
- `P11=nil`，执行 [`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1)。

### 21.2 同步等待镜头移动

```lua
f_000526A3(0, 0, 300, 1000, 3, nil, 1, 0, 1, 1, nil, nil)
```

近似含义：

- 移动到 `(0,0,300)`；
- 使用 `975 ms` 的运动时长；
- 使用 motion type `3`；
- `P6=1`，等待 V3D motion 完成；
- `P8=1`，处理辅助层；
- `P9=1`，设置 `G[28]=1`。

### 21.3 跳过辅助层与前置刷新

```lua
f_000526A3(0, 200, 300, 900, nil, nil, 0, 2, 0, 1, nil, -1)
```

近似含义：

- `P8=0`：跳过 prim 187 辅助层处理；
- `P7=2`：不进入 `P7==0 or P7==1` 的标准 UI 刷新分支；
- `P11=-1`：跳过 [`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1)；
- 仍然执行主 [`V3DMotion`](../syscalls/31_V3D.md:108)。

## 22. 与相关函数的分工

### 22.1 与 [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 的关系

| 函数 | 定位 |
|---|---|
| [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) | 简化的 V3D 复位/重启动作，固定使用较简单的 motion 参数 |
| [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) | 完整的 V3D 运动调度器，负责参数修正、辅助层、UI、快进和可选等待 |

`G[310] == 1` 时，`f_000526A3` 会退化为调用 `f_0005261B` 的短路路径。

### 22.2 与 [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 的关系

[`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 只是更上层的 12 参数转发包装器，最终进入 [`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:1)。它不能单独代表 V3D motion 的全部行为。

分析实际三维镜头效果时，应重点追踪：

```text
剧情函数
  -> f_0005207E / f_000519FC
  -> f_000526A3
  -> V3DMotion
  -> 帧循环更新全局 V3D
  -> 启用 V3D 投影的 prim 重算模型矩阵
```

### 22.3 与 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 的关系

`f_00052882` 只处理 prim 187 辅助层的 alpha/运动表现，不负责全局 V3D 坐标本身。它是 `f_000526A3` 在背景模糊/辅助层启用时调用的同步子流程。

### 22.4 与 [`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:1) 的关系

`f_0004A5DE` 负责场景/UI 状态准备和输入状态相关判断；它不是 V3D motion syscall 的包装器。`f_000526A3` 在启动主运动前调用它，是为了让 UI/场景图元处于兼容状态。

## 23. 对研究和注入的实际意义

如果要在新剧情或新 function 中复用 Sakura 的三维镜头效果，不能只复制：

```lua
V3DMotion(x, y, z, duration, typ, reverse)
```

因为 `f_000526A3` 还承担了大量前置和后置工作：

1. 坐标缺省缓存；
2. 时长的 `-25` 规则；
3. 快进状态下的时长压缩；
4. `G[17]`、`G[18]`、`G[28]`、`G[88]`、`G[89]` 等全局状态维护；
5. 背景辅助层 prim 187 的同步；
6. UI/场景 prim 的准备；
7. 可选同步等待。

如果只调用 [`V3DMotion`](../syscalls/31_V3D.md:108)，可能出现：

- 辅助模糊层没有同步；
- 对话框/UI 图元处于不正确显示状态；
- 新场景第一次运动时出现突兀跳变；
- 后续使用 `nil` 坐标的镜头无法继承正确目标值；
- 需要等待运动结束的剧情逻辑提前继续执行。

### 23.1 最小异步复用方案

如果只需要最小化的异步 V3D 运动，理论上可以使用：

```lua
V3DMotion(dst_x, dst_y, dst_z, duration, 3, nil)
```

但这不等价于完整的 `f_000526A3`。

### 23.2 更接近原作的复用方案

若希望兼容原作状态，至少需要同时处理：

```lua
G[1176] = dst_x
G[1177] = dst_y
G[1178] = dst_z
G[88] = duration
G[89] = duration
G[17] = true
V3DMotion(dst_x, dst_y, dst_z, duration, motion_type, reverse)
G[17] = nil
```

若场景启用了背景辅助层，还应根据 [`G[1973]`](Sakura_hcb_ir/Sakura/f_000526A3.lua:193) 和 `P8` 调用 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1)。

## 24. 最终结论

1. [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) 是 Sakura.hcb 的全局 V3D 运动核心控制函数。
2. 它有 `12` 个真实入参，但 Lua-like 导出器把真实参数名整体右移了一位；本文使用 `P0..P11` 消除歧义。
3. `P0/P1/P2` 是全局 V3D 目标 X/Y/Z。
4. `P3` 是上层时长参数，默认 `495`，常规路径最终变为 `P3-25`，小于等于 `24` 时压缩为 `1`。
5. `P4` 是 V3D motion type，默认 `3`，即 Decelerate。
6. `P5` 直接作为 V3DMotion 的 reverse 参数传递。
7. `P6` 是是否同步等待 V3D motion 完成的开关。
8. `P7` 控制是否进入标准 UI/场景准备链；`0/1` 都会进入，其他值会跳过。
9. `P8` 控制是否处理背景辅助层 prim 187，默认开启。
10. `P9` 控制 `G[28]` 的模式值。
11. `P10` 是 prim 187 辅助层处理参数。
12. `P11 == -1` 时跳过 [`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1)，否则执行该场景/UI 前置刷新。
13. `G[310] == 1` 时函数走 [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 短路路径，而不会执行完整流程。
14. `G[1176..1178]` 保存最近一次 V3D 目标坐标，用于后续 `nil` 参数补齐。
15. `G[88]/G[89]` 保存本次最终运动时长。
16. `G[17]` 是本轮 V3D 调度期间的临时活动标志，结束时清除。
17. 函数本身没有有意义的返回值，核心价值在于它产生的全局状态、图层同步、V3D motion 和可选等待副作用。

最准确的总括是：

> **`f_000526A3` 不是单纯的 `V3DMotion` 包装器，而是 Sakura 场景系统中负责“准备状态 → 修正镜头参数 → 同步辅助层/UI → 启动全局三维运动 → 可选等待 → 清理活动标志”的完整 V3D 演出控制器。**
