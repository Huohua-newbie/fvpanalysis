# [`f_0004B135()`](Sakura_hcb_ir/Sakura/f_0004B135.lua:1) 逐条反汇编与作用分析

## 1. 函数定位与总体结论

- 原始函数：[`f_0004B135.lua`](Sakura_hcb_ir/Sakura/f_0004B135.lua:1)
- HCB：[`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb)
- IR：[`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json)
- 函数地址范围：`0x0004B135–0x0004B1D1`
- HCB 文件偏移：`307509–307665`
- 字节长度：`157` 字节
- 函数序言：`init_stack args=5, locals=2`
- 显式入参数量：`5`
- 局部变量数量：`2`
- 直接调用的内部函数：无
- 直接调用的 syscall：无

本函数是一个**场景上下文模式批量设置函数**。它不直接装载背景、不直接调用图像或文本 syscall，而是把调用者传入的场景参数整理后写入一组全局槽，供后续背景、场景差分、过渡和演出函数读取。

其主要副作用是：

- `G[1244]`：保存一个经过 `1..12` 范围检查的场景上下文编号；
- `G[1245]`：保存第二个可选场景参数；
- `G[1246]`：保存第三个场景参数，缺省时可由 `G[1245]` 的值派生为 `1` 或 `2`；
- `G[1247]`：保存当前场景模式/差分模式的主要编号；
- `G[32]`：特殊保存/覆盖模式标志；
- `G[33]`：在特殊模式下备份旧的 `G[1247]`。

因此，本函数更准确的名称是：

> **场景上下文参数与背景差分模式全局状态设置函数。**

## 3. 调用样本分析

### 3.1 [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:13)

开场调用为：

```lua
f_0004B135(2, 4, 1, 1, nil)
```

按修正后的参数顺序：

```text
a0 = 2
a1 = 4
a2 = 1
a3 = 1
a4 = nil
```

结果：

```text
G[1244] = 1
G[1245] = 4
G[1246] = 1
G[1247] = 2
G[32]   不进入特殊保存分支
```

这个调用说明 `a0` 确实是主场景/背景模式编号，`a2` 是一个受 `1..12` 限制的上下文编号，而 `a3` 可以显式覆盖 `G[1246]`。

### 3.2 [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:36)

随后又调用：

```lua
f_0004B135(13, nil, nil, nil, nil)
```

结果：

- `a2 == nil`，因此不写 `G[1244]`；
- `a1 == nil`，因此不写 `G[1245]`；
- `a3 == nil`，根据当前 `G[1245]` 决定是否派生 `G[1246]`；
- `a0 = 13`，直接写入 `G[1247] = 13`；
- `a4 == nil`，走普通覆盖模式，若此前 `G[32]` 为真则会被清空。

值得注意的是：`a2` 的合法范围检查只影响 `G[1244]`，并不限制 `a0`。因此 `a0 = 13` 并不违反本函数的范围检查。

## 4. 全局槽下游追踪

### 4.1 `G[1244]`

本函数只负责在 `a2` 合法时写入 `G[1244]`。目前它的直接下游语义不足以单独命名为某一种资源编号，但可以确定：

- 允许值为 `1..12`；
- `nil`、`<=0`、`>=13` 会被清空为 `nil`，之后不写入 `G[1244]`；
- 它属于场景上下文参数组，与 `G[1245]`、`G[1246]` 配套。

后续应统计所有 `G[1244]` 读取点，并对照对应场景函数实际选择的资源或过渡模式。

### 4.2 `G[1245]`

`G[1245]` 保存 `a1`。它还参与 `a3 == nil` 时对 `G[1246]` 的派生：

```lua
if a3 == nil then
    if G[1245] == 1 then
        G[1246] = 1
    elseif G[1245] == 2 then
        G[1246] = 2
    end
end
```

所以 `G[1245]` 至少具有“场景上下文类别/模式”的作用，而不是单纯临时变量。

### 4.3 `G[1246]`

`G[1246]` 有两种来源：

1. `a3` 非 `nil` 时直接使用 `a3`；
2. `a3 == nil` 时，根据 `G[1245] == 1/2` 自动派生。

这表明 `G[1246]` 是一个可被显式覆盖、也可由上一级模式自动推导的场景子模式值。

### 4.4 `G[1247]`

`G[1247]` 是本函数最重要的全局槽之一。大量背景函数会读取它，并将其与 `1、2、3、4...` 等常量比较。例如：

- [`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:128)
- [`f_000107EC()`](Sakura_hcb_ir/Sakura/f_000107EC.lua:146)
- [`f_00016F8E()`](Sakura_hcb_ir/Sakura/f_00016F8E.lua:29)

在背景函数中，`G[1247]` 会影响 `BGxxx_000`、`BGxxx_010`、`BGxxx_020`、`BGxxx_030` 等背景差分选择；在 [`f_00016F8E()`](Sakura_hcb_ir/Sakura/f_00016F8E.lua:29) 中，它还参与把场景模式转换为 `G[1253]`、`G[1254]` 等更底层背景/过渡参数。

因此，`G[1247]` 可以暂定为：

> **当前场景主模式/背景差分模式编号。**

### 4.5 `G[32]` 与 `G[33]`

当 `a4 == -1` 时，本函数执行：

```lua
G[32] = true
G[33] = G[1247]
G[1247] = a0
```

这是一组典型的“保存旧模式、启用特殊模式、写入新模式”操作。

普通模式则执行：

```lua
G[32] = nil
G[1247] = a0
```

因此：

- `G[32]`：特殊场景模式/保存模式活动标志；
- `G[33]`：特殊模式下保存的旧 `G[1247]`。

配套函数 [`f_0004B1D2()`](Sakura_hcb_ir/Sakura/f_0004B1D2.lua:1) 和 [`f_0004B1DD()`](Sakura_hcb_ir/Sakura/f_0004B1DD.lua:1) 说明这套状态确实存在保存/恢复需求：

```lua
f_0004B1D2()
-- G[1248] = G[1247]

f_0004B1DD()
-- G[1247] = G[1248]
-- 再调用 f_0004B135(G[1247], nil, nil, nil, nil)
```

## 7. 等价伪代码

function f_0004B135(a0, a1, a2, a3, a4)
    -- a2 只接受 1..12
    if a2 <= 0 or a2 >= 13 then
        a2 = nil
    end

        G[1244] = a2
    end

    if a1 ~= nil then
        G[1245] = a1

            G[32] = nil
            G[1247] = a0

            G[32] = true
            G[33] = G[1247]
            G[1247] = a0
        end
    end
end
