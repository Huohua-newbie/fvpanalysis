# [`f_0009D283()`](Sakura_hcb_ir/Sakura/f_0009D283.lua:1) 详细解析

## 1. 函数定位

- 函数地址：`0x0009D283`
- IR/Lua-like 文件：[`f_0009D283.lua`](Sakura_hcb_ir/Sakura/f_0009D283.lua:1)
- 函数序言：`init_stack args=2, locals=0`
- 固定操作对象：prim `495`
- 固定资源：`EF_e17_1`
- 直接调用：
  - [`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1)
  - [`f_0006A92E()`](Sakura_hcb_ir/Sakura/f_0006A92E.lua:1)
  - [`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1)
  - [`f_00037476()`](Sakura_hcb_ir/Sakura/f_00037476.lua:1)
- 直接 syscall：`PrimSetBlend`、`PrimSetAlpha`

当前可将其命名为：

> **`EF_e17_1` 演出覆盖层与特殊文本/UI 状态的联动开关。**

它不属于上一节 [`$回想_effect`](./f_0009CF45详细解析.md:1) 的 prim `493` / `EF_e08` 滤镜控制器。它单独管理 prim `495` 和 `EF_e17_1`，并同时写入 `G[117]`；后者会改变消息窗口、文本演出计时与部分过渡 UI 的处理路径。

## 2. 必须修正的参数编号问题

导出结果显示：

```lua
function f_0009D283(a0, a1)
    -- init_stack args=2, locals=0
    S0 = a1
    ...
    S0 = a2
    ...
end
```

这里与前面已确认的导出器问题一致：`init_stack args=2`，但 Lua-like 本体使用 `a1/a2`。因此本文以真实参数位置命名：

| 真实参数 | Lua-like 显示名 | 作用 |
|---|---|---|
| `p0` | `a1` | 特殊状态启用/关闭主开关 |
| `p1` | `a2` | 覆盖层资源加载/保留策略选择器 |

不能将 Lua-like 中未出现的 `a0` 当作真实的第一个业务参数。

## 3. 原始控制流的语义化版本

```lua
function f_0009D283(p0, p1)
    if p0 == 1 then
        -- 每次进入启用路径，先清理旧的 495
        f_00037421(495)
        G[117] = 0

        -- -2 是“只启用状态、不装载图像”的特殊值
        if p1 ~= -2 then
            f_000373A5(495, "EF_e17_1", nil, nil)
            PrimSetBlend(495, 0)
            PrimSetAlpha(495, 220)
            f_00037476(495, 11)
        end

        G[117] = 1
    else
        -- -1 是“不要清空 prim 495”的保留值
        if p1 ~= -1 then
            f_00037421(495)
        end

        G[117] = 0
    end
end
```

其中 [`f_0006A92E()`](Sakura_hcb_ir/Sakura/f_0006A92E.lua:1) 只是写入：

```lua
G[117] = value
```

所以 `G[117]` 正是本函数维护的特殊演出/文本 UI 状态位。

## 4. prim `495` 的实际初始化

在 `p0 == 1` 且 `p1 != -2` 时，函数执行：

```lua
f_00037421(495)
f_000373A5(495, "EF_e17_1", nil, nil)
PrimSetBlend(495, 0)
PrimSetAlpha(495, 220)
f_00037476(495, 11)
```

逐项含义：

1. [`f_00037421(495)`](Sakura_hcb_ir/Sakura/f_00037421.lua:1) 清理旧资源、将 prim 移出父组并置空：它依次调用 `GraphLoad(495,nil)`、`PrimGroupOut(495)`、`PrimSetNull(495)`；
2. [`f_000373A5(495,"EF_e17_1",nil,nil)`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1) 将 `EF_e17_1` 绑定到 prim `495`；
3. `PrimSetBlend(495,0)` 设置该覆盖层使用混合模式 `0`；
4. `PrimSetAlpha(495,220)` 将其固定透明度设为 `220`，约为完全不透明 `255` 的 86%；
5. [`f_00037476(495,11)`](Sakura_hcb_ir/Sakura/f_00037476.lua:1) 最终执行 `PrimGroupIn(495,11)`，将它加入父组 `11`，随后运行一轮公共分组重建 [`f_00037496()`](Sakura_hcb_ir/Sakura/f_00037496.lua:1)。

因此 prim `495` 是一个随父组 `11` 显示的固定半透明图像覆盖层，而不是背景资源或角色立绘。

## 5. 参数行为表

| 调用 | prim `495` | `G[117]` | 用途 |
|---|---|---:|---|
| `f_0009D283(1, nil)` | 清理旧对象后加载 `EF_e17_1`，blend `0`，alpha `220`，加入 group `11` | `1` | 显示 `EF_e17_1` 覆盖层并启用特殊 UI 状态 |
| `f_0009D283(1, -2)` | 仅清理旧对象，不重新加载 `EF_e17_1` | `1` | 只启用特殊 UI/文本状态；不显示该覆盖层 |
| `f_0009D283(0, nil)` | 清理 prim `495` | `0` | 常规完整关闭 |
| `f_0009D283(0, -1)` | 保留 prim `495` 当前资源/分组 | `0` | 只关闭特殊 UI 状态，不主动清图；需结合调用点谨慎使用 |

`p1=-2` 与 `p1=-1` 的方向不能混淆：

- `-2` 仅在**启用路径**中有特殊意义，表示跳过 `EF_e17_1` 的加载；
- `-1` 仅在**关闭路径**中有特殊意义，表示跳过 `f_00037421(495)`，保留图元资源。

## 6. `G[117]` 的跨系统影响

`G[117]` 并非局部标记。它被多个消息/覆盖层/过渡函数读取，说明 `f_0009D283` 不只是“显示一张 EF 图”。

### 6.1 对普通消息窗口布局的影响

在 [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:192) 中，只有当 `G[117] != 1` 时，才会对 prim `787`、`551`、`552` 执行一组常规位置运动：

```lua
if G[117] ~= 1 then
    -- 调整 787、551、552 的通常 UI 位置
end
```

所以 `G[117]=1` 会跳过这套普通 UI/消息元素的重排，说明该标记选择了一套特殊显示布局。

### 6.2 对过渡 UI 显隐的影响

[`f_00049EC9()`](Sakura_hcb_ir/Sakura/f_00049EC9.lua:83) 与 [`f_00049EC9()`](Sakura_hcb_ir/Sakura/f_00049EC9.lua:169) 都根据 `G[117]` 决定 prim `513`、`346`、`514` 是否显示。这些对象属于消息/覆盖层相关 UI。

因此启用 `f_0009D283` 后，不只是 prim `495` 出现，周围 UI 的淡入、淡出与显隐规则也会切到特殊分支。

### 6.3 对文本演出计时的影响

[`f_0004D3E2()`](Sakura_hcb_ir/Sakura/f_0004D3E2.lua:8) 读取 `G[117]`，并与 `G[1193]`、`G[1276]`、`G[1277]` 等文本呈现状态共同调整 `G[237]`：

```lua
if G[117] == 1 then
    -- 按当前文本模式对 G[237] 做 3 倍、3 倍或 1/2、1/3 等换算
end
```

尽管 `G[237]` 的最终业务名还未完全确定，它已被消息/文本流程使用；因此 `G[117]` 会影响特殊文本演出的时序或速度计算。

综合来看，`G[117]` 可以暂命名为：

> **EF_e17 特殊覆盖层/特殊文本 UI 模式启用标记。**

## 7. 与 `f_00097A34` 的调用关系

[`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:30) 在 startmoji 演出准备阶段调用：

```lua
f_0009D283(1, -2)
```

这会：

1. 清理可能残留的 prim `495`；
2. 不加载 `EF_e17_1`；
3. 设置 `G[117]=1`。

所以该调用的准确解释不是“加载 `EF_e17_1`”，而是：

> **为 startmoji 演出启用与 `EF_e17` 共用的特殊文本/UI 布局状态，同时确保实际 `EF_e17_1` 覆盖层不显示。**

在收尾阶段，[`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:472) 调用：

```lua
f_0009D283(0, nil)
```

这会清理 prim `495` 并恢复 `G[117]=0`，让后续流程回到普通 UI/文本布局规则。

## 8. 与 `$回想_effect` 的关系

两组函数分别控制不同层：

| 功能 | 底层入口 | 固定 prim | 资源 |
|---|---|---:|---|
| 回想/非现实时间线滤镜 | [`f_0009CF45()`](Sakura_hcb_ir/Sakura/f_0009CF45.lua:1) → [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) | `493` | `EF_e08`、`EF_e08_B..O` |
| EF_e17 特殊覆盖层与文本 UI 状态 | [`f_0009D283()`](Sakura_hcb_ir/Sakura/f_0009D283.lua:1) | `495` | `EF_e17_1` |

它们都会以图元覆盖层的形式参与演出，但不能合并为同一个滤镜系统：

- prim `493` 由 `$回想_effect` 控制；
- prim `495` 由 `f_0009D283` 控制；
- `f_0009D283` 还独占写入 `G[117]`，对消息与 UI 系统有明确联动。

## 9. 结论

1. [`f_0009D283()`](Sakura_hcb_ir/Sakura/f_0009D283.lua:1) 固定操作 prim `495`，其资源为 `EF_e17_1`。
2. `p0=1` 启用 `G[117]=1` 的特殊文本/UI 状态；若 `p1!=-2`，还会显示半透明 `EF_e17_1` 覆盖层。
3. `p0=0` 关闭 `G[117]`；若 `p1!=-1`，还会清理 prim `495`。
4. `f_0009D283(1,-2)` 是“状态 ON、图像 OFF”的特殊预设，不应误判为普通的覆盖图加载。
5. `f_0009D283(0,nil)` 是通常的完整关闭路径。
6. `G[117]` 会改变消息窗口重排、覆盖层 UI 显隐和文本演出计时，是本函数的重要副作用。
7. 该函数与 `$回想_effect` 相邻出现时，二者分别处理 `EF_e17_1/495` 与 `EF_e08/493` 两个不同的画面层。

## 10. 待验证项
