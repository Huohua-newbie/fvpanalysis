# [`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 逐条反汇编与参数解析

## 1. 核心结论

[`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 是 Sakura 的**过渡图层/遮罩颜色准备函数**。它并不直接执行一个单独的 `Dissolve`，而是完成以下工作：

1. 清理旧的过渡相关 prim：`188/189/1590/1591`；
2. 初始化 `G[944]` 和一个过渡辅助图元 `210`；
3. 根据第二参数选择主过渡层 `prim 186` 或 `prim 187`；
4. 根据第一、第三至第六、第八参数，决定过渡图层使用的资源、颜色、尺寸和资源目录；
5. 对被选中的 prim 设置 tile、XY 和 OP；
6. 设置或清除相关过渡图层状态；
7. 调用 [`f_00051202()`](Sakura_hcb_ir/Sakura/f_00051202.lua:1) 做 OP/线程收尾；
8. 在 `G[68]` 有效时执行 [`DissolveWait(true)`](../syscalls/06_Dissolve.md:1)。

最重要的修正是：

> `f_00050EDB()` 的第三参数是**颜色预设选择器/颜色通道的第一个分量**，不是 `-1/-2` 形式的抽象“过渡模式号”。

因此：

- `f_00050EDB(nil,1,-1,nil,nil,nil,nil,nil)`：准备 `prim 186` 的**黑色过渡层**；
- `f_00050EDB(nil,1,-2,nil,nil,nil,nil,nil)`：准备 `prim 186` 的**白色过渡层**。

这就是 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1) 与 [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 使用 `-1/-2` 后表现不同的根本原因。

## 3. 参数槽位修正

当前 Lua-like 导出的函数头是：

```lua
function f_00050EDB(a0, a1, a2, a3, a4, a5, a6, a7)
```

但由于导出器存在参数槽编号偏移，函数体中的 `a1..a8` 才对应 8 个真实外部参数。建议统一使用 `P1..P8`：

| 真实参数 | 原始栈槽 | 导出函数体名称 | 主要作用 |
|---|---:|---|---|
| `P1` | `-9` | `a1` | 图像资源名/图像 basename；无第三参数时进入资源加载路径 |
| `P2` | `-8` | `a2` | 主过渡层选择：`1 -> prim 186`，`2 -> prim 187` |
| `P3` | `-7` | `a3` | 颜色预设选择器或 RGBA 第一个分量 |
| `P4` | `-6` | `a4` | 自定义 RGBA 第二个分量 |
| `P5` | `-5` | `a5` | 自定义 RGBA 第三个分量 |
| `P6` | `-4` | `a6` | 自定义 RGBA 第四个分量/alpha 分量 |
| `P7` | `-3` | `a7` | 特效槽位重建开关；`0` 时额外重建特效状态 |
| `P8` | `-2` | `a8` | 图像资源目录/资源类别选择器，传给 `f_00051038()` |

注意：`P3..P6` 在功能上组成颜色参数，但 `P3` 具有特殊负值预设含义。因此它不是始终意义单一的普通 R 通道。

## 4. 逐条反汇编

## 4.1 函数初始化与旧图层清理

| 地址 | 指令 | 作用 |
|---|---|---|
| `0x00050EDB` | `init_stack args=8, locals=0` | 建立 8 参数栈帧。 |
| `0x00050EDE` | `push_i16 188` | 压入 prim `188`。 |
| `0x00050EE1` | `call f_00037421` | 清理 prim `188`。 |
| `0x00050EE6` | `push_i16 189` | 压入 prim `189`。 |
| `0x00050EE9` | `call f_00037421` | 清理 prim `189`。 |
| `0x00050EEE` | `push_i16 1590` | 压入 prim `1590`。 |
| `0x00050EF1` | `call f_00037421` | 清理 prim `1590`。 |
| `0x00050EF6` | `push_i16 1591` | 压入 prim `1591`。 |
| `0x00050EF9` | `call f_00037421` | 清理 prim `1591`。 |

[`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1) 对每个 prim 执行：

```lua
GraphLoad(prim, nil)
PrimGroupOut(prim)
PrimSetNull(prim)
```

因此函数进入时首先清除四个旧的过渡/辅助图层，避免上一轮遮罩或演出资源残留。

## 4.2 初始化过渡状态

| 地址 | 指令 | 作用 |
|---|---|---|
| `0x00050EFE` | `push_i8 0` | 压入 `0`。 |
| `0x00050F00` | `pop_global 944` | 设置 `G[944] = 0`。 |
| `0x00050F03` | `call f_0004994E` | 清理辅助图元 `210`、隐藏 `788`，并将 `G[121]` 归零。 |

[`f_0004994E()`](Sakura_hcb_ir/Sakura/f_0004994E.lua:1) 的核心动作是：

```lua
MotionAnimStop(210)
PrimSetAlpha(210, 0)
f_0003767C(788, 0)
G[121] = 0
```

这里的 `210` 更像一个过渡辅助动画图元，`788` 则是相关的文本/界面图元之一。

## 4.3 规范化第七参数 `P7`

| 地址 | 指令 | 作用 |
|---|---|---|
| `0x00050F08` | `push_stack -3` | 读取 `P7`。 |
| `0x00050F0A` | `push_nil` | 与 `nil` 比较。 |
| `0x00050F0B` | `set_e` | 判断 `P7 == nil`。 |
| `0x00050F0C` | `jz 0x00050F15` | 若非 nil，跳过默认值。 |
| `0x00050F11` | `push_i8 1` | 压入 `1`。 |
| `0x00050F13` | `pop_stack -3` | `P7 = 1`。 |

等价逻辑：

```lua
if P7 == nil then
    P7 = 1
end
```

### P7 的后续用途

随后：

```lua
if P7 == 0 then
    f_00060795(nil, nil, nil)
    f_00066CB2()
end
```

对应 [`f_00050EDB.lua`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:23-33)。

因此：

- `P7 == 0`：额外清空/重建多路画面特效槽位；
- `P7 != 0`：跳过这一步；
- `P7 == nil`：默认变成 `1`，即跳过特效槽位重建。

更准确的名称是：

> **特效槽位重建开关**，而不是过渡颜色或 prim 选择参数。

### 4.4.2 P2 的直接作用

P2 主要选择两套过渡图层：

| P2 | 主过渡 prim | 相关状态 |
|---:|---:|---|
| `1` | `prim 186` | `G[69]` 记录/清理对应层状态 |
| `2` | `prim 187` | `G[70]` 记录/清理对应层状态 |

这不是“颜色模式”，而是：

> **当前要准备哪一个过渡层/遮罩层。**

在 [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:24) 中的调用：

```lua
f_00050EDB(nil, 1, -2, nil, nil, nil, nil, nil)
```

这里第二参数为 `1`，所以主要作用对象是 `prim 186`。


对应 [`f_00050EDB.lua`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:76-91)。

这说明第二类过渡层在重新使用前会清除旧图形并解除旧资源绑定。

## 4.7 第三参数 `P3` 是否存在：颜色参数路径与资源路径

函数在 `0x00050FA0` 附近判断 `P3`：

```lua
if P3 ~= nil then
    f_000510AE(P2, P3, P4, P5, P6)
    ...
else
    f_00051038(P2, P1, P8)
    ...
end
```

这形成两个完全不同的路径：

| 条件 | 主要含义 |
|---|---|
| `P3 != nil` | 使用颜色/瓦片模板路径，不依赖 P1 图像名 |
| `P3 == nil` | 使用 P1 图像名和 P8 资源类别进行 GraphLoad |

因此，P3 既不是简单的“模式编号”，也不是始终的普通颜色数值；它同时是“是否进入颜色模板路径”的判定点。

## 4.8 [`f_000510AE()`](Sakura_hcb_ir/Sakura/f_000510AE.lua:1)：P3–P6 的颜色含义

### 4.8.1 参数转发

[`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:97-103) 调用：

```lua
f_000510AE(P2, P3, P4, P5, P6)
```

由于下游导出器也存在槽位偏移，按实际数据流可还原为：

```text
颜色选择/第一个颜色分量 = P3
颜色第二分量 = P4
颜色第三分量 = P5
颜色第四分量 = P6
```

### 4.8.2 特殊颜色预设

[`f_000510AE()`](Sakura_hcb_ir/Sakura/f_000510AE.lua:1) 先判断颜色第一个参数：

| P3 | `ColorSet(19, ...)` 使用的颜色 |
|---:|---|
| `-1` | `0, 0, 0, 255`，黑色不透明 |
| `-2` | `255, 255, 255, 255`，白色不透明 |
| `-3` | `150, 0, 0, 255`，暗红/红色不透明 |
| `-4` | `0, 0, 255, 255`，蓝色不透明 |
| 其他值 | 使用传入的 `P3,P4,P5,P6` 作为四个颜色分量 |

原始逻辑见 [`f_000510AE.lua`](Sakura_hcb_ir/Sakura/f_000510AE.lua:14-79)。

所以 P3 的推荐名称是：

> **颜色预设选择器 / RGBA 第一个分量**。

P4–P6 则是：

> **自定义颜色的后续通道分量**。

### 4.8.3 ColorSet

最终执行：

```lua
ColorSet(19, color0, color1, color2, color3)
```

其中颜色表/颜色槽是 `19`。这个颜色随后供过渡图层资源使用。

### 4.8.4 P2 决定颜色模板应用到哪一个 prim

当 P2 归一化为 `1`：

```lua
PrimSetTile(186, 19, 0, 0, 1380, 820)
PrimSetXY(186, nil, -50)
PrimSetOP(186, 740, 460)
```

当 P2 归一化为 `2`：

```lua
PrimSetTile(187, 19, 0, 0, 1380, 820)
PrimSetXY(187, nil, -50)
PrimSetOP(187, 740, 460)
```

实际宽高计算为：

```text
1280 + 100 = 1380
720 + 100 = 820
```

而 OP 中心点约为：

```text
1280/2 + 100 = 740
720/2 + 100 = 460
```

这说明颜色路径会构造一个覆盖游戏画面的放大过渡平面。

## 4.9 第三参数为 nil 时：图像资源加载路径

当 `P3 == nil` 时，函数执行：

```lua
f_00051038(P2, P1, P8)
```

### 4.9.1 P1：图像资源 basename

[`f_00051038()`](Sakura_hcb_ir/Sakura/f_00051038.lua:1) 最终把 P1 传入 [`f_00037294()`](Sakura_hcb_ir/Sakura/f_00037294.lua:1)。后者执行：

```lua
path = folder(P8) .. P1
PrimSetNull(prim)
GraphLoad(prim, nil)
GraphLoad(prim, path)
```

所以 P1 是：

> **要加载的过渡/遮罩图像资源名或 basename。**

### 4.9.2 P8：资源目录/资源类别

[`f_00037294()`](Sakura_hcb_ir/Sakura/f_00037294.lua:1) 根据第三个实际参数 P8 选择资源目录：

| P8 | 资源目录 |
|---:|---|
| `1` | `graph_vish/`，同时受 `G[8]` 影响可能为 `graph_sd/` 或 `graph_vis/` |
| `2` | `graph_bg/` |
| `3` | `graph/` |
| 其他 | 进入默认/兼容路径 |

因此 P8 不是简单的布尔值，而是：

> **过渡图像资源所属目录/资源类别编号。**

### 4.9.3 资源路径样例

若：

```lua
P1 = "diss00"
P8 = 2
```

则可能加载：

```text
graph_bg/diss00
```

若 P8 为 `3`，则可能加载：

```text
graph/diss00
```

## 4.11 调用 [`f_00051202()`](Sakura_hcb_ir/Sakura/f_00051202.lua:1)

函数在完成颜色模板或资源装载后执行：

```lua
f_00051202(P2)
```

[`f_00051202()`](Sakura_hcb_ir/Sakura/f_00051202.lua:1) 根据 P2 处理：

- prim 186 或 187 的 OP 值；
- `G[244]` 对应的特效/资源分支；
- `f_00037476()` 对图元属性进行设置；
- 最后调用 [`f_00058A64(-1)`](Sakura_hcb_ir/Sakura/f_00058A64.lua:1)。

### P2 = 1

主要处理 prim 186：

```lua
if G[244] == true then
    f_00037476(186, 8)
else
    f_00037476(186, 12)
end
```

### P2 = 2

主要处理 prim 187：

```lua
if G[244] == true then
    f_00037476(187, 8)
else
    f_00037476(187, 12)
end
```

所以 P2 的影响贯穿整个函数族：它不只是选择资源加载对象，也决定最终属性收尾对象。

## 4.12 G[68] 有效时等待 dissolve

最后：

```lua
if G[68] ~= nil then
    DissolveWait(true)
end
```

这不是无条件等待。`G[68]` 为空时，函数执行完准备工作后直接返回；`G[68]` 有效时，才等待当前 dissolve/过渡状态。

因此 [`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 既有资源准备职责，也可能承担过渡同步职责。

## 5. 八个入参的最终解释

| 参数 | 推荐名称 | 详细含义 |
|---|---|---|
| `P1` | `graph_name` | 当 P3 为 nil 时使用的过渡图像/遮罩资源 basename；传给 `GraphLoad` 路径构造。 |

| `P4` | `color_g_or_arg1` | 自定义颜色第二分量；与 P3–P6 一起形成 `ColorSet(19, ...)` 参数。颜色预设路径下通常被忽略。 |

| `P7` | `effect_rebuild_flag` | 特效槽位重建开关；nil 默认 1，等于 0 时调用 `f_00060795()` 和 `f_00066CB2()`。 |
| `P8` | `graph_category` | 资源目录/资源类别编号；通过 `f_00051038()` → `f_00037294()` 选择 `graph_vish/`、`graph_bg/`、`graph/` 等目录。 |

## 6. `-1` 与 `-2` 的具体差异

### 6.1 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1)

其最后调用为：

```lua
f_00050EDB(nil, 1, -1, nil, nil, nil, nil, nil)
```

参数解释：

```text
P1 = nil
P2 = 1       -> 使用 prim 186
P3 = -1      -> ColorSet(19, 0, 0, 0, 255)
P4..P8=nil
```

结果：

> 准备一个以 prim 186 为载体、颜色为黑色不透明的全屏过渡平面。

### 6.2 [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1)

其最后调用为：

```lua
f_00050EDB(nil, 1, -2, nil, nil, nil, nil, nil)
```

参数解释：

```text
P1 = nil
P2 = 1       -> 使用 prim 186
P3 = -2      -> ColorSet(19, 255, 255, 255, 255)
P4..P8=nil
```

结果：

> 准备一个以 prim 186 为载体、颜色为白色不透明的全屏过渡平面。

### 6.3 两者真正差异

| 项目 | `f_000104E8()` | `f_0001052C()` |
|---|---|---|
| P2 | `1` | `1` |
| 主过渡 prim | `186` | `186` |
| P3 | `-1` | `-2` |
| 颜色 | `0,0,0,255`，黑色 | `255,255,255,255`，白色 |
| P1/P4/P5/P6/P7/P8 | 相同 | 相同 |
| 前置清理链 | 相同 | 相同 |
| 特效/UI/音频重建 | 相同 | 相同 |
| 本质区别 | 黑色过渡底 | 白色过渡底 |

因此，之前把 `-1/-2` 临时称作“过渡模式 A/B”并不够精确。更准确的结论是：

> 两个函数的前置清场和系统复位完全相同；唯一实质差异是最后由 `f_00050EDB()` 生成的全屏颜色模板不同：`-1` 为黑色，`-2` 为白色。

## 9. 最终结论

1. [`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 是一个**全屏过渡层/遮罩层准备与状态收束函数**。
2. 它的主要操作对象是 prim `186` 或 `187`，由 P2 选择。
3. P1 是图像资源 basename，只有在 P3 为 nil 的资源路径中使用。
4. P3–P6 是颜色模板参数；P3 的 `-1/-2/-3/-4` 分别选择黑、白、红、蓝预设。
5. P7 控制是否额外重建画面特效槽位。
6. P8 选择图像资源目录/类别。
7. P2 为 1 时使用 prim 186，P2 为 2 时使用 prim 187。
8. [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1) 和 [`f_0001052C()`](Sakura_hcb_ir/Sakura/f_0001052C.lua:1) 的 `-1/-2` 差异不是抽象的过渡模式差异，而是：
   - `-1`：黑色不透明过渡平面；
   - `-2`：白色不透明过渡平面。
9. 两个函数的前置清理、UI 复位、舞台缓存、环境音、特效槽位和后台线程处理完全相同；最终颜色模板不同才是其视觉差异来源。

最准确的函数名可以写成：

> **全屏过渡图层/遮罩颜色与资源准备函数**
