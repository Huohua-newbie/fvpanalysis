# [`f_000547D2()`](Sakura_hcb_ir/Sakura/f_000547D2.lua:1) 逐条反汇编与 Sound 参数验证

> 本文在原逐条表基础上重写。特别修正了参数槽位：本函数 `init_stack args=5, locals=4`，因此 `push_stack -6/-5/-4/-3/-2` 对应 `a0/a1/a2/a3/a4`，而正索引 `0/1/2/3` 对应局部槽 `l0/l1/l2/l3`，不能再把局部槽显示为 `a0/a1/...`。

## 1. 函数作用总览

[`f_000547D2()`](Sakura_hcb_ir/Sakura/f_000547D2.lua:1) 是 Sakura 的 **SE/音效播放与停止控制器**。它不只是简单转发一个 `SoundPlay`，而是同时负责：

1. 把音效编号格式化为三位数字，并构造 `se/NNN` 资源路径；
2. 为音效选择内部通道 `0..7`，并维护每个通道的当前音效路径与播放计数；
3. 播放路径：停止旧通道、设置音效类型、加载新音效、设置初始/目标音量、播放并可选渐入；
4. 停止路径：按音效编号找到当前通道，并执行指定时长的 `SoundStop`；
5. 使用全局槽 `G[275..282]` 保存 8 个通道的当前资源路径，使用 `G[283..290]` 保存对应的播放/引用计数；
6. 使用 `G[275] == nil` 等状态判断空闲通道，并以计数器最小值选择可用通道。

因此更准确的命名是：

> **按音效编号管理 `se/NNN` 资源、通道、循环播放、停止淡出、目标音量和渐入的 SE 播放控制器。**

### 2.1 关键纠正：真实参数编号

本函数原始 Lua-like 头部为 `function f_000547D2(a0, a1, a2, a3, a4)`，但函数体曾出现 `a5`。结合 `init_stack args=5, locals=4` 和原始槽位，正确理解为：

- `push_stack -6 -> a0`：音效编号；
- `push_stack -5 -> a1`：播放循环真值，停止时为 fadeout 时长；
- `push_stack -4 -> a2`：播放/停止模式；
- `push_stack -3 -> a3`：目标音量百分比；
- `push_stack -2 -> a4`：音量渐入/crossfade 时长；
- 正索引 `0..3 -> l0..l3`：通道计数、路径和临时状态局部槽。

这也是此前“第五入参为渐入时长”结论产生混淆的主要原因。

## 4. syscall 数据流摘要

### 播放路径

核心指令序列最终形成：

```lua
SoundStop(channel, 0)
SoundType(channel, 2)
SoundLoad(channel, "se/NNN")
SoundVol(channel, target_volume, nil)
SoundPlay(channel, looped_value, nil)
SoundVol(channel, target_volume, fade_value)
```

其中：

- `channel` 是内部通道 `0..7`，不是原始音效编号；
- `SoundType(channel, 2)` 把该通道绑定到音效类型槽 `2`；
- `SoundLoad` 的第二参数是 `se/` 加三位音效编号；
- `SoundVol` 的第二参数是 `0..100` 音量百分比；
- `SoundVol` 的第三参数才是音量交叉渐变时长；
- `SoundPlay` 的第三参数才是播放渐入时长，但本函数传入固定 `nil`。

### 停止路径

停止分支最终形成：

```lua
SoundStop(channel, a1)
```

其中 `channel` 是根据 `a0` 查找到的内部通道，`a1` 是原始第二入参：

- `a1 = nil` -> 先归一化为 `0`，立即停止；
- `a1 > 0` -> 在 `a1` 毫秒内淡出停止。

## 5. 现有实验结论的修订建议

### 可以保留的部分

- 第一入参对应音效编号：保留；
- 第二入参在播放/停止分支中复用：播放时为循环真值，停止时为毫秒 fadeout；
- 第三入参控制播放/停止：保留，但 `0` 的细分路径需结合第四参数；
- 播放音量使用百分比：保留；Sound 文档确认 `0..100`；
- 函数支持循环、停止和音量变化：保留。

### 需要修订的部分

1. “第一入参是音效编号”：保留，并更准确地称为 `sound_id`。
2. “第二入参控制循环/停止时长”：保留；它是播放/停止分支复用参数。
3. “第三入参控制播放或停止”：保留，但 `a2=-1` 是明确停止路径，`a2=nil/1` 是明确播放主路径，`a2=0` 需结合 `a3` 判断。
4. “第四入参是百分比音量”：保留，真实参数是 `a3`。
5. “第五入参是渐入时长”：保留，但底层实现是 `SoundVol(channel, a3, a4)` 的 crossfade；`SoundPlay` 的 fadein 参数固定为 `nil`。
6. 如果实验中观察到了额外渐入，还应考虑它来自：
   - `SoundVol(channel, volume, crossfade)` 的第三参数；
   - 其他上游/下游音效包装函数；
   - 音频后端默认行为；
   - 旧导出器把局部槽和外部参数混名造成的误读。

## 6. 当前总判断

你的总结中：

- 第一点：**正确**；
- 第二点：**正确，且与第三参数共同决定播放/停止路径中的不同语义**；
- 停止时长部分：**正确，第二入参作为 `SoundStop` 的 fadeout 毫秒数**；
- 第三点：**基本正确，但应区分 `nil/1` 播放、`-1` 停止以及 `0` 的组合分支**；
- 第四点：**正确，第四个真实入参 `a3` 是 `0..100` 音量百分比**；
- 第五点：**基本正确，真实第五入参 `a4` 通过 `SoundVol` crossfade 实现渐入，而不是通过 `SoundPlay` 的 fadein 参数**。

最稳妥的当前接口描述是：

```text
f_000547D2(sound_id, loop_or_fadeout, play_stop_mode, target_volume, volume_crossfade)
```

它负责：

```text
音效编号 -> se/NNN
播放：选择内部通道、SoundStop、SoundType、SoundLoad、SoundVol、SoundPlay
停止：按音效编号查找内部通道并 SoundStop(channel, a1)
```

因此，用户给出的五项总结在修正参数槽位后总体成立；唯一需要特别注明的是：第五参数控制的是 `SoundVol` 的 crossfade，而不是 `SoundPlay` 的第三参数 fadein。
