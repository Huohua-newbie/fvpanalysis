# [`f_0009CF45()`](Sakura_hcb_ir/Sakura/f_0009CF45.lua:1) 详细解析：`$回想_effect`

## 1. 函数定位

- 函数地址：`0x0009CF45`
- IR/Lua-like 文件：[`f_0009CF45.lua`](Sakura_hcb_ir/Sakura/f_0009CF45.lua:1)
- 函数序言：`init_stack args=5, locals=0`
- 唯一直接调用：[`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1)
- 直接 syscall：无
- 主要直接调用方：[`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:1)、[`f_00097EA5()`](Sakura_hcb_ir/Sakura/f_00097EA5.lua:1) 以及多个主剧情 function

结合宏名 `$回想_effect` 及其调用场景，当前可以将 [`f_0009CF45()`](Sakura_hcb_ir/Sakura/f_0009CF45.lua:1) 命名为：

> **“回想/非现实时间线”画面滤镜的开关入口。**

它本身仍然只是一个薄包装器；真正执行滤镜图层、资源、混合方式、alpha 动画和线程操作的是 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1)。

这里的“回想”不是打开回想菜单，而是对当前游戏画面叠加一层视觉滤镜，用于提示当前叙事处于回忆、过去或与现实时间线不同的表现层。

## 2. 反编译结果与参数偏移

导出的 Lua-like 结果为：

```lua
function f_0009CF45(a0, a1, a2, a3, a4)
  local S0, S1, S2, S3, S4, S5, S6
  S0 = a1
  S1 = a2
  S2 = a3
  S3 = a4
  S4 = a5
  f_0009CAC2(S0, S1, S2, S3, S4)
  return
end
```

这里存在和此前函数相同的导出器参数编号偏移：函数元数据明确为 `args=5`，但导出结果主体读取了 `a1..a5`。因此分析时不应直接使用导出变量名，而应使用原始参数位置：

| 原始参数位置 | Lua-like 导出名 | 当前用途 |
|---:|---|---|
| `p0` | `a0` | 传入包装器，但未被包装器读取 |
| `p1` | `a1` | 转发给 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 的第 1 个真实参数 |
| `p2` | `a2` | 转发给 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 的第 2 个真实参数 |
| `p3` | `a3` | 转发给 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 的第 3 个真实参数 |
| `p4` | `a4` | 转发给 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 的第 4 个真实参数 |
| `p5` | `a5` | 转发给 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 的第 5 个真实参数 |

由于 `args=5`，更可靠的语义化伪代码是：

```lua
function f_0009CF45(p0, p1, p2, p3, p4)
    f_0009CAC2(p0, p1, p2, p3, p4)
end
```

也就是说，**在原始参数语义上它很可能并不忽略第一个参数**；`a0..a5` 是导出器人为造成的显示偏移。这里与 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 不同，不能把 `p0` 误判为未使用。

## 3. 实际核心：[`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1)

## 3.1 总体功能

[`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 操作固定 prim `493`，并围绕一组 `EF_e08` 资源执行显示、透明度动画和线程控制。

结合宏 `$回想_effect` 的语义，prim `493` 更准确地应视为**回想效果的画面滤镜/覆盖层 prim**，而不是角色立绘槽或普通背景层。`EF_e08` 及其后缀资源属于这套滤镜的不同表现变体，最终通过 prim `493` 叠加到游戏画面上。

它的核心功能包括：

1. 对默认参数进行归一化；
2. 根据特效编号选择 `EF_e08_B` 至 `EF_e08_O` 的资源；
3. 将资源加载到 prim `493`；
4. 设置 prim `493` 的操作区域和父组关系；
5. 根据模式设置混合方式；
6. 按不同模式执行 alpha 淡入、淡出或直接设置 alpha；
7. 必要时启动线程 `12`，线程入口为地址 `642813`；
8. 当第一个模式参数不为 `1` 时，走清理/隐藏分支，并退出线程 `12`。

因此它不是普通的静态图片加载函数，而是一个**固定特效图元上的多模式演出控制器**。

## 3.2 固定对象：prim `493`

函数在多个分支中都使用 prim `493`：

```lua
f_00037421(493)
f_000373A5(493, "EF_e08_*", nil, nil)
PrimSetOP(493, 640, 360)
f_00037440(493, 777, 5)
PrimSetBlend(493, ...)
PrimSetAlpha(493, ...)
f_000520EE(493, ...)
```

其中：

- [`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1) 应为旧资源/图元状态清理包装；
- [`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1) 负责把特效资源加载或绑定到 prim；
- `PrimSetOP(493, 640, 360)` 将其操作区域设置为 `640 × 360`；
- [`f_00037440()`](Sakura_hcb_ir/Sakura/f_00037440.lua:1) 将 prim `493` 加入编号为 `777` 的父组或显示组，层级/组参数为 `5`；
- [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 是已有分析中的通用 alpha 动画包装器。

`640 × 360` 不是全屏背景尺寸，而更像一个特效画布/局部演出区域。其实际屏幕位置和缩放仍需结合 prim 父组 `777` 的定义确认。

## 4. 参数语义

以下参数使用原始位置 `p0..p4` 表示，不沿用存在偏移的 Lua-like 名称。

### 4.1 `p0`：主开关/显示模式

[`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 首先将其第一个真实参数归一化为：

```lua
if p0 == nil then
    p0 = 1
end
```

随后有两条主要路径：

- `p0 == 1`：进入显示/播放特效路径；
- `p0 ~= 1`：进入 prim `493` 的隐藏/清理路径。

在清理路径中，函数会：

```lua
f_000520EE(493, nil, 0, p4, ...)
ThreadExit(12)
```

因此 `p0` 可以高置信度命名为：

> **回想滤镜的 ON/OFF 主模式。**

它不是具体特效编号，也不是 alpha 值。

调用样本中常见的第一个实参是 `0` 或 `1`：

```lua
f_0009CF45(0, nil, nil, nil, nil)
f_0009CF45(1, nil, 9, nil, nil)
```

按真实参数位置解释：

- `p0=0`：关闭、隐藏或清理 prim `493`，对应 `$回想_effect #flag="OFF"`；
- `p0=1`：启用/显示 prim `493` 对应的 EF_e08 回想滤镜，对应 `$回想_effect #flag="ON"`。

### 4.2 `p1`：alpha / 混合或第二控制参数

函数对第二个真实参数进行缺省处理：

```lua
if p1 == nil then
    p1 = 1
end
```

该值主要参与 `PrimSetBlend` 的选择，同时影响某些特效模式下的混合设置：

```lua
if p1 == 0 then
    PrimSetBlend(493, 0)
elseif p1 == 1 then
    PrimSetBlend(493, 1)
else
    PrimSetBlend(493, 0 or 1) -- 不同分支有固定回退
end
```

当前可确认它是**混合/合成方式控制参数**，但 `PrimSetBlend` 的具体枚举含义应以 syscall 数据库和实机结果为准。它不是资源编号。

### 4.3 `p2`：是否启动后台线程

第三个真实参数缺省时被设置为 `1`：

```lua
if p2 == nil then
    p2 = 1
end

if p2 == 1 then
    ThreadStart(12, 642813)
end
```

因此 `p2` 是一个线程/异步执行开关：

| `p2` | 行为 |
|---:|---|
| `nil` | 归一化为 `1`，启动线程 `12` |
| `1` | 启动线程 `12`，入口 `642813` |
| 其他值 | 不启动该线程 |

这个线程很可能负责 EF_e08 特效的持续更新、帧切换或 alpha 状态维护，但仅凭当前函数无法确定其具体循环内容。

### 4.4 `p3`：EF_e08 资源变体编号

第四个真实参数是资源选择器。函数根据它选择：

| `p3` | 加载资源 |
|---:|---|
| `1` | `EF_e08_B` |
| `2` | `EF_e08_C` |
| `3` | `EF_e08_D` |
| `4` | `EF_e08_E` |
| `5` | `EF_e08_F` |
| `6` | `EF_e08_G` |
| `7` | `EF_e08_H` |
| `8` | `EF_e08_I` |
| `9` | `EF_e08_J` |
| `10` | `EF_e08_K` |
| `11` | `EF_e08_L` |
| `12` | `EF_e08_M` |
| `13` | `EF_e08_N` |
| `14` | `EF_e08_O` |
| 其他值 | `EF_e08` |

函数的默认资源路径是：

```lua
f_000373A5(493, "EF_e08", nil, nil)
```

所以 `p3` 可以高置信度命名为：

> **EF_e08 特效资源变体/帧组编号。**

这也是本函数最明确的参数。它直接决定实际绑定到 prim `493` 的资源 basename。

注意：资源名中的字母后缀不是简单的数字格式化结果，而是显式分支映射。因此新增变体不能只传大于 `14` 的编号，除非资源选择逻辑被扩展。

### 4.5 `p4`：alpha 动画时长或透明度控制

第五个真实参数在显示路径中被送入 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 的时长/控制位置：

```lua
f_000520EE(493, 0, 240, p4, ...)
f_000520EE(493, 0, 220, p4, ...)
f_000520EE(493, 0, 150, p4, ...)
f_000520EE(493, 0, 200, p4, ...)
```

当 `p4` 为 `nil` 时，函数在入口将其设置为 `-1`：

```lua
if p4 == nil then
    p4 = -1
end
```

从不同路径看，`p4` 不是单纯的最终 alpha 值，而更像传给 alpha 动画包装器的**等待/动画控制参数**。实际的起始 alpha、目标 alpha 和时长由 `p3` 以及其它内部固定值共同决定。

在非线程分支中还能看到固定的 `500` 作为动画时长：

```lua
f_000520EE(493, 0, 240, 500, ...)
f_000520EE(493, 0, 250, 500, ...)
f_000520EE(493, 0, 190, 500, ...)
```

因此当前建议使用保守命名：

> **alpha 演出附加参数；在常见调用中表现为淡入/淡出时序控制。**

是否严格为“淡入时长”或“等待开关”，需要继续追踪 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 的第四参数定义以及运行时调用差异。

## 5. 资源选择与显示流程

当 `p0 == 1` 时，函数大致执行如下流程：

```text
清理 prim 493 旧状态
    ↓
根据 p3 选择 EF_e08 / EF_e08_B ... EF_e08_O
    ↓
将资源绑定到 prim 493
    ↓
设置 PrimSetOP(493, 640, 360)
    ↓
将 prim 493 加入父组/显示组 777
    ↓
根据 p1 设置 PrimSetBlend
    ↓
根据 p2 决定是否启动 ThreadStart(12, 642813)
    ↓
根据 p4 和 p3 选择 alpha 处理方式
```

`p3` 的资源选择发生在 alpha 处理之前，因此资源必须先绑定，再执行可见性动画。

## 6. alpha 分支

### 6.1 `p4` 非空时

当第五个真实参数 `p4` 非空时，函数根据资源变体编号选择不同的 alpha 目标值：

- `p3 == 1` 或 `p3 == 12`：目标 alpha `240`；
- `p3 == 10`：目标 alpha `220`；
- `p3 == 11`：目标 alpha `150`；
- `p3 == 2`：直接设置 alpha `250`；
- 其他变体：通常使用目标 alpha `200`。

这些值通过 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 进入 alpha motion：

```lua
f_000520EE(493, 0, target_alpha, p4, ...)
```

因此不同 EF_e08 变体不仅更换资源，也可能使用不同的默认透明度。

### 6.2 `p4` 为空/缺省路径

当第五个真实参数为空时，函数走另一组固定时长 `500` 的 alpha 处理：

```lua
p3 == 1 -> MotionAlpha(..., 240, 500, ...)
p3 == 2 -> MotionAlpha(..., 250, 500, ...)
其他    -> MotionAlpha(..., 190, 500, ...)
```

这说明 `p4` 是否提供，会影响 alpha 控制采用“调用方参数”还是内部固定时长。

### 6.3 `p0 != 1` 的清理路径

如果第一个真实参数不等于 `1`，函数不进行资源变体选择，而是对 prim `493` 执行 alpha 降至 `0` 的处理：

```lua
f_000520EE(493, nil, 0, p4, ...)
ThreadExit(12)
```

因此 `f_0009CF45(0, nil, nil, nil, nil)` 的主要效果不是选择 `EF_e08` 的某个资源，而是关闭/隐藏回想滤镜覆盖层，也就是 `$回想_effect` OFF。

## 7. 调用样本

### 7.1 [`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:1) 中的关闭调用

调用形式：

```lua
f_0009CF45(0, nil, nil, nil, nil)
```

按原始参数位置：

```text

p2 = nil
p3 = nil
p4 = nil
```

归一化后：

```text

p2 = 1

```

由于 `p0 != 1`，进入 prim `493` 的隐藏/清理分支，并执行线程退出。

这与 [`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:1) 前后连续出现的场景收尾函数相符：它是在演出结束阶段关闭 EF_e08 回想滤镜，即执行 `$回想_effect #flag="OFF"` 的底层效果。

### 7.2 [`f_00097EA5()`](Sakura_hcb_ir/Sakura/f_00097EA5.lua:1) 中的启动调用

调用形式：

```lua
f_0009CF45(1, nil, 9, nil, nil)
```

按原始参数位置：

```text
p0 = 1
p1 = nil
p2 = 9
p3 = nil
p4 = nil
```

注意这里必须区分“真实参数位置”和导出器显示的 `a1..a5`。如果调用字节码的五个压栈值确实依次为 `1,nil,9,nil,nil`，那么：

- `p0=1`：启用显示路径；
- `p1=nil`：混合参数使用默认值 `1`；
- `p2=9`：不启动线程 `12`；
- `p3=nil`：使用默认资源 `EF_e08`；
- `p4=nil`：使用固定 `500` 时长的 alpha 路径。

这里的 `9` 若原始参数位置确认无误，不能直接解释为资源变体 `EF_e08_J`；资源编号位于 `p3`，而不是 `p2`。这正是参数偏移问题最容易造成的误判。

### 7.3 [`f_000977CB()`](Sakura_hcb_ir/Sakura/f_000977CB.lua:1) 中直接调用核心

该函数存在：

```lua
f_0009CAC2(-1, nil, nil, nil, nil)
```

它绕过了 [`f_0009CF45()`](Sakura_hcb_ir/Sakura/f_0009CF45.lua:1)，直接调用核心函数。此时第一个真实参数为 `-1`，因此同样属于非 `1` 的清理/关闭路径。

这进一步支持：第一个真实参数是主显示/清理模式，而不是被包装器丢弃的保留槽。

## 9. 当前伪代码

使用原始参数位置表示，可以整理为：

```lua
function f_0009CF45(p0, p1, p2, p3, p4)
    return f_0009CAC2(p0, p1, p2, p3, p4)
end
```

核心逻辑：

```lua
function f_0009CAC2(mode, blend_mode, thread_mode, effect_variant, alpha_param)
    if blend_mode == nil then
        blend_mode = 1
    end
    if alpha_param == nil then
        alpha_param = -1
    end
    
    if mode ~= 1 then
        -- 关闭/隐藏固定特效 prim
        MotionAlpha(493, ..., 0, alpha_param, ...)
        ThreadExit(12)
        return
    end
    
    -- 固定特效图元
    clear_prim(493)
    
    -- 资源变体
    local graph = {
        [1] = "EF_e08_B",
        [2] = "EF_e08_C",
        [3] = "EF_e08_D",
        [4] = "EF_e08_E",
        [5] = "EF_e08_F",
        [6] = "EF_e08_G",
        [7] = "EF_e08_H",
        [8] = "EF_e08_I",
        [9] = "EF_e08_J",
        [10] = "EF_e08_K",
        [11] = "EF_e08_L",
        [12] = "EF_e08_M",
        [13] = "EF_e08_N",
        [14] = "EF_e08_O",
    }
    load_graph(493, graph[effect_variant] or "EF_e08")
    PrimSetOP(493, 640, 360)
    set_parent_or_group(493, 777, 5)
    set_blend(493, blend_mode)
    
    if thread_mode == nil then
        thread_mode = 1
    end
    if thread_mode == 1 then
        ThreadStart(12, 642813)
    end
    
    local target_alpha = 200
    if effect_variant == 1 or effect_variant == 12 then
        target_alpha = 240
    elseif effect_variant == 10 then
        target_alpha = 220
    elseif effect_variant == 11 then
        target_alpha = 150
    elseif effect_variant == 2 then
        PrimSetAlpha(493, 250)
        return
    end
    
    MotionAlpha(493, 0, target_alpha, alpha_param_or_500, ...)
end
```

上述伪代码只表达控制流和参数关系，不应直接作为可执行脚本使用；尤其是 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 的完整参数还需要按照其自身的真实栈槽定义展开。

## 10. 结论

1. [`f_0009CF45()`](Sakura_hcb_ir/Sakura/f_0009CF45.lua:1) 是宏 `$回想_effect` 的五参数底层薄包装器。
2. 由于 `init_stack args=5` 与导出变量名存在偏移，不能把导出的 `a0` 直接判定为未使用；应使用原始位置 `p0..p4`。
3. [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1) 固定控制 prim `493`。
4. prim `493` 使用 `EF_e08`、`EF_e08_B` 至 `EF_e08_O` 这一组特效资源。
5. 第一个真实参数 `p0` 是回想滤镜 ON/OFF 主模式：`1` 进入显示路径，对应 ON；其他值进入关闭/清理路径，对应 OFF。

9. 该函数属于一个固定特效 prim 的资源切换与 alpha 演出控制器，不是通用背景加载函数，也不是 dissolve 执行器。
