# [`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:1) 背景调用详细解析

## 1. 函数定位

- 原始函数：[`f_00015543.lua`](Sakura_hcb_ir/Sakura/f_00015543.lua:1)
- 已有逐条反汇编：[`f_00015543逐条反汇编对照.md`](./f_00015543逐条反汇编对照.md:1)
- 函数地址范围：`0x00015543–0x0001568D`
- `init_stack args=10, locals=0`
- 函数无直接 syscall，但会通过 [`f_0005074C()`](Sakura_hcb_ir/Sakura/f_0005074C.lua:1) 和 [`f_00050859()`](Sakura_hcb_ir/Sakura/f_00050859.lua:1) 间接进入 Graph/Prim/Motion syscall 层。

本函数属于典型的 **BGimageLoading 背景调用函数**。它不是通用背景引擎本体，而是“满月・夜の国”这一具体场景/背景组的专用包装函数：

1. 写入地点标题；
2. 设置该场景的背景上下文标志；
3. 根据若干参数和全局状态选择 `BG106_xxx` 资源名；
4. 调用主背景层导入器；
5. 将资源名追加 `b` 后调用模糊/对话背景层导入器。

总体结构可以概括为：

```lua
function f_00015543(...)
    f_0004D788("満月・夜の国")
    G[1255] = 0
    f_00016F8E(nil, nil)

    normalize_parameters()
    select G[63] = "BG106_xxx"

    f_0005074C(G[63], nil, 50, p1, p2, p3, p4, p5)
    G[63] = G[63] .. "b"
    f_00050859(G[63], nil, 50, p1, p2, p3, p4, p5)
end
```

## 2. 参数编号勘误

本函数有 10 个显式参数。正确的负栈索引映射是：

| 原始栈槽 | 正确参数 |
|---|---|
| `-11` | `a0` |
| `-10` | `a1` |
| `-9` | `a2` |
| `-8` | `a3` |
| `-7` | `a4` |
| `-6` | `a5` |
| `-5` | `a6` |
| `-4` | `a7` |
| `-3` | `a8` |
| `-2` | `a9` |

旧 Lua-like 导出文本整体右移了一位，因此其中常见的：

- 导出名 `a4` 实际是 `a3`；
- 导出名 `a6` 实际是 `a5`；
- 导出名 `a8` 实际是 `a7`；
- 导出名 `a9` 实际是 `a8`；
- 导出调用中的 `a1..a5` 实际对应真实 `a0..a4`。

因此阅读本函数时，应以 [`f_00015543逐条反汇编对照.md`](./f_00015543逐条反汇编对照.md:1) 的原始 `push_stack -N` 为准。

## 3. 第一阶段：标题与上下文初始化

### 3.1 地点标题

函数开头固定调用：

```lua
f_0004D788("満月・夜の国")
```

[`f_0004D788()`](Sakura_hcb_ir/Sakura/f_0004D788.lua:1) 的本体是：

```lua
TextClear(9)
TextPrint(9, "満月・夜の国")
```

也就是说，本函数首先刷新文本槽 9，把当前地点标题设置为“満月・夜の国”。这一步属于文本层初始化，不是背景图片装载本身。

### 3.2 `G[1255] = 0`

随后写入：

```lua
G[1255] = 0
```

根据多个背景函数的共同结构，`G[1255]` 是背景/场景导入链使用的一个模式归一化标记。它并不直接等于背景资源编号，而是会影响后续参数模板如何解释或归一化。

目前可保守命名为：

> **当前背景导入流程的场景模式归一化标志。**

### 3.3 `f_00016F8E(nil, nil)`

函数随后调用：

```lua
f_00016F8E(nil, nil)
```

[`f_00016F8E()`](Sakura_hcb_ir/Sakura/f_00016F8E.lua:1) 自身会：

- 调用背景/过渡清理函数；
- 根据 `G[1247]` 的场景模式编号设置 `G[1253]`、`G[1254]`；
- 调用 `f_00050BD0()`、`f_00050C82()` 等场景状态处理函数；
- 为后续背景差分选择准备全局上下文。

因此，`f_00015543()` 并不是收到参数后马上选背景名，而是先要求公共场景上下文函数根据当前全局状态做一次预处理。

这一步与 [`f_0004B135()`](./f_0004B135逐条反汇编对照.md:1) 的关系是：

```text
f_0004B135()
    -> 写入 G[1244]..G[1247]
    -> f_00015543()
        -> f_00016F8E()
            -> 读取 G[1247]
            -> 设置 G[1253]/G[1254]
```

## 4. 第二阶段：参数默认化

### 4.1 `a3` 的默认值

原始槽位 `-8` 对应真实 `a3`。若 `a3 == nil`，函数执行：

```lua
a3 = 1600 / 2
```

即：

```lua
a3 = 800
```

这个值随后作为参数组的一部分传给 `f_0005074C()` 和 `f_00050859()`。结合两个下游函数对 `PrimSetZ`、`PrimSetRS`、运动时长等参数的使用，它很可能是某个空间/运动参数的默认值，但不能仅凭本函数把它简单命名成“Z”或“缩放”。

### 4.2 `a8` 的默认值

原始槽位 `-3` 对应真实 `a8`。若为空：

```lua
a8 = 0
```

随后 `a8` 参与背景名选择：

- `a8 == -1`：直接使用 `BG106_000`；
- 否则继续检查 `G[1250]` 和 `a8` 的具体数值。

因此 `a8` 是本函数最直接的**背景差分选择参数**。

### 4.3 `a5` 的默认值

原始槽位 `-6` 对应真实 `a5`。若为空：

```lua
a5 = 1
```

它会被传给后面的两个背景层导入器。结合 [`f_0005074C()`](Sakura_hcb_ir/Sakura/f_0005074C.lua:1) / [`f_00050859()`](Sakura_hcb_ir/Sakura/f_00050859.lua:1) 的参数链，可以暂定为背景图层布局/显示模式相关参数，但具体字段仍需结合更多同族调用验证。

## 5. 第三阶段：`BG106_xxx` 背景资源选择

本函数最终写入全局字符串 `G[63]`，其资源名全部属于 `BG106` 背景组。

### 5.1 `a7 == -1`

若真实 `a7 == -1`：

```lua
G[63] = "BG106_000"
```

该分支优先级最高，会绕过后续 `G[1250]` 和 `a8` 判断。

### 5.2 `G[1250] >= 1`

若 `a7 != -1`，且：

```lua
G[1250] >= 1
```

则仍选择：

```lua
G[63] = "BG106_000"
```

这与其他背景函数的共同模式一致：当某个全局背景装载模式标志有效时，强制回到基础背景资源。

`G[1250]` 由 [`f_0004B1F4()`](./f_0004B1F4逐条反汇编对照.md:1) 设置，默认常见值为 `0`。因此在本场景中：

- `G[1250] >= 1`：优先选择基础 `BG106_000`；
- `G[1250] < 1`：继续使用本函数的 `a8` 差分选择逻辑。

### 5.3 `a8 == 100`

```lua
G[63] = "BG106_001"
```

### 5.4 `a8 == 101`

```lua
G[63] = "BG106_011"
```

### 5.5 `a8 == 1`

```lua
G[63] = "BG106_010"
```

### 5.6 `a8 == 500`

```lua
G[63] = "BG106_100"
```

### 5.7 其他情况

统一回退：

```lua
G[63] = "BG106_000"
```

因此本函数的资源选择表可以写成：

| 条件 | `G[63]` |
|---|---|
| `a7 == -1` | `BG106_000` |
| `a7 != -1` 且 `G[1250] >= 1` | `BG106_000` |
| `a8 == 100` | `BG106_001` |
| `a8 == 101` | `BG106_011` |
| `a8 == 1` | `BG106_010` |
| `a8 == 500` | `BG106_100` |
| 其他 | `BG106_000` |

注意：`a8` 不是普通的连续差分编号，而是一个离散模式值；`100/101/1/500` 分别对应不同资源名。

## 6. 第四阶段：主背景层导入

选择完 `G[63]` 后，函数执行：

```lua
f_0005074C(G[63], nil, 50, a0, a1, a2, a3, a4)
```

这里调用者传入的动态参数来自真实参数 `a0..a4`。由于旧导出文本右移，原 Lua-like 中显示为 `a1..a5` 的部分应整体左移一位。

### 6.1 `f_0005074C()` 的主要动作

[`f_0005074C()`](Sakura_hcb_ir/Sakura/f_0005074C.lua:1) 负责 prim `186` 的主背景层导入，关键 syscall/动作包括：

1. 设置 `G[118] = true`；
2. 停止 prim `186` 的 `MotionMove`、`MotionMoveZ`、`MotionAlpha`；
3. 调用 [`f_00050EDB()`](Sakura_hcb_ir/Sakura/f_00050EDB.lua:1) 做过渡/图层准备；
4. 通过 [`PrimSetOP`](../syscalls/21_Prim.md:1) 设置 prim 操作属性；
5. 通过 [`PrimSetXY`](../syscalls/21_Prim.md:1) 设置位置；
6. 通过 [`PrimSetZ`](../syscalls/21_Prim.md:1) 设置深度；
7. 通过 [`PrimSetRS`](../syscalls/21_Prim.md:1) 设置旋转/缩放类属性；
8. `PrimSetAlpha(186, 255)` 使主背景层可见；
9. 通过 [`GraphRGB`](../syscalls/10_Graph.md:1) 应用 RGB 色调；
10. 设置 `G[310] = 1`、`G[71] = 0` 等过渡状态。

因此，`f_00015543()` 传给 `f_0005074C()` 的不是简单的“背景资源名 + 五个无关参数”，而是一整组会参与 prim 位置、Z、旋转/缩放、颜色和过渡初始化的背景显示参数。

## 7. 第五阶段：`b` 差分层导入

主背景层调用返回后：

```lua
G[63] = G[63] .. "b"
```

例如：

```text
BG106_000 -> BG106_000b
BG106_001 -> BG106_001b
BG106_011 -> BG106_011b
BG106_010 -> BG106_010b
BG106_100 -> BG106_100b
```

随后调用：

```lua
f_00050859(G[63], nil, 50, a0, a1, a2, a3, a4)
```

### 7.1 `f_00050859()` 的主要动作

[`f_00050859()`](Sakura_hcb_ir/Sakura/f_00050859.lua:1) 与主层函数基本平行，但目标是 prim `187`：

- 首先检查 `G[1973] == true`；
- 若不成立，直接返回，不装载 `b` 层；
- 若成立，则停止 prim `187` 的移动类动作；
- 调用 `f_00050EDB(..., 2, ...)`；
- 设置 prim `187` 的 OP、XY、Z、RS；
- 设置 `PrimSetAlpha(187, 0)`，使 `b` 层初始透明；
- 调用 `GraphRGB`；
- 返回。

因此，`f_00015543()` 总是构造并尝试准备 `b` 资源，但 `b` 层是否真正参与画面显示由 `G[1973]` 控制。

这一区分非常重要：

> **资源名带 `b` 不等于该层当场可见。**

它更像是为后续对话模糊背景、特殊画面状态或过渡效果预先准备的备用层。

## 9. 与其他背景函数族的共性

[`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:1) 与 [`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:1)、[`f_000107EC()`](Sakura_hcb_ir/Sakura/f_000107EC.lua:1)、[`f_00013C1F()`](Sakura_hcb_ir/Sakura/f_00013C1F.lua:1) 等函数共有稳定模板：

1. 固定地点标题；
2. 写入背景相关全局状态；
3. 调公共上下文准备函数；
4. 根据全局槽和参数决定背景差分字符串；
5. 调主背景层导入器；
6. 追加 `b`；
7. 调模糊/备用背景层导入器。

差异主要体现在：

- 固定地点标题字符串不同；
- 基础资源组不同，如 `BG001`、`BG002`、`BG106`；
- 差分选择条件不同；
- 传给底层导入器的参数模板不同；
- 是否使用 `G[1250]`、`G[1247]`、`G[1253]` 等全局状态不同。

## 10. 最终结论

### 高置信度

- [`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:1) 是 `BG106` 背景组的专用背景加载/差分切换包装函数；
- 会将地点标题固定写为“満月・夜の国”；
- 会设置 `G[1255] = 0`；
- 会根据 `a7`、`G[1250]`、`a8` 选择 `BG106_000/001/011/010/100`；
- 会先加载主层，再以 `b` 后缀准备第二层；
- 主层由 prim `186` 承载，`b` 层由 prim `187` 承载；
- `b` 层实际是否进入流程受 `G[1973]` 控制，且初始 alpha 为 `0`。

### 中等置信度

- `a8` 是本函数的主要背景差分选择参数；
- `G[1250] >= 1` 表示某种强制基础背景/标准背景模式；
- `G[1255]` 是背景参数归一化或场景类型标志；
- `f_00016F8E()` 负责把 `G[1247]` 等上层场景模式转换为背景/过渡侧参数。

### 尚需验证

- `a0..a5` 传给 `f_0005074C()` / `f_00050859()` 后分别对应 XY、Z、RS、时长、插值和其他显示字段中的哪一项；
- `BG106_001`、`BG106_011`、`BG106_010`、`BG106_100` 的具体视觉差异；
- `G[1973]` 的完整业务名称和所有切换点；
- `G[1250]`、`G[1247]`、`a8` 三者共同作用时的优先级在所有 BG106 分支中的一致性。

> 综合来看，[`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:1) 并不是简单的“加载一张背景图”，而是一个完整的场景背景切换模板：它同步处理地点标题、场景上下文、差分资源选择、主背景层、模糊/备用背景层和下游图元过渡参数。
