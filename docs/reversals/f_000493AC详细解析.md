# [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:1) 详细解析

## 1. 函数定位

- 函数地址：`0x000493AC`。
- IR 元数据：`args_count = 2`、`locals_count = 2`，函数本体共有 48 个 CFG block，Lua-like 导出范围为第 1–458 行，见 [`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json:8958655) 与 [`Sakura.cfg.json`](../../03_data/cfg/Sakura.cfg.json:282265)。

- 主要处理对象：文本缓冲、文本窗口相关 prim、右侧功能块父组 `349`、play 区域 `64/65/85`、控制条 `90/91/92`。

一句话概括：

> [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:1) 在“特殊/演出式文本布局”和“普通消息窗口布局”之间切换；它同时负责状态位切换、文本缓冲重设、按钮图元显隐、父组 `349` 的移动与最终显示，以及 UI 状态清理。

## 2. 参数槽映射：必须修正 Lua-like 名称

函数序言是：

```text
init_stack args=2 locals=2
```

但导出结果在函数体中读取了 `a1`、`a2`，例如第 6 行和第 32 行。这是当前 Lua-like 导出器仍然存在的参数名称偏移表现，不能直接把 `a1/a2` 当作用户层面的第 1/2 参数。

按照修正后的负栈槽规则，应以原始 `push_stack -N` 为准。结合所有调用点：

```lua
f_000493AC(1, -1)
f_000493AC(0, nil)
```

以及同类调用中首参数是 `500`、`1000`、`0` 等，真实参数应解释为：

| 真实参数 | 当前 Lua-like 常见显示 | 语义 | 置信度 |
|---|---|---|---|
| `p0` | `a1` | 模式/布局类型；`1` 进入特殊布局，`0` 进入普通布局 | 高 |
| `p1` | `a2` | 尺寸缩放或特殊布局控制值；`-1` 选择特殊尺寸路径，`nil` 选择普通尺寸路径 | 高 |

因此本文将函数调用写成 `f_000493AC(p0, p1)`，而不沿用容易误读的导出变量名。

重要结论：函数内部对第一个真实参数的使用被导出器显示成 `a1`，对第二个真实参数的使用被显示成 `a2`。函数中后续对 `a0/a1` 的重新赋值，实际上主要是在复用参数槽作为局部临时变量，并不表示函数有第三、第四个外部参数。

## 4. 特殊/演出式文本布局：`f_000493AC(1, -1)`

### 4.1 设置特殊模式状态

第 11–19 行执行：

```lua
G[1193] = true
if G[212] == true then
    f_0004C9E2(0)
end
```

这里的作用是：

1. 置 `G[1193] = true`，标记当前进入特殊文本/窗口演出状态；
2. 如果已有另一套窗口或控制层处于活动状态，则通过 [`f_0004C9E2()`](Sakura_hcb_ir/Sakura/f_0004C9E2.lua:1) 对 prim `245` 做位置和透明度收束，并清理 `G[212]` 相关状态。

[`f_0004C9E2()`](Sakura_hcb_ir/Sakura/f_0004C9E2.lua:47-101) 的核心 syscall 链为：

```text
MotionAlpha(245, ..., 255, duration)
MotionMove(245, ..., duration)
MotionMoveTest(245)
ThreadNext()
```

因此这不是单纯的状态赋值，而是会先等待旧 UI 动画结束。

### 4.2 清理旧文本层并设置新的文本缓冲布局

第 21–31 行：

```lua
PrimSetXY(788, nil, -280)
f_0004CB77(nil, nil, nil, nil, 1)
```

其中：

- `PrimSetXY(788, nil, -280)` 把 prim `788` 的 Y 坐标移动到 `-280`，使其离开当前可视区域；
- [`f_0004CB77()`](Sakura_hcb_ir/Sakura/f_0004CB77.lua:1) 负责重设主文本缓冲。

[`f_0004CB77()`](Sakura_hcb_ir/Sakura/f_0004CB77.lua:5-60) 的默认值为：

```text
文本缓冲槽：0
缓冲区域：x=220，y=577，宽度=830，行高/高度=150
```

但特殊路径传入的参数为：

```text
f_0004CB77(nil, nil, nil, nil, 1)
```

因此：

- 文本起始 X 默认 `220`；
- 默认文本区域的第二个尺寸参数为 `578 - 1 = 577`；
- 宽度默认 `1280 - 225*2 + 21 = 851`；
- 最后一个参数为 `1`，覆盖默认的 `150`。

由于 [`f_0004CB77()`](Sakura_hcb_ir/Sakura/f_0004CB77.lua:45-60) 还会把 `G[52]` 写成文本缓冲相关参数，并调用 `PrimSetText`、`TextBuff`，该调用可视为“特殊文本区域初始化”。

### 4.3 计算特殊布局尺寸

第 32–87 行先把内部尺寸参数归一化为 `200`，再按照 `G[1988]` 做一次缩放：

```text
基础值：200
G[1988] == 1：再次除以 2
最小值：1
```

最终得到两组尺寸：

```text
p0_size = 200 或 100
p1_size = p0_size / 2
```

若 `G[1988] == 1`，则尺寸会进一步变成大约 `100 / 50`。这更像是高 DPI、窗口缩放或虚拟分辨率适配，而不是剧情层传入的实际动画时长。

这里第二参数 `p1 == -1` 的作用不是直接作为数值使用，而是选择特殊路径后采用固定基准尺寸；`p1 != -1` 时也仍会使用固定 `200`，区别主要在分支标志和调用上下文。

### 4.4 初始化窗口状态并刷新右侧 UI

第 89–109 行：

```lua
G[1194] = true
G[67] = nil
G[116] = true
f_0004F0AD()

if G[206] == true then
    f_0003767C(90, 0)
    f_0003767C(91, 0)
    f_0003767C(92, 0)
end
```

含义如下：

- `G[1194] = true`：特殊布局初始化/进行中的状态；
- `G[67] = nil`：清除旧的某类窗口/文本状态；
- `G[116] = true`：通知后续 UI 流程当前正在进行布局刷新；
- [`f_0004F0AD()`](Sakura_hcb_ir/Sakura/f_0004F0AD.lua:1)：刷新右侧功能块的固定坐标、alpha、命中检测和 `play` 图元版本；
- 若 `G[206] == true`，额外关闭控制条 prim `90/91/92`。

[`f_0004F0AD()`](Sakura_hcb_ir/Sakura/f_0004F0AD.lua:207-262) 明确按 `G[206]` 切换：

```text
G[206] == nil：显示 64，隐藏 65/85
G[206] != nil：隐藏 64/65，显示 85
```

因此特殊模式本身不会简单地“显示所有右侧按钮”，而是会重新执行一轮状态相关的 UI 刷新。

### 4.5 特殊模式下的窗口图元 alpha/移动

若第二参数不是 `-1`，函数会继续根据 `G[54]` 分支。

#### `G[54] == true`

第 121–159 行：

```text
f_000520EE(514,255,0,p1,...)
f_000520EE(347,255,0,p0,...)
f_000520EE(552,255,0,p1,...)
f_000524BB(347,nil,nil,nil,100,p0,3,nil,nil,nil)
```

这组调用主要是：

- 对 prim `514`、`347`、`552` 设置 alpha 到 `255`；
- 以 `p0/p1` 作为动画时长或运动参数；
- 对 prim `347` 使用 [`f_000524BB()`](Sakura_hcb_ir/Sakura/f_000524BB.lua:1) 的 `MotionMoveS2` 路径。

[`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:357-381) 最终调用：

```text
MotionAlpha(prim, start, end, duration, ...)
MotionAlphaTest(prim)
ThreadNext()
```

当其第 6 个参数为 `nil` 时通常不等待，因此这些调用可以是并行启动的 alpha 动画。

[`f_000524BB()`](Sakura_hcb_ir/Sakura/f_000524BB.lua:42-69) 最终调用：

```text
MotionMoveS2(prim, ...)
MotionMoveS2Test(prim)
ThreadNext()
```

#### `G[54] != true`

第 160–191 行：

```text
f_0004AC7E(0,p0,nil)
f_000520EE(345,255,0,p0,...)
f_000520EE(346,G[1955],0,p1,...)
f_000520EE(513,255,0,p1,...)
```

[`f_0004AC7E()`](Sakura_hcb_ir/Sakura/f_0004AC7E.lua:47-124) 是另一套窗口/按钮 alpha 控制器，会根据模式参数对 prim `52/55/58/61`、`64/67`、`70/71/86`、`73`、`76/79`、`82` 等图元进行淡入淡出设置。其底层大量使用 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 和 `PrimSetAlpha`。

因此，特殊布局的显示不是由一个 prim 完成，而是通过多个窗口、按钮和控制图元的同步 alpha/运动状态组合出来的。

### 4.6 其他窗口图元移动

当 `G[117] != 1` 时，第 196–233 行还会调用：

```text
f_000523A8(787,nil,nil,nil,16,p0,3,nil,nil,nil)
f_000523A8(551,nil,G[52],nil,G[52]+16,p0,3,nil,nil,nil)
f_000523A8(552,nil,G[53],nil,G[53]+16,p0,3,nil,nil,nil)
```

[`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:55-82) 最终调用 `MotionMove`，并可通过 `MotionMoveTest` + [`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1) 逐帧等待。

这三次调用大致对应：

- prim `787`：文本/窗口主体；
- prim `551`：主文本对象或文本框；
- prim `552`：附加文本/窗口对象。

它们的运动目标由当前 `G[52]`、`G[53]` 和偏移 `16` 形成，说明特殊模式还会对文本对象本身做垂直或局部位置调整。

### 4.7 父组 `349` 的特殊布局移动

第 237–290 行先关闭/开启若干控制 prim：

```text
PrimSetDraw(4,0)
PrimSetDraw(3,0)
PrimSetDraw(2,0)
PrimSetDraw(1,1)
PrimSetDraw(551,1)
```

然后计算：

```text
x = 220 + 10 = 230
y = 268 + 15 = 283
w = 1280 - ((220+10)*2 - 10) = 830
h = 720 - 360 = 360
```

并调用：

```text
f_0004CB77(230,283,830,360,nil)
```

这次调用把正文文本区域切换到特殊演出布局。

随后函数轮询 prim `349` 的运动：

```lua
while MotionMoveTest(349) == true do
    f_0003769F()
    MotionMove(349, nil, nil, nil, 0, 1, 1, nil)
end
```

这里的 [`MotionMoveTest`](fvp_analysis/result/syscall语义数据库/21_Prim.md:110) 用于检测父组运动是否结束；[`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1) 是空操作式帧让渡点；`MotionMove` 的这组参数用于维持/结束当前运动状态。该循环的明确目的，是避免在 `349` 尚未完成移动时立即写入最终坐标。

运动结束后，根据 `G[152]` 设置父组位置：

```text
G[152] == true  -> PrimSetXY(349, 0, 0)
G[152] != true  -> PrimSetXY(349, 0, 145)
```

父组 `349` 是所有 `fc_*` 右侧功能块的父节点，见 [`f_0004B23C()`](Sakura_hcb_ir/Sakura/f_0004B23C.lua:354-393)。因此 `G[152]` 不只是一个局部坐标参数，而是决定整套右侧 UI 垂直停靠位置的状态位。

最后：

```text
PrimSetDraw(349, 1)
f_0004AC7E(1, p0, nil)
```

这一步将父组真正打开，并再次调用 [`f_0004AC7E()`](Sakura_hcb_ir/Sakura/f_0004AC7E.lua:307-450) 对右侧按钮做 alpha 刷新。

若 `G[206] == true`，还会将 `90/91/92` 的 draw 设置为 `1`，恢复控制条显示。

## 5. 普通消息窗口布局：`f_000493AC(0, nil)`

### 5.1 计算普通模式尺寸

第 345–385 行先根据第二参数是否为 `-1` 选择基础值：

```text
p1 == -1 -> 基础尺寸 100
p1 != -1 -> 基础尺寸 200
```

随后若 `G[1988] == 1`，再除以 2；如果结果小于等于 0，则钳制为 `1`。当 `G[1988] == 0` 时，尺寸也会被强制为 `1`。

在常见调用 `f_000493AC(0,nil)` 中，实际进入的是 `p1 != -1` 分支，因此基础值为 `200`，再结合 `G[1988]` 适配。

### 5.2 清理特殊状态并刷新窗口

第 386–399 行：

```text
G[1194] = nil
G[116] = true
f_0004F0AD()
f_0004AC7E(0, size, -1)
f_0003767C(1,0)
```

与特殊路径相比：

- `G[1193]` 暂时还未立即清除；
- `G[1194]` 先被清除；
- `G[116]` 置为 `true`；
- 通过 [`f_0004F0AD()`](Sakura_hcb_ir/Sakura/f_0004F0AD.lua:1) 重新设置右侧 UI 基础状态；
- 通过 [`f_0004AC7E()`](Sakura_hcb_ir/Sakura/f_0004AC7E.lua:1) 以第三参数 `-1` 进入普通窗口收束/恢复路径；
- prim `1` 被设为 draw `0`，表示关闭一类特殊文本或控制对象。

### 5.3 等待父组 `349` 的移动结束

普通路径第 400–418 行再次轮询：

```text
while MotionMoveTest(349) == true do
    MotionMove(349, nil, nil, nil, 0, 1, 1, nil)
    f_0003769F()
end
```

与特殊路径相同，这保证父组 `349` 在被写入最终位置前不会残留未完成的运动。

随后同样依据 `G[152]` 设置：

```text
G[152] == true  -> PrimSetXY(349, 0, 0)
G[152] != true  -> PrimSetXY(349, 0, 145)
```

所以普通模式和特殊模式共享同一套右侧功能组停靠机制。

### 5.4 普通路径的控制条和最终清理

第 435–453 行：

```text
f_0004CB77(nil,nil,nil,nil,nil)
PrimSetXY(788,nil,0)
G[116] = nil
G[1194] = nil
G[1193] = nil
f_0004D713(175)
```

具体效果：

1. `f_0004CB77(nil,nil,nil,nil,nil)` 恢复标准文本缓冲默认布局；
2. prim `788` 从 `Y=-280` 恢复到 `Y=0`；
3. 清除 `G[116]`、`G[1194]` 和 `G[1193]`；
4. 将 `G[237]` 设置为 `175`。

因此 `f_000493AC(0,nil)` 是真正的特殊模式退出函数，而不只是把某个开关改为 `0`。

| `G[52]`、`G[53]` | 文本缓冲/文本对象位置参数 | 由 [`f_0004CB77()`](Sakura_hcb_ir/Sakura/f_0004CB77.lua:45-60) 和移动包装器使用 |

## 8. 两个典型调用的实际差异

### 8.1 `f_000493AC(1, -1)`

这是切入特殊演出式文本布局的调用：

1. `G[1193] = true`；
2. 必要时收束旧 prim `245`；
3. 将 prim `788` 移到 `Y=-280`；
4. 重设文本缓冲为特殊区域；
5. 切换文本窗口和附属按钮的 alpha/运动状态；
6. 隐藏部分普通控制对象；
7. 将父组 `349` 移到目标停靠位置并打开；
8. 重新刷新右侧功能块；
9. 清理临时刷新标志，但保留 `G[1193] = true`，表示仍处于特殊文本模式。

它与 [`G[1276] = 1`](Sakura_hcb_ir/Sakura/f_000A2981.lua:76) 配合，使随后输出的正文进入演出式/居中类布局，而不是通常底部消息栏。

### 8.2 `f_000493AC(0, nil)`

这是恢复普通消息窗口布局的调用：

1. 选择普通尺寸基准；
2. 清除 `G[1194]`；
3. 刷新右侧功能块和普通窗口 alpha；
4. 关闭特殊文本对象；
5. 等待父组 `349` 动画结束；
6. 依据 `G[152]` 将 `349` 放到 `y=0` 或 `y=145`；
7. 恢复标准文本缓冲；
8. 将 prim `788` 放回 `Y=0`；
9. 清除 `G[116]`、`G[1194]`、`G[1193]`；
10. 将 `G[237]` 恢复为 `175`。

因此这不是“把特殊模式标志改成 0”，而是一次完整的 UI 恢复和重排。

## 9. 与右侧功能块缺失问题的关系

结合 [`f_0004B23C()`](Sakura_hcb_ir/Sakura/f_0004B23C.lua:354-393) 和已有 UI 分析，可以确认：

- `52..88`、`784`、`89`、`184` 等图元统一挂在父组 `349` 下；
- `349` 初始 draw 为 `0`；
- [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:307-310) 负责最终执行 `PrimSetDraw(349,1)`；
- `G[206]` 决定 play 区域显示 `64/65` 还是 `85`；
- `G[152]` 决定父组的垂直位置；
- [`f_0004F0AD()`](Sakura_hcb_ir/Sakura/f_0004F0AD.lua:207-262) 和 [`f_0004AC7E()`](Sakura_hcb_ir/Sakura/f_0004AC7E.lua:90-114) 负责进一步刷新显隐和 alpha。

所以“新建剧情 function 后右侧缺一块，但右键隐藏/恢复后正常”的现象，很可能是：

1. 初始流程创建了图元，但没有完整调用 [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:1)；
2. 或 `G[206]` 没有进入正确分支；
3. 或父组 `349` 仍保持 draw `0`、坐标错误或运动未收束；
4. 或只初始化了 `_1` 版本，没有重新刷新 `65/85` 等备用版本。

右键隐藏/恢复流程会再次切换 `G[206]` 并刷新相关 prim，因此会产生“自动修正”的表象。

## 10. 结论与置信度

### 高置信结论

- [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:1) 是消息 UI/正文文本布局切换器；
- `p0=1` 是特殊布局，`p0=0` 是普通布局；
- `p1=-1` 是特殊尺寸/控制分支，`p1=nil` 是常见普通恢复调用；
- 函数直接使用 `PrimSetXY`、`PrimSetDraw`、`MotionMoveTest`、`MotionMove`；
- 函数通过下游包装器间接使用 `PrimSetText`、`TextBuff`、`MotionAlpha`、`MotionMoveS2`；
- 父组 `349` 的最终位置由 `G[152]` 决定；
- `G[206]` 影响 `64/65/85` play 图元的显示版本。

### 中等置信结论

- `G[1193]` 可以命名为特殊文本/演出窗口模式标志；
- `G[1194]`、`G[116]` 是布局刷新过程中的临时状态；
- `G[237]=450/175` 与后续窗口计时或动画比例有关；
- prim `787/551/552/788` 分别属于文本主体、文本框或附属窗口层，但其具体资源身份仍需结合完整 prim 创建表确认。

### 后续验证方向

1. 从原始 [`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb:299948) 对应地址提取 syscall 参数，核对 Lua-like 中 `a1/a2` 的原始负槽；
2. 对 prim `787/788/551/552/347` 建立资源名和父子关系表；
3. 对比执行 `f_000493AC(1,-1)` 与 `f_000493AC(0,nil)` 前后的运行时 prim 状态；
4. 继续追踪 [`f_0004D3E2()`](Sakura_hcb_ir/Sakura/f_0004D3E2.lua:1)，确认 `G[237]` 的实际时间单位和在特殊文本模式下的换算；
5. 检查 [`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1) 何时设置 `G[128]`、`G[129]`，以确认它们是“布局完成”还是“消息栏已建立”标志。

最终判断：

> [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:1) 是 Sakura 消息系统中负责“文本布局模式 + 文本缓冲 + 右侧控制组 + 父组位置 + 动画收束”的综合 UI 状态机。`G[1276]` 选择剧情层面的呈现模式，而 [`f_000493AC()`](Sakura_hcb_ir/Sakura/f_000493AC.lua:1) 将该模式落实到实际文本缓冲和 prim 层级，因此它是第一句演出式台词、普通对话栏恢复以及右侧功能块正确显示的关键函数之一。
