# [`f_0004D788()`](Sakura_hcb_ir/Sakura/f_0004D788.lua:1) 逐条反汇编与作用分析

## 1. 函数定位与总体结论

- 原始函数：[`f_0004D788.lua`](Sakura_hcb_ir/Sakura/f_0004D788.lua:1)
- HCB：[`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb)
- IR：[`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json)
- 函数地址范围：`0x0004D788–0x0004D798`
- HCB 文件偏移：`317320–317336`
- 字节长度：`17` 字节
- 函数序言：`init_stack args=1, locals=0`
- 显式入参数量：`1`
- 局部变量数量：`0`
- 直接调用的内部函数：无
- 直接调用的 syscall：2 次
  - [`TextClear`](../syscalls/26_Text.md:1)
  - [`TextPrint`](../syscalls/26_Text.md:1)

本函数是一个极薄的文本槽刷新包装函数，完整行为只有：

```lua
TextClear(9)
TextPrint(9, a0)
```

它的第一个参数并不是“普通正文文本”的显示参数，而是被固定写入**文本槽 9**。结合调用点传入的内容，可以确认该槽主要用于显示场景/地点标题，例如：

- `"ゆめのねどこ・奥座敷"`
- `"桜ヶ丘学園・校門前"`
- `"参禅町・展望広場"`
- `"列車内"`
- `"空"`

因此更准确的作用名称是：

> **清空并刷新文本槽 9 的场景/地点标题函数。**

它本身不负责：

- 创建文本图元；
- 调整文本窗口位置；
- 设置字体、字号、颜色或文本速度；
- 等待文字显示；
- 执行背景切换；
- 执行 dissolve 或其他过渡。

这些职责由调用者或更早的 UI 初始化链完成。

## 2. 参数说明

| 参数 | 当前含义 | 证据与置信度 |
|---|---|---|
| `a0` | 要写入文本槽 9 的标题字符串。调用者通常传入场景名、地点名，偶尔传入全角空格作为清空后的占位标题。 | **高**：原始 `TextPrint(9, a0)` 直接证明参数用途，调用样本中的字符串内容进一步证明其为场景/地点标题。 |

参数槽位映射如下：

- 函数有 1 个显式参数；
- `push_stack -2 -> a0`；
- 因此旧版 Lua-like 导出中若出现 `a1`，应按参数编号勘误整体左移一位理解。

### 2.1 标题字符串样本

调用点显示，该函数被大量背景/场景函数在场景资源选择前调用。典型样本包括：

```lua
f_0004D788("ゆめのねどこ・奥座敷")
f_0004D788("ゆめのねどこ・店先")
f_0004D788("桜ヶ丘学園・校門前")
f_0004D788("参禅町・展望広場")
f_0004D788("列車内")
f_0004D788("空")
f_0004D788("幻想の海")
```

这些字符串都具有明显的场景地点性质，而不是剧情正文句子。

### 2.2 全角空格样本

多个剧情入口会调用：

```lua
f_0004D788("　")
```

该调用不代表“显示一个可见的地点名称”，更可能用于：

- 清空文本槽 9 的旧标题后写入空白占位；
- 保持槽位处于已刷新状态，但不显示有效标题；
- 避免下游文本图元继续保留上一场景标题。

由于 `TextPrint` 的具体空白字符渲染由引擎文本层决定，这里暂不把它绝对命名为“隐藏标题”。

## 3. syscall 层追踪

### 3.1 [`TextClear`](../syscalls/26_Text.md:1)

本函数第一次 syscall 为：

```lua
TextClear(9)
```

其作用是清空文本槽 `9` 的当前内容/缓冲状态。槽编号 `9` 是本函数固定使用的对象，不由调用者改变。

这一步很重要，因为函数不是直接覆盖文本，而是先清空旧内容。这样可以避免：

- 新地点标题比旧标题短时残留旧文字；
- 文本槽内部仍保留上一地点标题；
- 后续文本图元刷新时继续显示旧缓冲内容。

### 3.2 [`TextPrint`](../syscalls/26_Text.md:1)

第二次 syscall 为：

```lua
TextPrint(9, a0)
```

它把 `a0` 写入/打印到文本槽 `9`。

因此本函数的实际操作顺序是：

```text
清空槽 9
    ↓
将新的地点标题写入槽 9
```

`TextPrint` 本身是否立即使画面中的文本图元可见，还取决于槽 9 所绑定的 prim、其 draw/alpha 状态以及上游 UI 布局。已有分析指出，某些文本槽可能已经写入内容，但对应图元仍被 alpha 或父组状态隐藏。因此，不能把本函数单独等同于“玩家必然看到标题”。

## 4. 调用者与调用时机

### 4.1 背景函数中的固定开头

大量具体背景函数以如下模板开始：

```lua
S0 = "场景/地点标题"
f_0004D788(S0)
```

例如 [`f_0001063E()`](Sakura_hcb_ir/Sakura/f_0001063E.lua:5)：

```lua
S0 = "ゆめのねどこ・奥座敷"
__ret = f_0004D788(S0)
```

随后该函数才开始：

- 读取和归一化背景相关参数；
- 根据全局状态选择 `BG001_000`、`BG001_010` 等资源名；
- 调用背景导入函数；
- 处理普通背景层和 `b` 差分层。

因此，在背景函数族中，`f_0004D788()` 的时序位置是：

```text
写地点标题
    ↓
选择背景差分
    ↓
装载背景资源
    ↓
设置图元/过渡状态
```

### 4.2 [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:11)

开场初始化中调用：

```lua
S0 = "　"
__ret = f_0004D788(S0)
```

这里先写入空白地点标题，之后执行背景设置、BGM、转场和居中文本布局。它的目的很可能是清理上一状态遗留的标题槽，而不是展示一个具体地点名。

### 4.3 [`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:5)

该背景函数调用：

```lua
S0 = "満月・夜の国"

```

随后才进入背景资源选择和差分处理。因此地点标题与背景资源之间存在稳定的剧情脚本级配对关系，但标题函数本身不读取背景资源，也不决定差分编号。

### 4.4 调用数量与复用范围

在 Sakura 的背景/剧情函数集合中，`f_0004D788()` 被大量复用，覆盖：

- 梦之寝床；

这说明它是通用地点标题入口，而非某一个场景专用函数。

## 7. 与背景装载链的关系

已有 [`BGimageLoading函数共性总结.md`](BGimageLoading函数共性总结.md:19) 将背景导入函数归纳为：

1. 显示场景/地点标题字符串；
2. 做背景切换前的大清场；
3. 归一化背景参数；
4. 选择背景资源名；
5. 装载普通背景和差分背景；
6. 设置背景过渡参数。

其中第 1 步就是 [`f_0004D788()`](Sakura_hcb_ir/Sakura/f_0004D788.lua:1)。但需要区分：

- `f_0004D788()` 只负责槽 9 的文本内容；
- 背景函数本体负责决定 `BGxxx_yyy` 资源和后续图像装载；
- 文本槽 9 是否可见，还取决于对应 prim、父组、alpha 和 UI 布局。

因此，背景函数可以抽象为：

```lua
function BGimageLoading(scene_title, ...)
    f_0004D788(scene_title)
    -- 后续才是背景差分选择和图像装载
end
```

## 8. 最终作用判断

### 高置信度结论

1. [`f_0004D788()`](Sakura_hcb_ir/Sakura/f_0004D788.lua:1) 是叶子函数。
2. 它固定操作文本槽 `9`。
3. 它先调用 `TextClear(9)`，再调用 `TextPrint(9, a0)`。
4. `a0` 是要写入文本槽 9 的字符串。
5. 大量调用样本中的 `a0` 都是场景名/地点名，因此它是场景/地点标题入口。
6. 它不直接调用图像、Prim、Motion、Dissolve 或其他内部 function。

### 中等置信度结论

- 文本槽 9 在 UI 中承担地点标题或场景标题显示职责。
- `f_0004D788("　")` 用于清空旧标题并写入空白占位。
- 在背景函数中先调用它、再装载背景，说明地点标题是背景切换流程的前置文本刷新步骤。

### 尚待验证

- 槽 9 对应的具体 prim 编号、父组编号和最终屏幕坐标；
- 文本槽 9 是否在所有 UI 模式下都可见；
- `TextPrint` 写入空白字符串后，底层文本图元是保留空白绘制、隐藏，还是仅清除字符缓存。

## 9. 后续验证建议

1. 追踪文本槽 9 在所有 `TextBuff`、`TextPos`、`PrimSetText`、`PrimSetDraw` 和 `PrimSetAlpha` 调用中的绑定关系。
2. 比较 `f_0004D788("地点名")`、`f_0004D788("　")` 和 `f_0004D788(nil)` 的实际画面差异。
3. 在一个背景函数中暂时去掉 `f_0004D788()`，观察背景是否仍能加载，以及旧地点标题是否残留。
4. 单独执行 `TextClear(9)` 与 `TextPrint(9, title)`，确认是否还需要额外的 `TextRepaint` 或 UI 刷新步骤。

> 结论：[`f_0004D788()`](Sakura_hcb_ir/Sakura/f_0004D788.lua:1) 并非“复杂的地点标题演出控制器”，而是一个非常明确的文本槽包装：**清空槽 9，再把场景/地点标题写入槽 9**。复杂的可见性、布局和背景关联发生在它的调用者及文本 UI 初始化链中。
