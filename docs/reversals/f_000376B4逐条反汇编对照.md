# [`f_000376B4()`](Sakura_hcb_ir/Sakura/f_000376B4.lua:1) 逐条反汇编与作用分析

## 1. 函数定位

- 原始函数：[`f_000376B4.lua`](Sakura_hcb_ir/Sakura/f_000376B4.lua:1)
- HCB：[`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb)
- 函数地址范围：`0x000376B4–0x00037707`
- HCB 文件偏移：`226996–227079`
- 函数字节长度：`84` 字节
- 函数序言：`init_stack args=2, locals=0`
- 直接调用 syscall：
  - [`InputGetState`](../syscalls/12_Input.md:1)
  - [`ThreadWait`](../syscalls/27_Thread.md:229)
- 直接调用内部 function：无

本函数是一个**带输入中断条件的定时等待包装函数**。它根据第二个参数决定是否启用特殊输入检查模式，必要时读取当前输入状态；如果没有满足提前结束条件，就调用 `ThreadWait(a0)` 等待指定毫秒数。

它不是 [`ThreadNext`](../syscalls/27_Thread.md:188) 的包装，也不是单纯的“睡眠一帧”：

- `ThreadWait(a0)` 会让当前脚本 Context 进入定时等待状态；
- 特殊模式下，函数可能因为输入状态或 `G[1964]` 直接跳过等待；
- 等待本身由 VM 的 Thread/Context 调度器推进。

更准确的作用名称是：

> **按指定毫秒等待，并根据模式允许输入或全局状态提前跳过等待的函数。**

## 2. 参数映射

本函数有 2 个显式参数，原始负栈索引对应：

| 原始槽位 | 正确参数 |
|---|---|
| `push_stack -3` | `a0` |
| `push_stack -2` | `a1` |

旧 Lua-like 导出文本曾将 `push_stack -2` 显示为 `a2`，这是参数编号右移错误。当前函数真实接口是：

```lua
f_000376B4(a0, a1)
```

| 参数 | 当前含义 | 置信度 |
|---|---|---|
| `a0` | 定时等待时长，传入 [`ThreadWait(a0)`](../syscalls/27_Thread.md:229)，单位 ms。 | 高 |
| `a1` | 等待模式/输入中断模式。`nil` 默认变为 `0`；`-1` 与 `0` 会进入特殊输入判断路径；其他值直接走 `ThreadWait(a0)`。 | 高 |

## 3. 分支逻辑总览

### 3.1 `a1 == nil`

入口先把 `a1` 归一化为 `0`：

```lua
if a1 == nil then
    a1 = 0
end
```

因此常见调用：

```lua
f_000376B4(3000, nil)
```

实际等价于：

```lua
f_000376B4(3000, 0)
```

### 3.2 `a1 == -1`

进入特殊输入判断：

1. 如果 `G[1964] == 1`，直接返回，不等待；
2. 否则调用 `InputGetState()`；
3. 检查返回位图的 bit `1`；
4. 如果 bit `1` 已置位，直接返回；
5. 如果没有输入，则执行 `ThreadWait(a0)`。

伪代码：

```lua
if a1 == -1 then
    if G[1964] == 1 then
        return
    end

    if (InputGetState() & 1) ~= 0 then
        return
    end

    ThreadWait(a0)
end
```

这里的 `a1=-1` 不是“等待 1 ms”，而是一个特殊的**允许某种输入/全局状态跳过等待**模式。

### 3.3 `a1 == 0`

同样会检查输入 bit `1`，但不会检查 `G[1964]`：

```lua
if a1 == 0 then
    if (InputGetState() & 1) ~= 0 then
        return
    end

    ThreadWait(a0)
end
```

因此 `nil` 默认值并不代表“无条件等待”。由于 `nil -> 0`，默认模式仍允许输入 bit `1` 使等待提前结束。

### 3.4 `a1` 为其他值

当 `a1` 既不是 `-1`，也不是 `0` 时，函数跳过输入判断，直接：

```lua
ThreadWait(a0)
```

例如：

```lua
f_000376B4(250, 1)
f_000376B4(1200, 1)
f_000376B4(6000, 1)
```

这种模式下，第二参数不是等待时长，而是“不要进入 `-1/0` 特殊输入分支”的模式值。

## 4. syscall 层追踪

### 4.1 [`InputGetState`](../syscalls/12_Input.md:1)

该 syscall 返回当前输入状态位图，而不是单一按键编号。函数随后执行：

```lua
(InputGetState() & 1) ~= 0
```

根据当前 Input 语义，bit `1` 表示键码/输入位 `0` 对应的状态。具体该位在原作输入配置中对应何种物理按键，需要结合游戏输入映射继续确认；本函数只能确定它检查的是输入位掩码 `1`。

当该位非零时，函数直接返回，不执行 `ThreadWait`。

### 4.2 [`ThreadWait`](../syscalls/27_Thread.md:229)

普通等待路径调用：

```lua
ThreadWait(a0)
```

根据 Thread syscall 语义：

- `a0` 是毫秒级等待时长；
- 当前 Context 被标记为 WAIT；
- 当前执行机会被让出；
- 后续由 VM runner 递减等待时间；
- 时间到达后恢复运行。

因此，`f_000376B4(3000, nil)` 的核心作用是“最多等待约 3000 ms”，但在默认模式 `a1=nil -> 0` 下，如果输入 bit `1` 已经置位，等待会被跳过。

## 5. `G[1964]` 的作用

本函数只在 `a1 == -1` 的路径读取 `G[1964]`：

```lua
if a1 == -1 and G[1964] == 1 then
    return
end
```

`G[1964]` 在其他输入/UI/等待函数中被反复读写，例如：

- [`f_00037E50()`](Sakura_hcb_ir/Sakura/f_00037E50.lua:10-17) 会设置或清除它；
- [`f_00037708()`](Sakura_hcb_ir/Sakura/f_00037708.lua:64-70) 会在等待逻辑中读取它；
- [`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:13-16) 也会将其与输入状态联合判断。

从本函数能够确定：

> `G[1964] == 1` 是 `a1=-1` 特殊等待模式下的“直接跳过等待”全局条件。

但仅凭当前函数还不能给 `G[1964]` 下最终业务名称。它可能表示：

- 输入/控制被屏蔽；
- 当前处于某个不可等待的 UI 模式；
- 某种强制推进或跳过状态；
- 文本/演出上下文中的特殊控制标志。

## 6. 调用样本

### 6.1 开场背景前等待

[`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:48-50) 中：

```lua
f_000376B4(3000, nil)
```

实际流程：

1. `a0 = 3000`；
2. `a1 = nil -> 0`；
3. 检查 `InputGetState() & 1`；
4. 若没有目标输入，执行 `ThreadWait(3000)`；
5. 若输入已存在，则立即返回；
6. 后续继续进入背景函数 [`f_00015543()`](Sakura_hcb_ir/Sakura/f_00015543.lua:1)。

因此现有文档中“第一句台词前的大等待”方向正确，但应补充：它不是绝对不可跳过的 3000 ms 延时，而是带输入提前结束条件的等待。

### 6.2 收尾时的一帧/短等待

常见调用包括：

```lua
f_000376B4(1, nil)
f_000376B4(0, nil)
```

这些调用通常出现在清理、收尾或下一段演出前。由于 `a1=nil -> 0`，它们仍会检查输入 bit `1`；没有输入时执行 `ThreadWait(1)` 或 `ThreadWait(0)`。

`ThreadWait(0)` 是否在具体 VM 实现中表现为立即恢复、至少让出一次调度，需以 ThreadManager 实现和实机行为为准；不能简单等同于 `ThreadNext()`。

### 6.3 大于 1 的第二参数

部分调用存在：

```lua
f_000376B4(1200, nil)
f_000376B4(5500, nil)
f_000376B4(6000, nil)
```

这里第二参数仍为 `nil`，因此走 `a1=0` 的输入检查路径。

也有调用传入：

```lua
f_000376B4(1, true)
```

由于 `true` 既不是 `0` 也不是 `-1`，它直接进入 `ThreadWait(1)`，不读取 `InputGetState()`。

## 8. 等价伪代码

```lua
function f_000376B4(a0, a1)
    if a1 == nil then
        a1 = 0
    end

    if a1 == -1 or a1 == 0 then
        if a1 == -1 and G[1964] == 1 then
            return
        end

        if (InputGetState() & 1) ~= 0 then
            return
        end
    end

    ThreadWait(a0)
end
```

## 9. 和 `f_00037708()` 的区别

两者都与等待有关，但职责不同：

| 函数 | 核心等待方式 | 输入处理 | 计时处理 |
|---|---|---|---|
| [`f_000376B4()`](Sakura_hcb_ir/Sakura/f_000376B4.lua:1) | 直接 `ThreadWait(a0)` | 仅在 `a1=-1/0` 时检查 `InputGetState() & 1` | 交给 ThreadWait/Context |
| [`f_00037708()`](Sakura_hcb_ir/Sakura/f_00037708.lua:1) | 自己循环检查计时器 | 更细的输入位判断 | `TimerSet`/`TimerGet` + `ThreadNext` |

因此：

- `f_000376B4()` 更像**一次性定时等待请求**；
- `f_00037708()` 更像**可逐帧推进、可处理中断条件的主动等待循环**。

## 10. 最终作用判断

### 高置信度结论

1. 第一个参数 `a0` 是 `ThreadWait` 的等待时长，单位 ms。
2. 第二个参数 `a1` 是等待模式，而不是第二个时间值。
3. `a1 == nil` 时默认变为 `0`。
4. `a1 == -1` 或 `a1 == 0` 会启用输入相关的提前结束判断。
5. `a1 == -1` 且 `G[1964] == 1` 时直接返回。
6. 输入状态 `InputGetState() & 1 != 0` 时直接返回。
7. 没有提前结束时，最终执行 `ThreadWait(a0)`。

### 中等置信度结论

- `a1=-1` 是比 `a1=0` 更特殊的等待模式，因为它额外受 `G[1964]` 控制；
- `a1=0` 是默认的可输入跳过等待模式；
- `a1=1` 等其他非 `-1/0` 值代表无输入检查的普通定时等待模式。

### 仍需验证

- 输入掩码 `1` 在 Sakura 原作配置中对应哪个具体按键/按钮；
- `G[1964] == 1` 的完整业务名称；
- `ThreadWait(0)` 在原版 VM 中是否保证至少让出一次调度机会。

## 11. 典型调用的准确解释

```lua
f_000376B4(3000, nil)
```

表示：最多等待 3000 ms，但如果默认模式下检测到输入 bit `1`，可以提前结束。

```lua
f_000376B4(1, nil)
```

表示：执行一次非常短的等待请求，但仍然允许输入 bit `1` 使其提前结束。

```lua
f_000376B4(1, true)
```

表示：直接走普通 `ThreadWait(1)`，不进入 `a1=-1/0` 的输入检测分支。

```lua
f_000376B4(250, -1)
```

表示：进入特殊 `-1` 模式；若 `G[1964] == 1` 或输入 bit `1` 已置位则直接返回，否则等待 250 ms。

> 结论：[`f_000376B4()`](Sakura_hcb_ir/Sakura/f_000376B4.lua:1) 是一个“**按模式执行定时等待，并在特定模式下允许输入或全局状态提前跳过**”的线程调度辅助函数，而不是单纯的固定延时函数。
