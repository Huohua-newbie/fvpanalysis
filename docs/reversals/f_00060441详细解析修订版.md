# [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1)：`$chara_disp` 立绘批量显示/运动刷新详解

## 1. 结论先说

[`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 是 KS 宏 `$chara_disp` 对应的立绘批量刷新入口。它本身只有两步：

```lua
f_00060795(p1, p2, p3)
f_00066CB2()
```

但这两步分别承担了完整立绘显示链的两个阶段：

1. [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)：读取此前由 `$chara`、`$chara_delete`、`$chara_color` 等操作积累的槽位状态，批量提交颜色、alpha、XY、Z、Parts motion 和 Graph/Parts motion。
2. [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1)：检查 alpha motion，推进槽位阶段，并进行部件/Graph 资源的后续收束、清理或重建。

因此，对用户提出的“它是否指向 display，即立绘入场方式的控制”的回答是：

> **宏名 `$chara_disp` 的确表示“执行/刷新立绘显示”，但函数不是单一的“入场方式选择器”。它是一个批量运动提交 + 动画同步 + 状态收束入口。**

立绘调用可以不立即跟随 `$chara_disp`，这点也成立：

- `$chara` 主要负责登记/装载角色图像、Parts、位置和初始状态；
- `$chara_disp` 才负责把积累的状态批量提交到运动系统；
- 后续文本或其他演出也可能在合适的时机统一调用 `$chara_disp`。

但如果始终不调用 `$chara_disp` 或等价的刷新链，立绘的许多 alpha、移动、Parts 运动和删除状态不会被统一提交或收束。

## 2. 参数编号：表面四参数与真实三个业务参数

### 2.1 反编译器的表面结果

拆分文件显示：

```lua
function f_00060441(a0, a1, a2, a3)
    S0 = a1
    S1 = a2
    S2 = a3
    f_00060795(S0, S1, S2)
    f_00066CB2()
end
```

看起来像是 `a0` 没有使用，只有 `a1/a2/a3` 被转发。

但这不能直接推出“调用的第一个参数被丢弃”。项目中已经确认 Lua-like 导出器的参数名存在整体偏移：函数体中名为 `a1` 的槽位对应真实调用的第 1 个实参。因此，应该使用 VM/调用顺序重新命名。

### 2.2 真实业务抽象

将原始四参数布局按真实调用位置还原后，建议写成：

```lua
function CharaDisplay(time, time2, disp, reserved)
    f_00060795(time, time2, disp)
    f_00066CB2()
end
```

更严格地说，HCB 仍保留四参数调用布局，但业务上当前确认的是前三个参数：

| 调用位置 | 旧 Lua-like 名称 | 本报告名称 | 当前语义 |
|---|---|---|---|
| 第 1 实参 | 函数体 `a1` | `time` | 立绘 Graph/Prim alpha 与 XY/Z motion 的主要时长/时序参数 |
| 第 2 实参 | 函数体 `a2` | `time2` | Parts motion 的持续时间参数，默认 `200` |
| 第 3 实参 | 函数体 `a3` | `disp` | 立绘离场/入场位移幅度基准，默认 `150` |
| 第 4 实参 | 函数体未读取槽 | `reserved` | 当前函数层面未直接使用；通常保持 `nil` |

注意：这是按真实 VM 槽位重命名后的业务视角。不要把拆分文件中的 `a0/a1/a2/a3` 直接当成最终参数编号。

## 3. 参数一：`time`

### 3.1 基本含义

`time` 是本轮立绘批处理的主要时序参数。它首先进入 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:571) 并被存入/换算为 `G[1173]`。

在不同全局状态下，`time` 可能发生以下归一化：

- 若调用者传 `nil`，函数可能从 `G[88]` 或默认值推导；
- 某些状态下会执行 `time - 50`；
- 某些模式下会执行约 `time * 2 / 3`；
- 结果小于等于 `1` 时会钳制到 `1`；
- 某些过渡/初始化状态会强制设为 `1`。

因此它不是简单地“原样保存的毫秒数”，但业务上最接近：

> **本轮角色图元 alpha/位置运动的主要时长或阶段时序控制值。**

### 3.2 直接进入 Graph/Prim motion

[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 将归一化后的 `G[1173]`复制到大量槽位，例如 `G[999]`、`G[1006]` 等，随后用于：

- [`MotionAlpha()`](../../syscall语义数据库/syscall含义详解/18_Motion.md:150) 的目标 alpha/过程控制；
- [`MotionMove()`](../../syscall语义数据库/syscall含义详解/18_Motion.md:216) 的坐标计算；
- [`MotionMoveZ()`](../../syscall语义数据库/syscall含义详解/18_Motion.md:364) 的 Z 坐标计算；
- [`MotionAlphaTest()`](../../syscall语义数据库/syscall含义详解/18_Motion.md:200) 的后续同步判断。

Motion syscall 的标准持续时间参数单位是毫秒，但 `G[1173]`在 Sakura 包装器内部同时承担阶段/门控作用。因此更严谨的描述是：

> `time` 是主要的立绘运动/alpha 刷新时序输入；在具体分支中，它会被转成毫秒时长、阶段阈值或 motion 门控值。

不能把所有使用点都机械地标成一个单纯的 `duration`。

### 3.3 KS 实例

原作中大量使用：

```ks
[macro name="$chara_disp" #time="1200"]
[macro name="$chara_disp" #time="800"]
[macro name="$chara_disp" #time="500"]
```

例如：

- [`common_01.ks`](../../reference/SakuraMoyu_NS/common_01.ks:5716)
- [`route_haru.ks`](../../reference/SakuraMoyu_NS/route_haru.ks:9601)
- [`route_kuro.ks`](../../reference/SakuraMoyu_NS/route_kuro.ks:1220)

这些数值符合“显示/离场运动的主要时长”语义，而不是角色编号或单纯开关。

### 3.4 特殊值 `time=-1`

原作有：

```ks
[macro name="$chara_disp" #time="-1" #time2="-1" #disp="500"]
```

见 [`common_01.ks`](../../reference/SakuraMoyu_NS/common_01.ks:13719)。

由于底层函数会对时序值做特殊归一化，`-1`不能直接解释为 `-1 ms`。它更可能是宏层传入的“使用既有状态/特殊即时模式”哨兵值，随后被[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:604)转换、压缩或钳制。

因此：

- 普通正数：可按毫秒级时序理解；
- `-1`：特殊模式值，不能直接当负时长使用。

## 4. 参数二：`time2`

### 4.1 默认值与主要消费者

[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:627) 对第二个真实业务参数执行：

```lua
if time2 == nil then
    G[1174] = 200
else
    G[1174] = time2
end
```

随后，`G[1174]`被反复作为 [`PartsMotion()`](../../syscall语义数据库/syscall含义详解/20_Parts.md:180) 的第三个参数：

```lua
PartsMotion(parts_id, entry_id, G[1174])
```

而 [`PartsMotion()`](../../syscall语义数据库/syscall含义详解/20_Parts.md:180) 的第三参数明确是部件帧切换的持续时间，单位为毫秒。

因此 `time2` 可以高置信度命名为：

> **Parts/部件层 motion 的持续时间，默认 200 ms。**

### 4.2 与 `time` 的区别

两者不是同一个时长：

| 参数 | 缓存 | 主要作用对象 | 默认值 |
|---|---|---|---:|
| `time` | `G[1173]` | Graph/prim 的 alpha、XY、Z 运动及整体阶段 | 由状态/历史值推导；通常使用调用时传入值 |
| `time2` | `G[1174]` | Parts 条目的切换 motion | `200` |
| `disp` | 直接参与坐标偏移 | Graph/prim 的位置偏移幅度 | `150` |

`time`控制角色图元运动的主要时序；`time2`控制部件纹理/表情帧切换的时序。两者可以相互独立。

### 4.3 `time2=-1`

在原作的特殊调用中：

```ks
[macro name="$chara_disp" #time="-1" #time2="-1" #disp="500"]
```

`time2=-1`并不符合 [`PartsMotion()`](../../syscall语义数据库/syscall含义详解/20_Parts.md:180) 的正常正数 duration 约定，因此应理解为宏/包装层的特殊控制值。底层 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:648) 会对其做比例修正与最小值钳制，不能把它直接当成负毫秒传给引擎。

## 5. 参数三：`disp`

### 5.1 基本含义

第三个真实业务参数在 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:662) 中执行：

```lua
if disp == nil then
    disp = 150
end
```

然后它作为参数传入由[`f_00068A8C()`](Sakura_hcb_ir/Sakura/f_00068A8C.lua:1)使用的位移展开逻辑：

```lua
f_00068A8C(exit_mode, disp)
```

`f_00068A8C()`根据此前由 `$chara` / `$chara_delete`写入的方向模式，计算：

```text
ΔX = 0 或 ±disp
ΔY = 0 或 ±disp
ΔZ = 0 或 ±150
```

所以 `disp`不是一个“显示开关”，而是：

> **立绘入场/离场或构图调整时使用的空间位移幅度基准。**

### 5.2 与 `$chara_delete #param` 的关系

[`$chara_delete`](../../reference/SakuraMoyu_NS/route_haru.ks:9821) 的 `#param="1/2"`只负责写入离场方向模式：

```text
1 → +X
2 → -X
```

随后 `$chara_disp #disp="250"`才提供幅度：

```text
方向 = -X
幅度 = 250
最终偏移 = (-250, 0, 0)
```

因此，`f_00060433(slot, exit_mode)`和`f_00060441(..., disp, ...)`是配套关系：

```text
chara_delete 的第二参数：方向
chara_disp 的第三业务参数：幅度
```

### 5.3 原作实例

原作中有多种：

```ks
[macro name="$chara_disp" #disp="200"]
[macro name="$chara_disp" #disp="250"]
[macro name="$chara_disp" #time="600" #disp="250"]
[macro name="$chara_disp" #time="-1" #time2="-1" #disp="500"]
```

例如：

- [`common_01.ks`](../../reference/SakuraMoyu_NS/common_01.ks:6052)
- [`common_01.ks`](../../reference/SakuraMoyu_NS/common_01.ks:13165)
- [`route_haru.ks`](../../reference/SakuraMoyu_NS/route_haru.ks:9822)
- [`common_01.ks`](../../reference/SakuraMoyu_NS/common_01.ks:13720)

这些值明显更像空间位移幅度，而不是持续时间：它们通常以 `200/250/500`出现，并且和 `time`同时作为两个独立参数存在。

## 6. 第四参数：保留槽位/未在该函数层消费

从拆分结果看，`f_00060441()`函数表面有四个参数，但只把前三个真实业务槽位转发给[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)，第四个槽位没有进入下游。

在 KS 宏层可能仍保留第四参数，例如宏实现的内部固定参数布局或未来兼容参数，但对当前 Sakura.hcb 的这条函数链来说：

- 不参与 `G[1173]`；
- 不参与 `G[1174]`；
- 不参与 `disp`计算；
- 不参与 `f_00066CB2()`调用。

因此新增脚本时建议保持为 `nil`，不要给它擅自赋予语义。

## 7. 函数的真实整体作用

### 7.1 它不是单纯入场控制器

如果只看宏名 `$chara_disp`，确实容易得到“display = 立绘入场”的解释。但原作调用证明它覆盖的范围更大：

- `$chara` 后调用：提交新立绘的显示/入场 motion；
- `$chara_delete` 后调用：提交旧立绘的淡出/离场 motion；
- `$chara_color` 后调用：把颜色缓存刷新到 Graph/Parts；
- 过渡/dissolve过程中调用：同步立绘 alpha 与部件状态；
- 某些界面/特效流程调用：统一刷新一批 prim 和 Parts。

所以更准确的命名是：

> **立绘显示状态批量提交器 / 立绘运动刷新与收束入口。**

### 7.2 `$chara` 可以不立即跟 `$chara_disp`

用户的观察基本正确：立绘调用不一定紧跟 `$chara_disp`。

典型状态机是：

```text
$chara
  ↓
登记资源、角色槽位、位置、Z、alpha、Parts 条目
  ↓
（可以继续登记其他角色/颜色/删除操作）
  ↓
$chara_disp(time, time2, disp)
  ↓
统一提交本轮所有角色的 alpha/XY/Z/Parts motion
  ↓
后处理与同步
```

这意味着 `$chara_disp` 是一个**批量提交点**，而不是每个 `$chara` 的必需即时后缀。

### 7.3 `$chara_disp` 也不一定只处理入场

在同一批次中可能同时存在：

- 新角色状态 `G[slot] = 1`：执行入场/显示路径；
- 已有角色状态：执行颜色、位置或 Parts 更新；
- 删除状态 `G[slot] = 3`：执行淡出/离场路径；
- 其他状态：清理、重建或跳过。

因此它的方向取决于此前各槽位登记的状态和模式，而不是由 `$chara_disp` 自己单独决定。

## 8. 下游运动的具体分工

### 8.1 Alpha/图元运动

在[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:4018)等槽位分支中，函数反复调用：

```lua
GraphRGB(prim_id, r, g, b)
PartsRGB(parts_id, r, g, b)
MotionAlpha(...)
MotionMove(...)
MotionMoveZ(...)
```

其中：

- `time`影响整体 motion/阶段参数；
- `disp`影响由方向模式展开出的坐标偏移；
- `G[1173]`等内部缓存参与 alpha 与位置时序；
- `G[1174]`不用于这些 Graph/Prim motion 的主要时长，而主要用于 PartsMotion。

### 8.2 Parts motion

在[`f_00060795()`](fvp_analysis/result/hcbtool_test/Sakura_hcb_ir/Sakura/f_00060795.lua:4177)等分支中：

```lua
PartsMotion(parts_id, entry_id, G[1174])
```

因此：

```text
$chara_disp 的 time2 → PartsMotion duration
```

这也是为什么 `$chara_disp`必须同时维护 Graph/Prim层和 Parts层：一个角色立绘并不是单一图元，而是 Graph + Parts 的联合显示对象。

### 8.3 后处理与资源重建

[`f_00066CB2()`](fvp_analysis/result/hcbtool_test/Sakura_hcb_ir/Sakura/f_00066CB2.lua:1)会：

- 对多个立绘 prim 执行 `MotionAlphaTest`；
- 在仍有 motion 时通过[`f_0003769F()`](fvp_analysis/result/hcbtool_test/Sakura_hcb_ir/Sakura/f_0003769F.lua:1)让出一帧；
- 推进 `G[311]..G[334]` 等状态；
- 必要时执行 `PrimSetNull`、`PartsLoad(nil)`、`GraphLoad(nil)`、`MotionAlphaStop`、`MotionMoveStop`；
- 释放或重建对应立绘/部件槽位。

所以 `$chara_disp`不是“调用完马上返回的纯设置函数”，它可能在`G[26]`等状态允许时触发同步轮询和后处理。

## 9. 对原有 `f_00060441详细解析.md` 的参数勘误

旧报告中有一处需要修正：

> “调用 `f_00060441(1,nil,nil,nil)` 时，前面的 `1`落在未使用的 `a0`，因此不参与运动。”

这只是表面 Lua-like 参数名造成的误判。正确处理方式是：

- 先按原始 VM 槽位校正参数编号；
- 再将 KS 宏参数与 HCB 调用实参对齐；
- 最终业务参数应写成 `time/time2/disp`，而不是把调用首参统一判定为丢弃。

报告[`f_00060441详细解析.md`](fvp_analysis/result/hcbtool_test/f_00060441详细解析.md:41)中的“函数体读取 `a1/a2/a3`”仍然正确，但这些名称不应直接当作用户看到的第 2/3/4 个参数；它们是导出器偏移后的变量名。

## 10. 推荐调用形式

### 10.1 默认显示/刷新

```lua
f_00060441(time, time2, disp, nil)
```

按真实业务参数理解：

```lua
CharaDisplay(time, time2, disp)
```

### 10.2 常见默认值

```text
time  = nil → 由 G[88] 或模式默认值推导
 time2 = nil → 200
 disp  = nil → 150
```

实际新增脚本可先使用：

```lua
f_00060441(1200, nil, nil, nil)
```

但必须根据原作函数的真实 VM 参数布局编码，不能直接把 Lua-like 拆分文件的 `a0/a1/a2/a3` 名称当作字节码参数编号。

### 10.3 删除后刷新

```lua
f_00060433(slot, exit_mode)
f_00060441(time, time2, disp, nil)
```

此时：

- `f_00060433`登记要删除的槽位及离场方向；
- `f_00060441`提交离场 alpha/位移并收束资源。

### 10.4 立绘颜色后刷新

```lua
f_00069F71(color_slot, r, g, b)
f_00060441(time, time2, disp, nil)
```

这会让此前写入的颜色缓存进入[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:4018)，并实际作用到 Graph/Parts。

## 12. 最终结论

1. [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1)确实对应 `$chara_disp`，但它不是狭义的“立绘入场方式选择器”，而是立绘批量显示/运动刷新入口。
2. `$chara` 可以先登记多个立绘，之后再统一调用 `$chara_disp`；因此立绘调用不必紧跟 `$chara_disp`。
3. `$chara_disp`既处理入场，也处理已有立绘刷新、颜色应用、删除离场和部件 motion。
4. `#time`是 Graph/Prim层的主要运动/alpha时序输入；`#time2`是 PartsMotion持续时间；`#disp`是方向模式对应的空间位移幅度。
5. `#disp`不能单独决定方向；方向来自此前 `$chara` / `$chara_delete`写入的模式，`disp`只提供幅度。
6. 不带参数的 `$chara_disp`并非“什么都不做”：它会使用底层默认值/历史状态，执行当前已登记立绘的批量刷新和后处理。
