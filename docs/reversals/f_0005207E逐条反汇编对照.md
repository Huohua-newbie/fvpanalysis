# [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 逐条反汇编与 KS `$vm` 宏对应分析

## 1. 结论摘要

[`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 本体不是运动 syscall，也不直接操作 prim。它是一个**12 参数公开包装器**：按顺序取出调用者提供的 12 个参数，再固定补入一个 `nil`，转发给真正的核心函数 [`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:1)。

因此，用户给出的同义 KS 语句：

```ks
[macro name="$vm" #x="-255" #y="70" #z="1600" #speed="1600"]
```

在 Sakura HCB 中对应的核心调用形态是：

```lua
f_0005207E(
    -255,   -- P1: 目标 X
    70,     -- P2: 目标 Y
    1600,   -- P3: 目标 Z / 纵深量
    nil,    -- P4: 当前实现被核心函数覆盖，属于保留位
    1600,   -- P5: 主运动时长/速度，单位 ms
    nil,    -- P6: 使用默认补间类型 4
    nil,    -- P7: 默认辅助分支模式 -1
    nil,    -- P8: 默认尾端清理开关 1
    nil,    -- P9: 默认执行/等待模式 0
    nil,    -- P10: 默认自动补正开关 nil
    nil,    -- P11: 默认使用 prim 191 路径
    nil     -- P12: 默认允许预清场
)
```

这不是简单的“把四个宏参数直接传给 `MotionMove`”。核心函数会根据全局状态选择 `prim 190` 或 `prim 191`，并组合调用：

- [`MotionMoveZ`](../syscalls/18_Motion.md:365)：Z/纵深运动；
- [`MotionMoveR`](../syscalls/18_Motion.md:270)：旋转运动；
- [`MotionMove`](../syscalls/18_Motion.md:214)：二维 XY 平移；
- 相关 alpha、scale、状态清理和输入/UI 收束函数。

## 2. 函数定位

- HCB 函数地址：`0x0005207E`。
- IR 起始地址：`335998`，见 [`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json:1312998)。
- 原始函数长度：从 `335998` 到 `336032`，共 35 字节。
- 函数签名：`args=12, locals=0`。
- 唯一直接下游：[`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:1)。
- 现有调用样本统计：旧分析文档统计到 433 个公开调用样本，见 [`f_0005207E函数解析.md`](f_0005207E函数解析.md:675)。

需要区分两个层次：

| 层次 | 函数 | 作用 |
|---|---|---|
| 外层接口 | [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) | 固定 12 参数 ABI，负责转发并补尾参数 |
| 核心控制器 | [`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:1) | 参数默认化、状态机、prim 运动和收尾 |

## 3. Lua-like 导出参数偏移

当前导出器的函数头为：

```lua
function f_0005207E(a0, a1, a2, a3, a4, a5, a6, a7, a8, a9, a10, a11)
```

但函数体读取的是 `a1` 到 `a12`。这是 HCB Lua-like 导出中的负栈槽命名偏移，不应直接按函数头名称理解。

原始 `init_stack args=12` 后依次读取：

```text
push_stack -13
push_stack -12
push_stack -11
push_stack -10
push_stack -9
push_stack -8
push_stack -7
push_stack -6
push_stack -5
push_stack -4
push_stack -3
push_stack -2
```

对于 12 个真实外部参数，建议使用 `P1` 到 `P12` 命名：

| 真实参数 | 原始栈槽 | 导出函数体名称 | 转发到核心函数 |
|---|---:|---|---|
| `P1` | `-13` | `a1` | `f_000519FC` 的 `a1` |
| `P2` | `-12` | `a2` | `a2` |
| `P3` | `-11` | `a3` | `a3` |
| `P4` | `-10` | `a4` | `a4` |
| `P5` | `-9` | `a5` | `a5` |
| `P6` | `-8` | `a6` | `a6` |
| `P7` | `-7` | `a7` | `a7` |
| `P8` | `-6` | `a8` | `a8` |
| `P9` | `-5` | `a9` | `a9` |
| `P10` | `-4` | `a10` | `a10` |
| `P11` | `-3` | `a11` | `a11` |
| `P12` | `-2` | `a12` | `a12` |

包装器额外补入：

```text

```

### 4.6 等价伪代码

```lua
function f_0005207E(P1, P2, P3, P4, P5, P6,
                    P7, P8, P9, P10, P11, P12)

```

因此，`f_0005207E()` 本体的结论非常确定：

> 它是一个固定 ABI 的参数转发器，不在自身执行运镜。

## 5. 核心函数 [`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:1) 的入口处理

虽然 [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 本身只有转发逻辑，但要解释 KS `$vm`，必须继续分析核心函数入口。

### 5.1 初始全局状态

核心函数开始执行：

```lua
G[248] = nil
G[13] = true
G[14] = 1
a4 = nil
```

对应 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:6-13)。

含义：

- `G[13] = true`：进入一轮图片/演出运动控制阶段；
- `G[14] = 1`：设置当前演出子模式；
- `G[248] = nil`：先清除“跳过预清场”状态；
- `a4 = nil`：覆盖核心内部第 4 槽。

### 5.2 `P4` 在当前公开入口中被丢弃

这里是一个关键事实：核心函数一进入就执行：

```lua
a4 = nil
```

因此外部传入的 `P4` 不会保留为可用业务参数。后续核心函数会把 `a4` 作为内部临时布尔工作槽，依据 `P7`、`G[164]`、`G[1950]` 等条件重新写入 `true` 或 `nil`。

所以对于用户给出的四参数 KS 宏：

```ks
#x #y #z #speed
```

第四个宏参数 `#speed` 并不是 `P4`，而是 `P5`。中间的 `P4` 是由 HCB 调用处补入的 `nil`。

## 6. 12 个参数的核心语义

### 6.1 `P1`：目标 X 坐标

核心入口中：

```lua
if P1 == nil then
    P1 = G[169]
end
```

之后在 [`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:550-560) 和其他同类路径中，P1 被传给 [`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:1)，最终进入：

```text
MotionMove(prim, src_x, src_y, dst_x, dst_y, duration, typ, reverse)
```

见 [`f_000523A8.lua`](Sakura_hcb_ir/Sakura/f_000523A8.lua:56-64) 与 [`18_Motion.md`](../syscalls/18_Motion.md:214)。

结论：

> `P1` 是二维运动的目标 X 坐标。若为 `nil`，沿用缓存 `G[169]`。

执行结束后，P1 会写回 `G[169]`，作为下一轮默认 X。

### 6.2 `P2`：目标 Y 坐标

P2 与 P1 对称：

```lua
if P2 == nil then
    P2 = G[170]
end
```

之后成为 `MotionMove` 的目标 Y 坐标，并在结束时写回 `G[170]`。

结论：

> `P2` 是二维运动的目标 Y 坐标。若为 `nil`，沿用缓存 `G[170]`。

### 6.3 `P3`：目标 Z / 纵深值

P3 是这套接口最重要的运动量之一。核心函数将它交给 [`f_0005243F()`](Sakura_hcb_ir/Sakura/f_0005243F.lua:1)，最终调用：

```text
MotionMoveZ(prim, src_z, dst_z, duration, typ, reverse)
```

见 [`f_0005243F.lua`](Sakura_hcb_ir/Sakura/f_0005243F.lua:43-49)。

在某一路径中，prim 190 使用 `P3 / 2`，而 prim 191 使用完整的 P3，见 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:507-518) 与 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:577-586)。

此外：

```lua
if P3 < 2000 then
    -- 进入短程/特殊准备分支
end
```

结论：

> `P3` 是演出对象的目标 Z / 纵深量，并参与短程与长程路径选择。

### 6.4 `P4`：当前公开接口中的保留位

核心函数入口立即执行：

```lua
a4 = nil
```

因此调用者传入的 P4 被覆盖，当前实现不会以外部输入的形式读取它。

后续的 `a4` 是核心内部临时开关，不能再反向解释为 P4。

结论：

> `P4` 是当前 wrapper 公开调用中的保留位/废弃位；传入值对当前核心路径无直接效果。

### 6.5 `P5`：主运动时长，KS 中命名为 `speed`

P5 的默认值：

```lua
if P5 == nil then
    if G[164] == 2 then
        P5 = 1100
    else
        P5 = 900
    end
end
```

见 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:71-86)。

随后 P5 被作为 duration 传给：

- [`MotionMoveZ`](Sakura_hcb_ir/Sakura/f_0005243F.lua:43-49)；
- [`MotionMoveR`](Sakura_hcb_ir/Sakura/f_0005253B.lua:43-49)；
- [`MotionMove`](Sakura_hcb_ir/Sakura/f_000523A8.lua:56-64)。

Motion 语义数据库确认这些 duration 单位为毫秒，见 [`18_Motion.md`](../syscalls/18_Motion.md:73-89)。

结论：

> `P5` 是整轮复合运动的主持续时间，单位为毫秒；KS 同义宏中 `#speed` 对应 P5，而不是 P4。

因此：

```ks
#speed="1600"
```

对应：

```lua
P5 = 1600
```

表示相关 Z、旋转和 XY 运动的主要 duration 基准为约 `1600 ms`。

注意：这不是“速度”意义上的每秒像素速度，而是运动完成所需的时间长度。KS 宏使用 `speed` 命名，是脚本层命名；在 HCB/FVP Motion 层更准确的名称是 `duration_ms`。

### 6.6 `P6`：运动插值类型

若 P6 为 `nil`，核心函数设置：

```lua
P6 = 4
```

随后 P6 传给 `MotionMoveZ`、`MotionMoveR` 和 `MotionMove` 的 type 参数。

Motion 语义中该参数对应运动插值/easing 类型，见 [`18_Motion.md`](../syscalls/18_Motion.md:91-110)。

结论：

> `P6` 是运动类型/补间编号；普通调用传 `nil` 时使用默认值 `4`。

### 6.7 `P7`：辅助路径选择器

若 P7 为 `nil`，核心函数将其归一化为 `-1`。它不直接成为 Motion syscall 参数，而是在内部条件树中决定临时开关 `a4` 的取值，并影响是否进入辅助运动/旧状态撤场路径。

可保守归纳为：

| P7 | 行为 |
|---:|---|
| `nil` | 归一化为 `-1`，自动选择路径 |
| `1` | 显式第一类路径 |
| 其他值 | 第二类路径 |

### 6.8 `P8`：尾端附加清理开关

若 P8 为 `nil`，默认设为 `1`。函数末尾检查：

```lua
if P8 >= 1 then
    f_0004A1AA(nil, nil, nil)
end
```

见 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:734-743)。

结论：

> `P8 >= 1` 时，主运动完成后追加一轮 UI/演出状态收束。

### 6.9 `P9`：执行方式/等待模式

若 P9 为 `nil`，默认设为 `0`。当 P9 等于 `1` 时，核心函数在 prim 190/191 的运动路径中轮询：

```lua
MotionMoveTest(190 or 191)
f_0003769F() -- ThreadNext
```

相关循环见 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:561-574)、[`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:629-642) 和 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:697-710)。

结论：

> `P9=1` 表示调用路径需要等待运动完成；默认 `P9=0` 则不一定在这些位置同步等待。

### 6.10 `P10`：特殊状态自动补正开关

P10 会传给 [`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:1)、[`f_0005243F()`](Sakura_hcb_ir/Sakura/f_0005243F.lua:1) 和 [`f_0005253B()`](Sakura_hcb_ir/Sakura/f_0005253B.lua:1)。这些 helper 在特定全局状态下检查 `P10 != -1`，并可能把内部运动控制量强制改为 `1`。

结论：

> `P10` 是特殊状态下的自动补正/快速收束开关；显式 `-1` 可禁止该类自动补正。

### 6.11 `P11`：主执行 prim 选择位

在核心函数的主要运动分支中：

```lua
if P11 == true then
    -- prim 190
else
    -- prim 191
end
```

见 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:493-518) 与 [`f_000519FC.lua`](Sakura_hcb_ir/Sakura/f_000519FC.lua:577-586)。

结论：

| P11 | 主 prim |
|---|---:|
| `true` | `190` |
| `nil/false` | `191` |

现有公开调用样本中 P11 基本为 `nil`，所以普通 `$vm` 路径主要使用 prim 191。

### 6.12 `P12`：跳过预清场标志

核心入口先：

```lua
G[248] = nil
if P12 == 1 then
    G[248] = true
end
```

之后预清场分支会检查 `G[248]`。因此：

- `P12 == 1`：跳过一轮早期旧状态预清场；
- `P12` 为 `nil` 或其他值：允许按全局状态决定是否预清场。

### 6.13 隐藏第 13 参数：包装器固定为默认分支

包装器补入 `nil`，核心函数将：

```lua
if a13 == nil then
    a13 = 1
end
```

随后：

- `a13 == 1`：调用 `f_00037F11(1,nil)`；
- 否则：调用 `f_00037F11(0,nil)`。

所以 [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 固定使用核心函数第 13 参数的 `1` 分支。

## 7. KS 宏实例逐项代入

用户给出的同义语句：

```ks
[macro name="$vm" #x="-255" #y="70" #z="1600" #speed="1600"]
```

### 7.1 参数落位

按公开接口的实际签名，应补齐为：

```lua
f_0005207E(
    -255,  -- P1 / x
    70,    -- P2 / y
    1600,  -- P3 / z
    nil,   -- P4 / 保留位
    1600,  -- P5 / speed -> duration_ms
    nil,   -- P6 / 默认 type
    nil,   -- P7
    nil,   -- P8
    nil,   -- P9
    nil,   -- P10
    nil,   -- P11
    nil    -- P12
)
```

这与 Sakura 开场脚本中的真实样本一致：

```lua
S0 = 255
S0 = -S0
S1 = 70
S2 = 1600
S3 = nil
S4 = 1600
S5 = nil
...
__ret = f_0005207E(S0, S1, S2, S3, S4, ...)
```

见 [`f_000A2981.lua`](Sakura_hcb_ir/Sakura/f_000A2981.lua:401-414)。

### 7.2 进入核心函数后的默认化结果

在不考虑特殊全局状态覆盖的普通路径中，大致得到：

```lua
P1 = -255
P2 = 70
P3 = 1600
P4 = nil       -- 外部值本来就是 nil，且核心固定覆盖为 nil
P5 = 1600
P6 = 4         -- nil -> 默认运动类型
P7 = -1        -- nil -> 自动分支模式
P8 = 1         -- nil -> 启用尾端清理
P9 = 0         -- nil -> 默认非显式等待模式
P10 = nil
P11 = nil      -- 采用 prim 191
P12 = nil      -- 不强制跳过预清场
H1 = nil -> a13 = 1
```

### 7.3 实际 Motion 结果

核心函数在普通 `P11=nil` 路径中主要对 `prim 191` 执行：

```text
1. MotionMoveZ(191, ..., 1600, 4, ...)
2. MotionMoveR(191, ..., 1600, 4, ...)
3. MotionMove(191, ..., -255, 70, 1600, 4, ...)
```

具体是否同时执行某些辅助 prim、是否等待、是否进行预清场，还受 `G[77]`、`G[175]`、`G[1949]`、`G[1950]`、`G[1987]`、`G[250]` 等全局状态影响。

因此该宏的视觉含义可以概括为：

> 让当前图片演出对象在约 1600 ms 内移动/推进到 `(x,y,z)=(-255,70,1600)`，并按默认补间与默认收尾策略完成一轮复合运镜；其中 X/Y 是二维位置，Z 是纵深/缩放相关的深度量，`speed=1600` 实际是主运动 duration，而非速度单位。

---

## 8. “运镜”这一判断是否准确

判断基本准确，但“运镜”需要分层理解。

### 高置信度

- P1/P2 直接进入二维 `MotionMove` 的目标 X/Y；
- P3 进入 `MotionMoveZ` 的目标 Z，并控制纵深/景深式运动；
- P5 是多个运动分量共享的 duration；
- P6 是运动插值类型；
- 核心函数会轮询 `MotionMoveTest` 并逐帧让出执行权；
- 目标对象主要是 prim 190/191。

### 更准确的术语

与其称为单纯“摄像机运镜”，更准确的是：

> **针对剧情图片/前景演出 prim 的复合空间运动控制器。**

它会组合二维平移、Z 轴运动、旋转、缩放/辅助层调整和状态收尾。若 prim 190/191 是承载整张 CG 或场景前景的父图元，那么从玩家视觉上看，它就表现为“镜头运镜”；从引擎实现上看，本质是对图元变换属性的复合动画。

---

## 9. 与直接 [`MotionMove()`](../syscalls/18_Motion.md:214) 的区别

不能将 `$vm` 简化为：

```lua
MotionMove(191, nil, nil, -255, 70, 1600, 4, nil)
```

因为核心函数还会：

1. 维护 `G[13]`、`G[14]`、`G[248]` 等阶段状态；
2. 根据 P11 选择 prim 190/191；
3. 同时驱动 `MotionMoveZ` 和 `MotionMoveR`；
4. 可能先执行旧状态撤场；
5. 可能调用 `ControlPulse`、[`f_00037F11()`](Sakura_hcb_ir/Sakura/f_00037F11.lua:1) 等场景/UI 控制；
6. 根据 P9 轮询运动是否结束；
7. 结束后更新 `G[165]`、`G[166]`、`G[169]`、`G[170]` 缓存；
8. 根据 P8 再执行 [`f_0004A1AA()`](Sakura_hcb_ir/Sakura/f_0004A1AA.lua:1) 收尾。

因此 [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 是一个**运镜模板入口**，不是单一二维平移动画的别名。

## 11. 最终结论

1. [`f_0005207E()`](Sakura_hcb_ir/Sakura/f_0005207E.lua:1) 本体只有参数转发作用；其原始指令已逐条对应到 `0x0005207E–0x000520A0`。
2. 它将 12 个真实参数按原顺序转发给 [`f_000519FC()`](Sakura_hcb_ir/Sakura/f_000519FC.lua:1)，并固定补入第 13 参数 `nil`。
3. 用户给出的 KS 宏映射为：
   - `#x=-255` → `P1=-255` → 目标 X；
   - `#y=70` → `P2=70` → 目标 Y；
   - `#z=1600` → `P3=1600` → 目标 Z/纵深；
   - `#speed=1600` → `P5=1600` → 主运动时长约 1600 ms。
4. 宏中没有显式出现的 P4 是保留位，不应把 `#speed` 错位解释为 P4；`#speed` 实际落在 P5。
5. 整体效果不是单一 `MotionMove`，而是 prim 190/191 上的二维平移、Z 运动、旋转及辅助状态收尾组成的复合运镜模板。
6. 从引擎实现角度，`#speed` 更准确地应翻译为 `duration_ms`；它表示动画完成时长，而非像素/秒意义上的速度。
