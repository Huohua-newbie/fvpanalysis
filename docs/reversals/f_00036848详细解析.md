# [`f_00036848()`](Sakura_hcb_ir/Sakura/f_00036848.lua:1) BGM/长音频切换详细解析

## 1. 函数定位

- 原始函数：[`f_00036848.lua`](Sakura_hcb_ir/Sakura/f_00036848.lua:1)
- 已有逐条反汇编：[`f_00036848逐条反汇编对照.md`](./f_00036848逐条反汇编对照.md:1)
- 函数地址范围：`0x00036848–0x0003685B`
- HCB 文件偏移：`223304–223323`
- 字节长度：`20` 字节
- 函数序言：`init_stack args=1, locals=0`
- 直接调用内部函数：[`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)
- 直接调用 syscall：无

[`f_00036848()`](Sakura_hcb_ir/Sakura/f_00036848.lua:1) 是一个非常薄的 BGM/长音频切换包装器。它本身不执行 `AudioLoad` 或 `AudioPlay`，而是：

1. 设置 `G[2071] = true`；
2. 将固定参数 `44`、三个 `nil`/辅助值和调用者传入的音频编号转发给 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)。

因此，真正决定 BGM 路径、音频槽、循环、音量和切换等待行为的是 `f_0005511C()`，而 `f_00036848()` 更像一个**“原作标准 BGM 入口/模式预设包装函数”**。

## 2. 参数说明

本函数只有一个显式参数：

| 参数 | 当前含义 | 置信度 |
|---|---|---|
| `a0` | BGM/长音频编号，或在部分调用点中作为下游 Audio 路径/编号的来源。 | 高 |

参数映射：

```text
init_stack args=1
push_stack -2 -> a0
```

旧 Lua-like 导出文本中本函数体显示为 `a1`，那是此前已确认的参数编号整体右移错误；真实参数是 `a0`。

| 6 | `push_nil` | 准备下游第 3 个调用值。 |

| 8 | `push_nil` | 准备下游最后一个调用值。 |
| 9 | `call 0x0005511C` | 调用 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)，进入实际 Audio 控制链。 |

## 4. `G[2071]` 的作用

本函数固定执行：

```lua
G[2071] = true
```

当前资料中，`G[2071]` 的直接读取点较少，不能仅凭本函数给出绝对业务名称。但它很可能是：

- 标记当前 BGM/音频切换来自标准 BGM 包装入口；
- 标记进入某种特定 BGM 模式；
- 供下游音频、菜单或场景恢复逻辑识别“已初始化 BGM 状态”。

需要注意：`G[2071]` 并不负责实际播放。真正的播放由下游 [`AudioPlay`](../syscalls/01_Audio.md:149) 完成。

因此可以明确区分：

```text
G[2071] = true
    -> 模式/状态标记
f_0005511C(...)
    -> 实际音频槽切换与播放
```

## 5. 下游 `f_0005511C()` 的作用

### 5.1 下游整体流程

结合 [`f_0005511C.lua`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1) 和 [`f_00055202.lua`](Sakura_hcb_ir/Sakura/f_00055202.lua:1)，其流程可以概括为：

```text
判断目标音频是否与当前记录不同
    |
    |-- 相同：直接结束
    |
    `-- 不同：
          更新当前音频记录
          选择 BGM/ BGM2 路径
          格式化三位编号
          选择 Audio 槽位 0 或 1
          AudioStop(旧槽, 100)
          AudioType(槽, 1)
          AudioLoad(槽, 路径)
          AudioVol(槽, 音量, nil)
          AudioPlay(槽, true 或 nil)
          可选调用 f_00055202() 停止另一槽
```

### 5.2 音频路径选择

`f_0005511C()` 会根据一个下游模式参数选择：

```text
BGM/NNN
```

或：

```text
BGM2/NNN
```

然后用 `IntToText(..., 3)` 将编号格式化为三位数字。

因此，`f_00036848(a0)` 的编号最终很可能形成类似：

```text
f_00036848(44)
    -> BGM/044 或 BGM2/044
```

但要注意，`f_00036848()` 固定传给下游的 `44` 是另一个控制参数，而它的唯一外部参数 `a0` 位于下游参数序列的后部。换言之，不应只看 `f_00036848()` 中的固定 `44` 就断言 BGM 编号必然是 `44`；真正参与路径拼接的编号要看下游对应参数槽的转发关系。

### 5.3 Audio 槽位选择

`f_0005511C()` 维护两个 Audio 槽位：

- `G[213]`：当前操作的 Audio 槽；
- `G[214]`：另一个槽位/备用槽。

根据 `G[213]` 当前状态，函数会在槽 `0` 和槽 `1` 之间切换：

```lua
if G[213] == 0 then
    G[213] = 1
    G[214] = 0
else
    G[213] = 0
    G[214] = 1
end
```

随后对当前槽执行：

```lua
AudioStop(G[213], 100)
AudioType(G[213], 1)
AudioLoad(G[213], path)
AudioVol(G[213], volume, nil)
AudioPlay(G[213], looped)
```

这说明 `f_00036848()` 不是直接控制一个固定音频槽，而是通过下游函数参与两个 Audio 槽之间的切换。

### 5.4 音量与循环

`f_0005511C()` 的下游参数中：

- 音量缺省为 `100`；
- `AudioVol` 的音量单位为 `0..100` 百分比；
- 循环条件为某个参数 `== 1 or nil`，满足时调用：

```lua
AudioPlay(slot, true)
```

否则调用：

```lua
AudioPlay(slot, nil)
```

因此，`f_00036848()` 本身没有独立的循环参数；它固定把某些下游槽设为 `nil`，实际循环策略由 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:77) 的参数模板决定。

## 6. `f_00055202()` 的收尾作用

当下游 `f_0005511C()` 的某个参数要求旧音频停止时，会调用：

```lua
f_00055202(duration)
```

[`f_00055202()`](Sakura_hcb_ir/Sakura/f_00055202.lua:1) 会：

- `duration == nil` 时默认使用 `4500`；
- `duration != nil` 时加上 `1000`；
- 使用 `G[214]` 选择另一个 Audio 槽；
- 调用：

```lua
AudioStop(G[214], duration)
```

因此 BGM 切换不是简单的：

```text
停止旧 BGM -> 立即播放新 BGM
```

而可能是：

```text
选择新槽加载/播放新 BGM
    ↓
对另一槽执行带时长的 AudioStop
```

这具备一定的交叉切换特征。

## 7. 与调用样本的关系

### 7.1 [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:62)

开场调用为：

```lua
S0 = nil
__ret = f_00036848(S0)
```

也就是：

```lua
f_00036848(nil)
```

这会：

1. 设置 `G[2071] = true`；
2. 将 `nil` 转发给下游对应的 BGM 编号/控制槽；
3. 由下游函数决定实际使用的默认路径、音频槽、音量和播放状态。

因此 `f_00036848(nil)` 不一定等于“播放编号 0”；`nil` 的具体效果取决于 `f_0005511C()` 对该参数的默认化和路径构造。

### 7.2 其他调用样本

在其他剧情函数中，调用者可能传入：

- 整数 `1`、`44`、`51`、`170`、`221`；
- 大整数剧情/音频标识；
- 字符串或 `nil`。

这说明 `f_00036848()` 的参数在原作中不一定只表示简单的连续 BGM 编号。对整数值，最可能是 BGM 资源编号；对字符串或特殊值，则还需结合下游 `IntToText` 的类型处理和调用点验证。

## 8. syscall 层完整链路

```text
f_00036848(a0)
    |
    |-- G[2071] = true
    |
    `-- f_0005511C(44, nil, nil, a0, nil)
          |
          |-- IntToText(audio_id, 3)
          |-- AudioStop(current_slot, 100)
          |-- AudioType(current_slot, 1)
          |-- AudioLoad(current_slot, "BGM/NNN" 或 "BGM2/NNN")
          |-- AudioVol(current_slot, volume, nil)
          |-- AudioPlay(current_slot, true 或 nil)
          `-- 可选 f_00055202()
                `-- AudioStop(other_slot, fade_duration)
```

`Audio` syscall 的关键语义见 [`01_Audio.md`](../syscalls/01_Audio.md:1)：

- Audio 槽位范围为 `0..3`，本函数下游主要使用 `0/1`；
- `AudioLoad(slot, path)` 装载长音频资源；
- `AudioPlay(slot, looped)` 的第二参数按真值解释循环；
- `AudioVol(slot, volume, crossfade)` 使用 `0..100` 音量百分比；
- `AudioStop(slot, fadeout)` 的第二参数为毫秒淡出时长；
- 这些 syscall 本身不主动 yield，但音频播放由后端异步推进。

## 9. 最终作用判断

### 高置信度

1. [`f_00036848()`](Sakura_hcb_ir/Sakura/f_00036848.lua:1) 是 BGM/长音频切换包装函数。
2. 唯一参数 `a0` 是下游音频编号/资源参数的来源。
3. 它固定设置 `G[2071] = true`。
4. 它固定调用 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)。
5. 真正的 `AudioStop/AudioType/AudioLoad/AudioVol/AudioPlay` 都由下游函数执行。

### 中等置信度

- 固定值 `44` 是标准 BGM 入口的控制参数，可能决定 BGM/BGM2 路径或下游模式；
- BGM 主要使用两个 Audio 槽 `0/1` 交替切换；
- `G[2071]` 是标准 BGM 初始化/切换模式标志；
- 某些切换会通过 [`f_00055202()`](Sakura_hcb_ir/Sakura/f_00055202.lua:1) 对另一 Audio 槽执行延迟停止。

### 尚需验证

- `f_00036848(a0)` 的 `a0` 在实际下游参数序列中究竟对应哪个 BGM 编号槽；
- 固定值 `44` 的精确业务意义；
- `G[2071]` 的所有读取点和完整状态生命周期；
- `BGM/NNN` 与 `BGM2/NNN` 两类资源的具体区别；
- `f_00036848(nil)` 在原作中的默认 BGM 行为。

> 总结：[`f_00036848()`](Sakura_hcb_ir/Sakura/f_00036848.lua:1) 不是 BGM 播放底层函数，而是一个标准入口包装器。它设置 BGM 模式标志，然后把音频参数交给 [`f_0005511C()`](Sakura_hcb_ir/Sakura/f_0005511C.lua:1)，由后者完成路径选择、Audio 槽切换、加载、音量设置、循环播放和旧槽淡出停止。
