## 1. 函数定位与总体结论

- 原始函数：[`f_00055946.lua`](Sakura_hcb_ir/Sakura/f_00055946.lua:1)
- HCB：[`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb)
- 函数地址范围：`0x00055946–0x0005599C`
- HCB 文件偏移：`350534–350620`
- 字节长度：`87` 字节
- 函数序言：`init_stack args=3, locals=1`
- 显式入参数量：`3`
- 局部变量数量：`1`
- 直接调用的内部函数：
  - [`f_0005599D()`](Sakura_hcb_ir/Sakura/f_0005599D.lua:1)
  - [`f_00037708()`](Sakura_hcb_ir/Sakura/f_00037708.lua:1)
- 直接调用的 syscall：
  - [`V3DMotionTest`](../syscalls/31_V3D.md:1)

本函数是一个**dissolve 启动后与 V3D 动作同步的等待包装函数**。它本身不直接调用 `Dissolve`，而是把转场启动工作交给 [`f_0005599D()`](Sakura_hcb_ir/Sakura/f_0005599D.lua:1)，随后根据第三个参数和 `V3DMotionTest` 的结果，决定是否再等待一段时间。

其整体流程可以概括为：

```text
保存第一个入参到局部变量 l0
    ↓
第三个参数缺省为 0
    ↓
设置 G[23] = true
    ↓
调用 f_0005599D(a0, a1)，启动 dissolve
    ↓
如果 a2 == 1 且 V3DMotionTest() == true
    ↓
等待 max(a0 - 100, 1) ms
    ↓
清除 G[23]
```

因此它更准确的作用名称是：

> **启动 dissolve，并可选地等待 V3D 动作同步完成的辅助函数。**

## 2. 参数映射

该函数的 `init_stack` 是 `args=3, locals=1`。负索引参数映射为：

|---|---|
| `push_stack -4` | `a0` |
| `push_stack -3` | `a1` |
| `push_stack -2` | `a2` |

此外，本函数使用正索引 `0` 访问一个局部槽：

| 原始槽位 | 正确名称 |

旧 Lua-like 导出结果把这些槽位显示成了 `a1/a2/a3` 以及 `a0`，这是此前参数/局部槽命名偏移的另一表现。阅读本函数时应以原始负索引和 `init_stack args=3, locals=1` 为准。

## 4. 调用样本分析

### 4.1 开场调用

[`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:27) 的一条调用为：

```lua
f_00055946(nil, nil, nil)
```

这会产生：

- `l0 = nil`；
- `a2` 缺省为 `0`；
- 设置 `G[23] = true`；
- 调用 `f_0005599D(nil, nil)`，由下游将 dissolve 时长默认成 `400`；
- 因 `a2 == 0`，不进入 V3D 同步等待；
- 清除 `G[23]`。

### 4.2 带额外等待的调用

在 [`f_00010298()`](Sakura_hcb_ir/Sakura/f_00010298.lua:130) 中可见类似：

```lua
f_00055946(1300, nil, nil)
```

这里：

- `a0 = 1300` 被保存到 `l0`；
- `a1 = nil`，由 `f_0005599D()` 将 dissolve 时长默认成 `400`；
- `a2 = nil`，不会进入 `V3DMotionTest` 同步等待分支。

这说明 `a0` 并不等同于下游 dissolve 时长；它可能是供某些调用模式使用的后置同步等待基准，即使在该具体调用中由于 `a2=nil` 没有实际消费。

### 4.3 显式启用 V3D 同步

在部分特殊演出调用中，第三个参数为 `1`：

```lua
f_00055946(a0, a1, 1)
```

此时如果 `V3DMotionTest()` 返回 `true`，函数会：

```lua
l0 = max(a0 - 100, 1)
f_00037708(l0, -1)
```

因此第三个参数不是普通的时间值，而是一个明确的同步开关。

## 5. 下游函数追踪

### 5.1 [`f_0005599D()`](Sakura_hcb_ir/Sakura/f_0005599D.lua:1)

本函数调用：

```lua
f_0005599D(a0, a1)
```

`f_0005599D()` 的关键行为是：

1. 设置 `G[118] = true`，表示某种过渡/演出状态正在进行；
2. 若其第二参数为 `nil`，默认时长为 `400`；
3. 在 `G[1987] == 1` 且 `G[250] == nil` 时，将时长乘以 `2/3`；
4. 对时长做至少 `1` 的钳制；
5. 将 prim `190`、`191` 的 alpha 设为 `255`；
6. 必要时调用 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1)；
7. 设置 `G[310] = 0`；
8. 最终调用：

```lua
Dissolve(duration, nil, nil, nil, nil, nil, nil)
```

对应 syscall 为 [`Dissolve`](../syscalls/06_Dissolve.md:75)。

因此 `f_00055946()` 的前半段职责不是自己创建 dissolve，而是通过 `f_0005599D()` 启动一轮默认/颜色型 dissolve，然后再决定是否等待 V3D 动作。

### 5.2 [`V3DMotionTest`](../syscalls/31_V3D.md:1)

本函数在以下条件下调用 `V3DMotionTest`：

```lua
if a2 == 1 then
    V3DMotionTest()
end
```

返回值与 `true` 比较。只有返回 `true` 时才认为 V3D 动作仍处于需要等待的状态。

这里没有传入 V3D 动作编号，说明该 syscall 查询的是全局 V3D 动作状态，而非某个显式对象槽。

### 5.3 [`f_00037708()`](Sakura_hcb_ir/Sakura/f_00037708.lua:1)

同步分支中调用：

```lua
f_00037708(max(a0 - 100, 1), -1)
```

该函数继续追踪到：

- `TimerSet(0, duration)`：设置计时器；
- `TimerGet(0, 100)`：查询计时器经过时间；
- `InputGetState()`：读取输入；
- [`ThreadNext`](../syscalls/27_Thread.md:1)：循环中让出一帧。

因此这不是简单的阻塞 sleep，而是一个**可响应输入、按计时器推进并逐帧让出执行权的等待函数**。第二参数 `-1` 会影响 `f_00037708()` 内部的输入判断模式。

## 6. 全局状态 `G[23]`

本函数入口设置：

```lua
G[23] = true
```

函数结束时无论是否进入等待分支，都会执行：

```lua
G[23] = nil
```

`G[23]` 因此是一个明确的“当前正在进行某种同步/过渡辅助流程”标志。相关函数如 [`f_00055A57()`](Sakura_hcb_ir/Sakura/f_00055A57.lua:6)、[`f_00055CB5()`](Sakura_hcb_ir/Sakura/f_00055CB5.lua:17) 和 [`f_00055D3D()`](Sakura_hcb_ir/Sakura/f_00055D3D.lua:8) 也采用类似的设置/清除模式。

它的用途可能包括：

- 防止过渡期间重复进入某些 UI 或演出逻辑；
- 告知下游流程当前处于同步等待上下文；
- 让其他线程或系统状态判断当前是否正在执行过渡辅助。

仅凭本函数还不能确定所有读取 `G[23]` 的下游分支，但可以高置信度认为它是临时的过渡/同步活动标志，而不是持久场景参数。

## 8. 等价伪代码

function f_00055946(a0, a1, a2)
    local l0 = a0

    if a2 == nil then
        a2 = 0
    end

    G[23] = true

    -- 下游主要使用 a1 作为 dissolve 时长；a0 在本函数中保留为后置等待基准

## 9. 与相关函数的关系

## 10. 最终作用判断

### 高置信度结论

1. `f_00055946` 有 3 个显式参数和 1 个局部槽 `l0`。
2. `a2 == nil` 时默认变为 `0`。
3. 函数设置 `G[23] = true`，结束时清除。
4. 函数调用 `f_0005599D(a0, a1)` 启动 dissolve。
5. 只有 `a2 == 1` 且 `V3DMotionTest() == true` 时，才进入额外等待。
6. 额外等待时长为 `max(a0 - 100, 1)`。

### 中等置信度结论

- `a0` 是与 V3D 同步阶段相关的后置等待基准；
- `a1` 是传给 `f_0005599D` 的 dissolve 时长或其相关模式参数；
- `a2` 是 V3D 同步等待开关；
- `G[23]` 是临时过渡/同步活动标志。

### 尚待验证

- `a0` 与 `a1` 在所有调用模式中的精确时间关系；
- `a2 == 1` 是否只用于 V3D 动作等待，还是还代表某种更广义的同步模式；
- `f_0005599D()` 第一参数未被明显使用的原因，是否与底层栈槽/导出命名差异有关。

## 11. 后续验证建议

1. 对所有 `f_00055946()` 调用统计三参数，特别关注 `a0/a1/a2` 的非 `nil` 值组合。
2. 重点对比 `f_00055946(2000, nil, nil)`、`f_00055946(1300, nil, nil)` 和 `f_00055946(..., ..., 1)` 的画面时序。

4. 检查 `G[23]` 的读取点，确认它是否会影响并发线程或过渡状态机。

> 结论：[`f_00055946()`](Sakura_hcb_ir/Sakura/f_00055946.lua:1) 是一个“**发起 dissolve，并在指定条件下等待 V3D 动作结束/推进一段剩余时间**”的同步辅助函数，而不是独立的 dissolve 实现本体。
