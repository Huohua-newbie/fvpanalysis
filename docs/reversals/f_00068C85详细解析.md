# [`f_00068C85()`](Sakura_hcb_ir/Sakura/f_00068C85.lua:1)：`$chara_move` 单立绘成对图元运动调度器

## 1. 结论先说

[`f_00068C85()`](Sakura_hcb_ir/Sakura/f_00068C85.lua:1) 对应 KS 中的 `$chara_move`。它根据第一个参数选择一个立绘逻辑槽位，并同时操作该槽位关联的四个图元：

```text
主层 Graph prim
部件/辅助 Graph prim
主层 + 1500 的配对 prim
辅助层 + 1500 的配对 prim
```

它可以一次性提交：

- XY 平移；
- Z 深度移动；
- 旋转；
- 可选等待运动完成。

因此用户已有判断的主体是对的：前六个真实参数确实对应：

```text
slot, x, y, z, rotation, time
```

但需要校正两点：

1. 此函数实际有 **9 个真实显式参数**，不是 10 个；Lua-like 导出器的函数头/变量名存在整体偏移，不能按表面 `a0..a8` 直接计数。
2. 最后三个参数不是 alpha：它们是 **motion 插值类型、是否等待完成、前置刷新/输入处理开关**。

更准确的业务签名是：

```lua
CharaMove(slot, dx, dy, z, rotation, time, motion_type, wait, preflight)
```

其中：

| 参数 | 作用 |
|---|---|
| `slot` | 立绘逻辑槽位编号 |
| `dx` | X 增量（相对移动） |
| `dy` | Y 增量（相对移动） |
| `z` | 目标 Z（绝对值；传 `nil` 则不提交 Z motion） |
| `rotation` | 目标旋转角（绝对值；传 `nil` 则不提交旋转 motion） |
| `time` | XY/Z/旋转 motion 持续时间，默认 `500 ms` |
| `motion_type` | Motion easing/type，默认 `3` |
| `wait` | `1` 时轮询并阻塞到 motion 完成；其他值不等待 |
| `preflight` | 前置 UI/输入/舞台状态处理开关，默认 `1` |

**本函数没有调用 `MotionAlpha`，也没有读取或写入角色 alpha 值。**

### 2.2 真实参数数是 9

反编译函数头写成：

```lua
function f_00068C85(a0, a1, a2, a3, a4, a5, a6, a7, a8)
```

但函数体实际使用到 `a9`，而入口注释显示：

```text
init_stack args=9
```

因此应明确：

> **该函数有 9 个真实显式参数。Lua-like 导出器只在函数头中显示到 `a8`，但函数体的 `a1..a9` 对应真实第 1 至第 9 个实参。**

本报告不再使用导出器的表面参数名，而统一使用真实调用顺序。

## 4. 第 1 参数：`slot` 是立绘逻辑槽位，不是 prim ID

函数按 `slot` 分派到预定义的立绘对象组。例如：

| `slot` | 主/辅助 prim | 位置缓存 X/Y | Z/旋转缓存 |
|---:|---|---|---|
| `1` | `100,101` 与 `1600,1601` | `G[623],G[624]` | `G[625],G[626]` |
| `2` | `102,103` 与 `1602,1603` | `G[627],G[628]` | `G[629],G[630]` |
| `3` | `104,105` 与 `1604,1605` | `G[631],G[632]` | `G[633],G[634]` |
| `…` | `…` | `…` | `…` |
| `24` | `138,139` 与 `1638,1639` | `G[711],G[712]` | `G[713],G[714]` |
| `0` | `138,139` 与 `1638,1639` | `G[715],G[716]` | `G[717],G[718]` |

相关分派代码见 [`f_00068C85.lua`](Sakura_hcb_ir/Sakura/f_00068C85.lua:73) 至 [`f_00068C85.lua`](Sakura_hcb_ir/Sakura/f_00068C85.lua:719)。

`slot=20` 在该函数中没有对应分支，因此不宜传入。

### 4.1 为什么会操作四个 prim

每个逻辑角色槽位都有两个基础 prim，以及两者对应的 `+1500` 配对 prim。函数对四个对象都下发同样的 XY/Z/旋转 motion，例如 slot 1 会操作：

```text
100, 101, 1600, 1601
```

这与 Sakura 的立绘分层架构一致：Graph 与 Parts/辅助层需要一起运动，否则画面层会错位。

---

## 5. 第 2、3 参数：`dx` / `dy` 是相对增量

函数首先对两项做默认化：

```lua
if dx == nil then dx = 0 end
if dy == nil then dy = 0 end
```

然后对所选槽位的原始位置缓存做加法：

```lua
new_x = cached_x + dx
new_y = cached_y + dy
```

例如 slot 1 的逻辑等价于：

```lua
new_x = G[623] + dx
new_y = G[624] + dy
```

因此：

> `dx` / `dy` 是相对于当前已登记立绘位置的偏移量，而不是直接覆盖为绝对坐标。

KS 调用也印证这一点：

```ks
[macro name="$chara_move" #cname="..." #x="75" #t="500"]
```

出现在 [`route_haru.ks`](../../reference/SakuraMoyu_NS/route_haru.ks:20068)，其 `x=75` 很符合“从当前位置再移动 75”而非“移动到屏幕 X=75”的用法。

---

## 6. 第 4 参数：`z` 是目标 Z，而非 Z 增量

`z` 与 `dx/dy` 的处理不同：

```lua
if z ~= nil then
    target_z = z
    MotionMoveZ(..., current_z, target_z, time, motion_type, ...)
end
```

它不会先执行 `cached_z + z`。因此：

> `z` 是要写入的目标深度/构图 Z 值；传 `nil` 表示本次不移动 Z。

例如原始调用：

```lua
f_00068C85(4, nil, -25, 600, nil, 500, nil, nil, nil)
```

可见于 [`f_000A2981.lua`](Sakura_hcb_ir/Sakura/f_000A2981.lua:21439)。这里：

- `slot=4`
- `dx=nil → 0`
- `dy=-25`
- `z=600`
- `rotation=nil`
- `time=500`

会让该角色在 500 ms 内向 Y 负方向偏移 25，同时把 Z 移到 600。

---

## 7. 第 5 参数：`rotation` 是目标旋转角

`rotation` 只有在非 `nil` 时才进入：

```lua
MotionMoveR(prim, current_rotation, rotation, time, motion_type, nil)
```

其下游包装器是 [`f_0005253B()`](Sakura_hcb_ir/Sakura/f_0005253B.lua:43)，最终调用 [`MotionMoveR()`](../../syscall语义数据库/syscall含义详解/18_Motion.md:270)。

因此：

> `rotation` 是绝对目标旋转角；`nil` 表示保持当前旋转，不创建旋转 motion。

它不是 alpha，也不是“旋转增量”。函数将当前缓存旋转作为 motion 的起点，而把该参数作为终点。

---

## 8. 第 6 参数：`time` 是三类 motion 的共同持续时间

入口默认：

```lua
if time == nil then time = 500 end
```

在特殊全局状态下，函数可能：

- 将其缩短为 `time * 2 / 3`；
- 强制为 `1`；
- 在部分辅助层使用同一时长。

正常路径下，`time`被同时传给：

```text
MotionMove  的 duration
MotionMoveZ 的 duration
MotionMoveR 的 duration
```

对应下游调用：

- [`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:56) → `MotionMove`
- [`f_0005243F()`](Sakura_hcb_ir/Sakura/f_0005243F.lua:43) → `MotionMoveZ`
- [`f_0005253B()`](Sakura_hcb_ir/Sakura/f_0005253B.lua:43) → `MotionMoveR`

Motion syscall 的 duration 单位为毫秒。因此普通情况下：

> `time` 是这次单立绘 XY/Z/旋转运动的统一持续时间（ms）。

KS 中对应属性写作 `#t`，如：

```ks
[macro name="$chara_move" #cname="..." #y="415" #t="1000"]
```

见 [`route_haru.ks`](../../reference/SakuraMoyu_NS/route_haru.ks:14436)。

---

## 9. 第 7 参数：`motion_type` 是插值/easing 类型

入口默认：

```lua
if motion_type == nil then motion_type = 3 end
```

它被同时作为：

```text
MotionMove(..., typ = motion_type, ...)
MotionMoveZ(..., typ = motion_type, ...)
MotionMoveR(..., typ = motion_type, ...)
```

三个下游包装器均原样转发它：

- [`f_000523A8.lua`](Sakura_hcb_ir/Sakura/f_000523A8.lua:56) 的 `a7` → `MotionMove` 的 `typ`
- [`f_0005243F.lua`](Sakura_hcb_ir/Sakura/f_0005243F.lua:43) 的 `a5` → `MotionMoveZ` 的 `typ`
- [`f_0005253B.lua`](Sakura_hcb_ir/Sakura/f_0005253B.lua:43) 的 `a5` → `MotionMoveR` 的 `typ`

根据 Motion syscall 资料，`typ` 是 easing/motion type 枚举。因此：

> 第 7 参数控制平移、Z、旋转共同使用的插值曲线/运动类型，默认值为 `3`。

目前可以确认它是 Motion 类型，但尚未在 Sakura 实机中为 `0..N` 建立完整的视觉命名表。新增脚本建议省略，保持默认 `3`。

---

## 10. 第 8 参数：`wait` 是运动完成等待开关

入口默认：

```lua
if wait == nil then wait = 0 end
```

函数尾部只在：

```lua
wait == 1
```

时进入轮询：

```lua
while MotionMoveTest(primary) or MotionMoveTest(auxiliary) do
    ThreadNext()
end

while MotionMoveZTest(primary) or MotionMoveTest(auxiliary) do
    ThreadNext()
end

while MotionMoveRTest(primary) or MotionMoveTest(auxiliary) do
    ThreadNext()
end
```

见 [`f_00068C85.lua`](Sakura_hcb_ir/Sakura/f_00068C85.lua:1283)。

因此：

> 第 8 参数是同步等待开关：`1` 等待本次运动结束，其他值（默认 `0`）则提交 motion 后立即返回。

它不设置透明度，也不影响 alpha。

注意：反编译结果里 Z/旋转轮询的第二个对象误用 `MotionMoveTest` 的可能性存在，但不影响“第 8 参数控制等待”的结论。

---

## 11. 第 9 参数：`preflight` 是前置状态处理开关

入口默认：

```lua
if preflight == nil then preflight = 1 end
```

当：

```lua
preflight == 1
```

函数调用：

```lua
f_0005073F()
f_0004A5DE(nil, nil, nil, nil)
```

其中：

- [`f_0005073F()`](Sakura_hcb_ir/Sakura/f_0005073F.lua:5) 调用 [`f_00049EC9()`](Sakura_hcb_ir/Sakura/f_00049EC9.lua:1)，处理一组舞台/覆盖图元 alpha 状态；
- [`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:5) 调用 [`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1) 与 `InputGetState`，属于输入/UI/舞台状态的前置协调。

因此它可以保守命名为：

> **本次单立绘运动前是否执行全局舞台/UI/输入预处理的开关。**

它不是 alpha 数值，也不直接决定立绘透明度。

原作多数 `$chara_move` 调用省略该参数，因而使用默认 `1`；但针对新增脚本，若在一个已有演出批次中连续发起多次移动，是否可安全传 `0` 跳过前置处理仍应通过实机验证确认。

## 12. 三个下游运动包装器

### 12.1 [`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:1)：XY motion

此函数最终调用：

```lua
MotionMove(id, src_x, src_y, dst_x, dst_y, time, motion_type, reverse)
```

在本函数的调用里：

```text
src_x/src_y = nil/nil（使用当前坐标）
dst_x/dst_y = 当前缓存位置 + dx/dy
time        = 第 6 参数
typ         = 第 7 参数
reverse     = nil
```

### 12.2 [`f_0005243F()`](Sakura_hcb_ir/Sakura/f_0005243F.lua:1)：Z motion

最终调用：

```lua
MotionMoveZ(id, src_z, dst_z, time, motion_type, reverse)
```

在本函数中：

```text
src_z = nil（使用当前 Z）
dst_z = 第 4 参数 z
time  = 第 6 参数
typ   = 第 7 参数
```

### 12.3 [`f_0005253B()`](Sakura_hcb_ir/Sakura/f_0005253B.lua:1)：旋转 motion

最终调用：

```lua
MotionMoveR(id, src_rotation, dst_rotation, time, motion_type, reverse)
```

在本函数中：

```text
src_rotation = nil（使用当前旋转）
dst_rotation = 第 5 参数 rotation
time         = 第 6 参数
typ          = 第 7 参数
```

## 13. 它与 alpha 的边界

用户推测最后三个参数可能和 alpha 有关；现有代码不支持这一点：

- 本函数没有 `MotionAlpha` syscall；
- 三个直接下游只调用 `MotionMove`、`MotionMoveZ`、`MotionMoveR`；
- 最后三个参数分别流向 motion type、等待逻辑、前置 UI/输入处理；
- 角色 alpha 的批量控制发生在 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) → [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 及其 [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 后处理链中。

因此：

> `$chara_move` 是独立的单角色/单槽位位移、Z、旋转运动命令；它不承担角色淡入淡出。若要改 alpha，应研究 `$chara_disp`、`$chara` 的 alpha 参数或直接 `MotionAlpha` 路径。

## 15. 推荐调用方式

### 15.1 只做相对平移

```lua
f_00068C85(slot, dx, dy, nil, nil, time, nil, nil, nil)
```

例如：

```lua
f_00068C85(3, 75, 0, nil, nil, 500, nil, nil, nil)
```

含义：角色槽位 3 向 X 正方向移动 75，持续 500 ms，使用默认 motion type，不等待，不需要手动指定前置开关。

### 15.2 平移并改变 Z

```lua
f_00068C85(slot, dx, dy, target_z, nil, time, nil, nil, nil)
```

### 15.3 平移、Z、旋转同时进行

```lua
f_00068C85(slot, dx, dy, target_z, target_rotation, time, motion_type, wait, preflight)
```

### 15.4 需要脚本同步等待

```lua
f_00068C85(slot, dx, dy, z, rotation, time, nil, 1, nil)
```

`wait=1` 会在函数内 `ThreadNext()` 轮询动作结束。不要再额外插入同一立绘的互相冲突 motion，避免覆盖或竞争。

## 16. 最终结论

1. [`f_00068C85()`](Sakura_hcb_ir/Sakura/f_00068C85.lua:1)对应 `$chara_move`，是单立绘槽位的成对/四图元运动调度器。
2. 它有 9 个真实参数：`slot, dx, dy, z, rotation, time, motion_type, wait, preflight`。
3. `dx/dy` 是相对位移增量；`z/rotation` 是绝对目标值。
4. `time`是 XY、Z、旋转三类 motion 的共同持续时间；普通单位为 ms。
5. `motion_type`默认 `3`，控制 easing；`wait=1` 时同步等待运动完成；`preflight`默认 `1`，控制全局 UI/输入/舞台预处理。
6. 本函数不处理 alpha；最后三参数也没有 alpha 含义。
7. `$chara_move` 与 `$chara_disp` 的职责不同：前者针对单槽位提交局部移动/Z/旋转，后者针对全体待处理立绘批量刷新颜色、alpha、显示、离场和 Parts 状态。
