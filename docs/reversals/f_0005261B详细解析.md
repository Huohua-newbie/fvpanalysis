# [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 详细解析

## 1. 核心结论

[`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 是 Sakura.hcb 中的一个**简化版全局 V3D 运动/状态重置函数**。

它的核心行为可以还原为：

```lua
function set_v3d_immediate(dst_x, dst_y, dst_z, aux_mode)
    G[310] = 0
    G[17] = true
    G[71] = 0

    if aux_mode == nil then
        aux_mode = 1
    end

    if dst_x == nil then dst_x = G[1176] end
    if dst_y == nil then dst_y = G[1177] end
    if dst_z == nil then dst_z = G[1178] end

    if G[1973] == true and aux_mode ~= 0 then
        f_00052882(dst_z, nil, nil)
    end

    V3DMotion(dst_x, dst_y, dst_z, 1, 1, nil)

    G[1176] = dst_x
    G[1177] = dst_y
    G[1178] = dst_z
    G[17] = nil
end
```

最准确的功能标签是：

> **将全局 V3D 坐标以 1 ms、Linear 类型快速推进到目标值，并同步更新坐标缓存与辅助层状态的简化入口。**

它不是 [`V3DMotionStop()`](../syscalls/31_V3D.md:237)，因为它并不停止当前 motion；它会调用 [`V3DMotion()`](../syscalls/31_V3D.md:108) 启动一条新的、持续时间为 `1` 的 V3D motion。

在实际视觉效果上，`duration=1` 通常接近“立即设置/立即收束到目标坐标”，所以它常被用于：

- 场景初始化；
- 镜头状态复位；
- 背景加载后的 V3D 坐标同步；
- 标题/菜单进入前的舞台基线建立；
- [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) 的重入短路路径。

## 4. 参数编号勘误

函数序言为：

```text
init_stack args=4 locals=0
```

因此它只有 4 个真实入参。

但导出器显示的函数头为 `a0,a1,a2,a3`，函数体读取到了 `a4`。这仍然是 Lua-like 导出器参数名称整体右移的问题。

正确映射是：

| 真实参数 | 原始负栈槽 | 导出器旧名称 | 推荐名称 |
|---|---:|---|---|
| `P0` | `-5` | `a1` | 目标 V3D X |
| `P1` | `-4` | `a2` | 目标 V3D Y |
| `P2` | `-3` | `a3` | 目标 V3D Z |
| `P3` | `-2` | `a4` | 辅助层处理模式 |

相关问题见 [`HCB Lua-like参数编号偏移错误说明.md`](HCB%20Lua-like参数编号偏移错误说明.md:1)。

所以导出代码中的：

```lua
S0 = a1
S1 = a2
S2 = a3
S3 = 1
S4 = 1
S5 = nil
```

实际应理解为：

```lua
V3DMotion(P0, P1, P2, 1, 1, nil)
```

## 5. 第一阶段：重置状态标志

函数开头执行：

```lua
G[310] = 0
G[17] = true
G[71] = 0
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:5-10)。

### 5.1 `G[310] = 0`

`G[310]` 与完整函数 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:5-16) 的短路逻辑有关：

```lua
if G[310] == 1 then
    G[310] = 0
    f_0005261B(...)
    return
end
```

因此 `f_0005261B()` 自己首先清除 `G[310]`，防止后续再次进入同一短路状态。

可以将 `G[310]` 理解为：

> **V3D 运动初始化/重入保护状态。**

它不是坐标值，也不是运动时长。

### 5.2 `G[17] = true`

`G[17]` 表示当前正在执行一轮 V3D/场景运动处理：

```text
进入函数 -> G[17] = true
执行 V3DMotion
更新坐标缓存
函数结束 -> G[17] = nil
```

它在本函数中是临时活动标志。

### 5.3 `G[71] = 0`

`G[71]` 会被辅助层函数 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 读取和更新。这里先清零，说明每次快速 V3D 状态重置都要重新建立 prim 187 辅助层的相关 alpha/状态基准。

因此：

```text
G[71] = 0
```

属于辅助图层/过渡状态复位，而不是 V3D 坐标本身。

## 6. 第二阶段：`P3` 的默认值和辅助层开关

函数对第 4 个真实参数执行：

```lua
if P3 == nil then
    P3 = 1
end
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:11-17)。

随后使用：

```lua
if G[1973] == true and P3 ~= 0 then
    f_00052882(P2, nil, nil)
end
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:42-56)。

### 6.1 `P3` 的推荐含义

`P3` 控制是否执行背景辅助层 prim 187 的同步处理：

| `P3` | 行为 |
|---:|---|
| `nil` | 默认变为 `1`，允许处理辅助层 |
| `0` | 跳过 `f_00052882()` |
| 非 `0` | 在 `G[1973]==true` 时调用 `f_00052882()` |

因此 `P3` 应命名为：

```text
aux_layer_mode
```

或：

```text
process_aux_layer
```

不应命名为 V3D motion type，因为真正的 motion type 在后面固定为 `1`。

### 6.2 `G[1973]` 的作用

只有当：

```lua
G[1973] == true
```

时，辅助层处理才可能执行。已有背景加载分析表明，`G[1973]` 与背景的 b/模糊/辅助差分层有关，相关说明见 [`BGimageLoading函数共性总结.md`](BGimageLoading函数共性总结.md:258-354)。

因此本函数的辅助层路径是：

```text
背景辅助层功能已启用
    + P3 != 0
    -> f_00052882(P2, nil, nil)
```

### 6.3 `f_00052882(P2,nil,nil)` 的含义

[`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 在第三参数为 `nil` 时，会直接对 prim 187 执行 alpha 设置，而不是启动复杂的 alpha motion。

因此在本函数中，辅助层处理更接近：

> **根据新的 V3D Z 目标值，对 prim 187 的辅助透明度状态做一次快速同步。**

它不会像完整 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:192-206) 那样传入完整的运动时长和附加参数。

## 7. 第三阶段：使用缓存补齐 V3D 坐标

函数分别检查 `P0/P1/P2`：

```lua
if P0 == nil then
    P0 = G[1176]
end

if P1 == nil then
    P1 = G[1177]
end

if P2 == nil then
    P2 = G[1178]
end
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:18-41)。

因此：

| 参数 | 缺省来源 |
|---|---|
| `P0` | `G[1176]` |
| `P1` | `G[1177]` |
| `P2` | `G[1178]` |

这些全局槽保存上一次提交的 V3D 目标坐标。

例如：

```lua
f_0005261B(nil, nil, 300, nil)
```

如果缓存为：

```text
G[1176] = 0
G[1177] = 200
```

则实际目标变为：

```text
(0, 200, 300)
```

注意：这里使用的是脚本层缓存，而不是直接查询 V3D motion 容器当前插值坐标。

## 8. 第四阶段：固定参数的 `V3DMotion`

函数执行：

```lua
V3DMotion(P0, P1, P2, 1, 1, nil)
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:57-64)。

六个参数含义：

| 参数 | 值 | 含义 |
|---|---|---|
| `dst_x` | `P0` | 全局 V3D 目标 X |
| `dst_y` | `P1` | 全局 V3D 目标 Y |
| `dst_z` | `P2` | 全局 V3D 目标 Z |
| `duration` | `1` | 1 ms |
| `type` | `1` | Linear |
| `reverse` | `nil` | 不启用 reverse |

根据 [`31_V3D.md`](../syscalls/31_V3D.md:108-188)：

- duration 单位是毫秒；
- type `1` 是 Linear；
- reverse 为 `nil` 表示关闭；
- V3DMotion 是异步 motion 接口，但 1 ms 通常接近立即完成。

### 8.1 它不是 `V3DSet`

虽然视觉上可能接近立即设置，但它调用的是：

```lua
V3DMotion(..., 1, 1, nil)
```

而不是：

```lua
V3DSet(P0, P1, P2)
```

区别是：

| 函数 | 行为 |
|---|---|
| `V3DSet` | 直接写入当前 V3D 坐标，不创建 motion |
| `f_0005261B` | 创建 1 ms Linear V3D motion，推进到目标坐标 |
| `f_000526A3` | 创建可配置时长/类型的 V3D motion，并可等待 |

因此更准确的命名是“快速 V3D motion”，而不是“V3D 直接设置”。

### 8.2 为什么使用 1 ms

在 FVP 的脚本体系中，`duration=1` 常用于表达：

```text
不要进行可见的长时间过渡
尽快把状态收束到目标值
```

它仍保留了 motion 系统的调用路径，使后续 `V3DMotionTest()` 等状态查询能够按照统一机制工作。

## 9. 第五阶段：更新目标坐标缓存

启动 motion 后，函数执行：

```lua
G[1176] = P0
G[1177] = P1
G[1178] = P2
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:65-70)。

这一步保存的是本次提交的目标坐标：

```text
G[1176] = 最近一次目标 X
G[1177] = 最近一次目标 Y
G[1178] = 最近一次目标 Z
```

后续再次使用 `nil` 坐标时，会从这些槽中补齐。

### 9.1 与 `f_000526A3()` 的缓存关系

完整函数 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:231-236) 也会更新相同的三个槽位。

所以二者共享同一套 V3D 目标缓存：

```text
f_0005261B -> 更新 G[1176..1178]
f_000526A3 -> 更新 G[1176..1178]
```

这意味着两个函数可以互相衔接：

```lua
f_0005261B(0, 200, 300, nil)
f_000526A3(nil, nil, 350, 900, ...)
```

第二次调用可以继承：

```text
X = 0
Y = 200
Z = 350
```

## 10. 第六阶段：清除活动标志

函数最后执行：

```lua
G[17] = nil
return
```

对应 [`f_0005261B.lua`](Sakura_hcb_ir/Sakura/f_0005261B.lua:71-73)。

这表明该函数不会等待 1 ms motion 的完成，而是：

```text
设置活动标志
 -> 提交快速 motion
 -> 更新缓存
 -> 立即清除活动标志
 -> 返回
```

因此它的调用方不能依靠函数返回时 `V3DMotionTest()` 已经绝对为假；只是由于 duration 为 1，通常很快会在后续帧完成。

## 12. 与 `f_000526A3()` 的关系

### 12.1 `f_000526A3()` 的短路调用

完整函数入口：

```lua
if G[310] == 1 then
    G[310] = 0
    f_0005261B(P0, P1, P2, P8)

end
```

见 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:5-17)。

这说明 `f_0005261B()` 是完整 V3D 控制器在某种重入/初始化状态下的简化替代路径。

### 12.2 两者对比

| 特征 | `f_0005261B` | `f_000526A3` |
|---|---|---|
| 参数数量 | 4 | 12 |
| V3D duration | 固定 1 | 可配置并经过修正 |
| V3D type | 固定 1 | 默认 3，可配置 |
| reverse | 固定 nil | 可传入 |
| 辅助 prim 187 | 可选快速处理 | 可选完整处理 |
| UI/场景刷新 | 无完整链 | 有 `f_00037F11`、`f_0004A5DE` 等链 |
| 等待 motion | 不等待 | `P6==1` 时等待 |
| 主要定位 | 快速复位/同步 | 完整 V3D 演出控制 |

因此：

> `f_0005261B` 是“快速收束版”，`f_000526A3` 是“完整可配置版”。

## 13. 与 `f_000525B7()` 的区别

[`f_000525B7()`](Sakura_hcb_ir/Sakura/f_000525B7.lua:1) 的第一条有效操作是：

```lua
V3DMotionStop()
```

之后再执行 `V3DSet()`。

因此两者不能混淆：

| 函数 | 机制 |
|---|---|
| [`f_000525B7()`](Sakura_hcb_ir/Sakura/f_000525B7.lua:1) | 先停止当前 V3D motion，再直接 `V3DSet` |
| [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) | 不显式 Stop，直接提交 1 ms Linear `V3DMotion` |
| [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) | 提交完整可配置 V3DMotion，可选等待 |

如果当前存在尚未完成的 V3D motion：

- `f_000525B7` 更接近强制停止并直接设置；
- `f_0005261B` 会用新的 1 ms motion 覆盖/替代当前运动；
- `f_000526A3` 会按完整运动流程建立新的 motion。

## 14. 典型调用样本

### 14.1 标题/演出初始化

例如 [`f_00074DA5()`](Sakura_hcb_ir/Sakura/f_00074DA5.lua:1) 中的调用形式：

```lua
f_0005261B(nil, nil, nil, nil)
```

语义是：

```text
使用上一次缓存的 V3D 目标坐标
辅助层模式默认 1
以 1 ms Linear motion 快速同步到该坐标
```

### 14.2 背景/场景初始化

常见形式：

```lua
f_0005261B(0, 0, 600, nil)
```

语义是：

```text
V3D 目标 = (0, 0, 600)
辅助层处理开启
快速推进到新的全局三维位置
```

### 14.3 跳过辅助层

```lua
f_0005261B(0, 0, 600, 0)
```

语义是：

```text
V3D 目标 = (0, 0, 600)
不调用 f_00052882
仍然执行 V3DMotion(0,0,600,1,1,nil)
```

### 14.4 [`f_0005074C()`](Sakura_hcb_ir/Sakura/f_0005074C.lua:123-124) 中的调用

背景 prim 186 初始化完成后，会调用类似：

```lua
f_0005261B(0, 0, -300, nil)
```

这说明背景加载函数会在设置图片 prim 后，同步设置全局 V3D 状态，使背景在预期的三维投影位置呈现。

这里 `-300` 是全局 V3D Z 目标，而不是 prim 186 的 `PrimSetZ` 值。

## 15. 语义化伪代码

```lua
function quick_v3d_motion(dst_x, dst_y, dst_z, aux_mode)
    -- 清除完整控制器的重入/初始化状态
    G[310] = 0

    -- 标记本轮 V3D 状态处理开始
    G[17] = true

    -- 清除辅助 prim 187 的中间状态
    G[71] = 0

    -- 第四参数默认允许辅助层处理
    if aux_mode == nil then
        aux_mode = 1
    end

    -- 使用上一次的目标坐标补齐 nil
    if dst_x == nil then dst_x = G[1176] end
    if dst_y == nil then dst_y = G[1177] end
    if dst_z == nil then dst_z = G[1178] end

    -- 背景辅助层快速同步
    if G[1973] == true and aux_mode ~= 0 then
        f_00052882(dst_z, nil, nil)
    end

    -- 1 ms Linear V3D motion，视觉上近似立即完成
    V3DMotion(dst_x, dst_y, dst_z, 1, 1, nil)

    -- 保存最近目标坐标
    G[1176] = dst_x
    G[1177] = dst_y
    G[1178] = dst_z

    -- 结束本轮状态处理
    G[17] = nil
end
```

## 16. 对新场景注入的建议

### 16.1 需要快速设置 V3D 坐标

可以使用：

```lua
f_0005261B(x, y, z, nil)
```

这会保留原作的：

- 全局状态标志；
- 坐标缓存；
- 辅助层同步；
- V3D motion 调用路径。

### 16.2 需要真正停止当前 V3D motion

应使用：

```lua
f_000525B7(...)
```

因为它明确调用 [`V3DMotionStop()`](../syscalls/31_V3D.md:237)，而 `f_0005261B()` 不会显式停止当前 motion。

### 16.3 需要可见的镜头移动

应使用：

```lua
f_000526A3(...)
```

因为它允许配置：

- 目标坐标；
- 实际时长；
- easing 类型；
- reverse；
- 是否等待；
- UI/辅助层同步模式。

### 16.4 新场景的最小复位序列

若希望在新场景开始前快速建立 V3D 基线，可以采用：

```lua
f_0005261B(0, 0, 0, nil)
```

如果背景辅助层不应参与：

```lua
f_0005261B(0, 0, 0, 0)
```

但是否应使用 `(0,0,0)`，必须根据现有场景缓存和 prim 投影配置决定；盲目清零可能使背景突然改变大小或投影位置。

## 17. 最终结论

1. [`f_0005261B()`](Sakura_hcb_ir/Sakura/f_0005261B.lua:1) 是简化版全局 V3D motion 入口。
2. 它有 4 个真实参数：目标 X、目标 Y、目标 Z、辅助层模式。
3. 导出器中出现的 `a4` 是唯一真实的第 4 参数，不是隐藏的第 5 参数。
4. 第 4 参数为 `nil` 时默认取 `1`。
5. 第 4 参数为 `0` 时跳过 prim 187 的辅助层快速处理。
6. `P0/P1/P2` 为 `nil` 时分别从 `G[1176]、G[1177]、G[1178]` 补齐。
7. 它会清除 `G[310]`，设置 `G[17]=true`，清零 `G[71]`。
8. 在 `G[1973]==true && P3!=0` 时调用 [`f_00052882()`](Sakura_hcb_ir/Sakura/f_00052882.lua:1) 快速同步辅助层。
9. 核心调用固定为：

   ```lua
   V3DMotion(P0, P1, P2, 1, 1, nil)
   ```

10. duration 固定为 `1 ms`，motion type 固定为 `1`，即 Linear，reverse 固定关闭。
11. 它不显式调用 `V3DMotionStop()`，因此不是严格意义上的“停止函数”。
12. 它会把最终目标坐标保存到 `G[1176..1178]`。
13. 它不会等待 motion 完成，而是提交后立即清除 `G[17]` 并返回。
14. 它是 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) 在特殊重入/初始化状态下使用的快速替代路径。
15. 与 [`f_000525B7()`](Sakura_hcb_ir/Sakura/f_000525B7.lua:1) 相比，它是“1 ms motion 快速收束”，而不是“Stop 后 V3DSet”。

最准确的一句话概括是：

> **`f_0005261B(dst_x,dst_y,dst_z,aux_mode)` 负责将全局 V3D 状态快速推进到目标坐标，并同步更新坐标缓存和可选的背景辅助层；它是快速复位/同步入口，而不是显式停止函数。**
