# [`f_0009C12E()`](Sakura_hcb_ir/Sakura/f_0009C12E.lua:1)：`$cut_in type=002` 的 cut-in 演出函数解析

## 1. 结论先说

[`f_0009C12E()`](Sakura_hcb_ir/Sakura/f_0009C12E.lua:1) 是一段针对特定 cut-in 类型的具体演出函数。它的核心特征是固定操作 prim `480`，并在入场路径中加载资源：

```text
prim 480
resource = cut_e002_10
```

它不是立绘显示函数，也不是 `$cut_in` 的总分派器，而是：

> **`$cut_in #type="002"` 对应的 cut-in 资源/图元演出 worker；其唯一显式参数主要承担该 cut-in 的阶段控制。**

从原作调用关系看：

```text
$cut_in #type="002" #param="1"
    ↓
f_0009C12E(1)
    ↓
准备 cut_e002_10 到 prim 480
    ↓
alpha 从 0 运动到 255
    ↓
prim 480 沿 Y 方向移动 50
```

随后：

```text
$cut_in #type="002" #param="0"
    ↓
f_0009C12E(0)
    ↓
alpha 立即/快速归零
```

因此，用户发现的对应关系基本成立：

```text
[macro name="$cut_in" #type="002" #param="1"]
        ≈ f_0009C12E(1)
```

但 `#type="002"` 与 `#param="1"` 是两层不同参数：

- `type=002`：选择哪一类 cut-in worker；
- `param=1/2/0/-1`：控制该 worker 的阶段、入场方案或结束方案。

## 3. `cutin_param=1`：进入 cut-in 显示路径

函数第一分支判断：

```lua
if cutin_param == 1 then
    ...
end
```

此路径执行以下步骤。

### 3.1 资源准备：prim 480 加载 `cut_e002_10`

```lua
f_000373A5(480, "cut_e002_10", 6, nil)
```

[`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1)继续调用资源绑定/装载相关函数，因此可以确定：

- 目标 prim 是 `480`；
- 资源 basename 是 `cut_e002_10`；
- `6` 是资源/图像类别或装载模式参数，不是本函数的 `cutin_param`；
- 这是 cut-in 图像，而不是角色立绘资源。

### 3.2 初始透明度

```lua
PrimSetAlpha(480, 0)
```

这说明该 cut-in 在正式出现前先被设置为完全透明。

### 3.3 图元尺寸/中心点设置

```lua
PrimSetOP(480, 1280 / 2, 720 / 2)
```

计算结果为：

```text
PrimSetOP(480, 640, 360)
```

这里的 `PrimSetOP` 参数应理解为 prim 的 OP/中心/基准位置设置；从数值看，它使用了 `1280×720` 画布的中心点 `640,360`。

这说明 cut-in 图像按全屏画布中心作为显示基准。

### 3.4 Alpha motion：0 → 255

```lua
f_000520EE(480, 0, 255, 475, nil, nil, nil, nil)
```

结合 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 的参数转发关系，其核心效果是：

```text
prim 480
alpha: 0 → 255
duration: 475 ms
```

所以 `param=1` 会使 cut-in 在约 475 ms 内淡入。

### 3.5 XY motion：向 Y 方向移动 50

```lua
f_000523A8(480, nil, 50, nil, 0, 475, 3, nil, nil)
```

[`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:1)最终调用 [`MotionMove()`](../../syscall语义数据库/syscall含义详解/18_Motion.md:216)。其有效参数可概括为：

```text
prim       = 480
src_x/src_y = 当前值
目标偏移    = X 不变，Y +50
时长        = 475 ms
motion type = 3
```

这里的 `nil` 坐标参数表示沿用当前 prim 坐标，`50` 是 Y 方向目标/偏移相关参数。

因此 `param=1` 的整体视觉效果可描述为：

> **加载 `cut_e002_10`，将其放在画面中心附近，从透明状态淡入，同时进行约 475 ms 的 Y 方向移动。**

## 4. `cutin_param=2`：第二种进入路径

第二分支判断：

```lua
if cutin_param == 2 then
    ...
end
```

其资源和 prim 设置与 `param=1` 基本相同：

```lua
f_000373A5(480, "cut_e002_10", 6, nil)
PrimSetAlpha(480, 0)
PrimSetOP(480, 640, 360)
```

区别在于 motion 时长：

```lua
f_000520EE(480, 0, 255, 600, nil, nil, nil, nil)
f_000523A8(480, nil, 50, nil, 0, 600, 3, nil, nil)
```

因此：

| 参数 | alpha 淡入时长 | XY motion 时长 |
|---:|---:|---:|
| `1` | `475 ms` | `475 ms` |
| `2` | `600 ms` | `600 ms` |

`param=1` 和 `param=2`不是两个不同资源，而是同一 cut-in 资源的两种演出速度/阶段方案。

当前从函数本体可以高置信度确认：

> `1` 与 `2` 的直接差异是入场运动/淡入持续时间不同；两者都使用 `cut_e002_10`、prim 480、alpha 0→255、Y 方向 50 的运动。

如果实机视觉上二者还有其他差异，可能来自调用前的全局状态或调用后的上层 `effect/wait`，并非函数本体中资源或目标坐标的差异。

## 5. `cutin_param=0`：结束/隐藏路径

第三条分支：

```lua
if cutin_param == 0 then
    ...
end
```

它不重新加载资源，也不调用 `f_000373A5()`，而是：

```lua
f_0004A5DE(nil, nil, nil, nil)
PrimSetAlpha(480, 255, 0, 500, nil, nil, nil, nil)
```

### 5.1 前置状态处理

[`f_0004A5DE()`](Sakura_hcb_ir/Sakura/f_0004A5DE.lua:1) 会进入[`f_0004A608()`](Sakura_hcb_ir/Sakura/f_0004A608.lua:1)，并查询 `InputGetState`。它不是 cut-in 图像本身的运动，而是演出/UI/输入状态的前置协调。

### 5.2 Alpha motion：255 → 0

```lua
f_000520EE(480, 255, 0, 500, nil, nil, nil, nil)
```

因此 `param=0` 的主要作用是：

> **让当前 cut-in prim 480 在约 500 ms 内淡出隐藏。**

它不是立即释放资源的路径；函数本身没有 `GraphLoad(nil)`、`PrimSetNull` 或 `PrimGroupOut`。资源回收若存在，应由后续清理函数或其他状态链负责。

## 6. 其他参数：清理路径

如果参数既不是 `1`、`2`，也不是 `0`，函数执行：

```lua
f_0006A76F(nil)
```

[`f_0006A76F()`](Sakura_hcb_ir/Sakura/f_0006A76F.lua:1) 是更大范围的 cut-in/过渡图元清理器：

- 当参数归一化为 `0` 时，遍历 prim `480..492`；
- 对这些 prim 执行 `MotionMoveStop`、`MotionMoveZStop`、`MotionMoveRStop`、`MotionMoveS2Stop`；
- 调用[`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1)进行资源/图元清理；
- 在另一种状态下，至少遍历 `480..488` 做运动停止。

因此未知参数不是另一个正常 cut-in 类型，而是落入兜底清理逻辑。

注意：[`f_0006A76F()`](Sakura_hcb_ir/Sakura/f_0006A76F.lua:1)的 `nil` 参数会在内部默认成 `1`，所以本函数的未知值路径最终通常是“停止现有 cut-in 动作并回收相关图层”。

## 7. 与相邻函数的关系

### 7.1 [`f_0009C089()`](Sakura_hcb_ir/Sakura/f_0009C089.lua:1)：相邻 `type=001`

该函数结构与 [`f_0009C12E()`](Sakura_hcb_ir/Sakura/f_0009C12E.lua:1)几乎平行：

```text
param=1
  → 加载 cut_e001_10
  → prim 480 alpha 0
  → alpha 0→255
  → XY motion

param=0
  → 前置状态处理
  → alpha 255→0

其他
  → f_0006A76F(nil)
```

但它的入场 motion 时长为 `650 ms`，资源名是 `cut_e001_10`。

这证明 `f_0009C12E()`不是通用 cut-in 总函数，而是一个按资源编号分组的具体 worker。

### 7.2 [`f_0009C23D()`](Sakura_hcb_ir/Sakura/f_0009C23D.lua:1)：相邻 `type=003`

对应资源：

```text
cut_e003_10
```

其入场路径同样使用 prim 480、alpha 0→255、Y 方向 50，但时长为 `650 ms`；结束路径使用 alpha 255→0、`550 ms`。

由此可以推断：

```text
f_0009C089  ≈ cut-in type 001
f_0009C12E  ≈ cut-in type 002
f_0009C23D  ≈ cut-in type 003
```

这是高可信的地址/资源/调用结构对应关系。

## 8. `$cut_in` 的 `type` 与 `param` 分工

原作 KS 中出现：

```ks
[macro name="$cut_in" #type="002" #param="1"]
[macro name="$cut_in" #type="002" #param="2"]
[macro name="$cut_in" #type="002" #param="0"]
```

例如：

- [`common_01.ks`](../../reference/SakuraMoyu_NS/common_01.ks:3168)：`type=002,param=1`；
- [`common_02.ks`](../../reference/SakuraMoyu_NS/common_02.ks:1846)：`type=002,param=2`；
- [`common_02.ks`](../../reference/SakuraMoyu_NS/common_02.ks:1852)：`type=002,param=0`。

应区分：

| KS 参数 | 作用 |
|---|---|
| `type="002"` | 选择 cut-in 资源/worker 类型；对应 `cut_e002_10` 与 [`f_0009C12E()`](Sakura_hcb_ir/Sakura/f_0009C12E.lua:1) |
| `param="1"` | 方案 1：475 ms 淡入 + Y 方向 50 motion |
| `param="2"` | 方案 2：600 ms 淡入 + Y 方向 50 motion |
| `param="0"` | 结束：500 ms alpha 255→0 |
| 其他/特殊值 | 进入 [`f_0006A76F()`](Sakura_hcb_ir/Sakura/f_0006A76F.lua:1) 等清理路径，具体取决于上层分派 |

所以不能写成：

```text
cut_in(param)
```

而应理解为：

```text
cut_in(type, param)
  → 根据 type 选择 f_0009Cxxx worker
  → worker 根据 param 选择入场/结束方案
```

## 9. `f_0009C12E(1)` 的具体调用效果

等价伪代码：

```lua
function CutInType002(param)
    if param == 1 then
        PrepareGraph(480, "cut_e002_10", 6)
        PrimSetAlpha(480, 0)
        PrimSetOP(480, 640, 360)
        MotionAlpha(480, 0, 255, 475, ...)
        MotionMove(480, current_x, current_y,
                   current_x, current_y + 50,
                   475, 3, ...)
        return
    end

    if param == 2 then
        PrepareGraph(480, "cut_e002_10", 6)
        PrimSetAlpha(480, 0)
        PrimSetOP(480, 640, 360)
        MotionAlpha(480, 0, 255, 600, ...)
        MotionMove(480, current_x, current_y,
                   current_x, current_y + 50,
                   600, 3, ...)
        return
    end

    if param == 0 then
        PreflightCutInState()
        MotionAlpha(480, 255, 0, 500, ...)
        return
    end

    CutInCleanup()
end
```

这说明 `f_0009C12E(1)`不是“显示一个立绘”，而是：

> **在固定 prim 480 上播放 `cut_e002_10` cut-in 图像，并以淡入 + Y 方向移动的方式进入画面。**

## 10. 与外层 effect/wait 的关系

KS 中 `cut-in` 后面经常还有：

```ks
[effect time="..."]
[wait time="..."]
```

这些不应直接归因于[`f_0009C12E()`](Sakura_hcb_ir/Sakura/f_0009C12E.lua:1)。函数本体只负责：

- 资源绑定；
- 初始 alpha/OP；
- 启动 alpha motion；
- 启动 XY motion；
- 或结束 alpha motion。

真正的全屏 effect、等待、音效同步和后续场景推进由外层剧情函数负责。

因此，`f_0009C12E()`的返回并不必然意味着 cut-in 已经完成；它通常只是提交运动记录，后续由引擎帧更新或外层等待推进。

## 11. 推荐调用方式

### 11.1 播放 type 002 cut-in

```lua
f_0009C12E(1)
```

效果：加载 `cut_e002_10`，使用 prim 480，475 ms 淡入并向 Y 方向移动 50。

### 11.2 使用较慢入场方案

```lua
f_0009C12E(2)
```

效果：同一资源与运动方向，时长改为 600 ms。

### 11.3 结束当前 type 002 cut-in

```lua
f_0009C12E(0)
```

效果：prim 480 alpha 从 255 向 0 过渡，时长约 500 ms。

### 11.4 清理路径

不建议直接把任意未知数值传入；未知值会落入 cut-in 清理路径，可能停止/清理 `480..492` 等一组图层。

## 12. 最终结论

1. [`f_0009C12E()`](Sakura_hcb_ir/Sakura/f_0009C12E.lua:1)是 `$cut_in type=002` 的具体演出 worker。
2. 它固定操作 prim `480`，入场资源为 `cut_e002_10`。
3. `param=1`：alpha `0→255`，475 ms；同时启动 Y 方向 50 的 XY motion，475 ms。
4. `param=2`：同一资源和方向，但 alpha/XY motion 时长为 600 ms。
5. `param=0`：不重新加载资源，使 prim 480 alpha `255→0`，约 500 ms。
6. 其他参数：进入[`f_0006A76F()`](Sakura_hcb_ir/Sakura/f_0006A76F.lua:1)等清理逻辑。
7. `type`选择 cut-in 类型，`param`选择该类型的入场/结束方案；两者不可混为一个参数。
8. 该函数操作的是 cut-in 全屏/覆盖图元，不是角色立绘；与 `$chara_disp`、`$chara_move` 属于不同演出系统。
