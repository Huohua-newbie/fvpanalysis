# [`f_0004B21B()`](Sakura_hcb_ir/Sakura/f_0004B21B.lua:1) 逐条反汇编与作用分析

## 1. 函数定位与总体结论

- 原始函数：[`f_0004B21B.lua`](Sakura_hcb_ir/Sakura/f_0004B21B.lua:1)
- HCB：[`Sakura.hcb`](../../03_data/hcb_samples/Sakura.hcb)
- IR：[`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json)
- 函数地址范围：`0x0004B21B–0x0004B23B`
- HCB 文件偏移：`307739–307771`
- 字节长度：`33` 字节
- 函数序言：`init_stack args=2, locals=0`
- 显式入参数量：`2`
- 局部变量数量：`0`
- 直接调用的内部函数：无
- 直接调用的 syscall：无

本函数是一个很薄的**存档元数据与系统 UI 类别状态设置器**。它不创建窗口、不装载图片，也不直接调用存档 syscall；它只负责把两个可选入参分别写入两个全局槽：

```text
第 1 个入参 a0 -> G[1257]
第 2 个入参 a1 -> G[1256]
```

写入条件是“参数非 `nil`”。如果参数为 `nil`，对应的全局槽保持原值不变。

结合下游引用，可以得到比“文本窗口相关全局状态”更具体的结论：

- `G[1256]` 会在 [`f_0003793C()`](Sakura_hcb_ir/Sakura/f_0003793C.lua:11) 和 [`f_00037A7C()`](Sakura_hcb_ir/Sakura/f_00037A7C.lua:7) 中作为 [`SaveCreate()`](../syscalls/22_Save.md:85) 的第二个参数使用；在 `fnid = 0` 分支下，它对应存档标题/作品标题元数据。
- `G[1257]` 会在 [`f_00071272()`](Sakura_hcb_ir/Sakura/f_00071272.lua:298) 中被比较为 `0、1、2、...、17`，并据此选择 `sys_cap_000`–`sys_cap_017` 图片，绑定到 prim `171`，因此它是系统 UI/功能类别图标的选择编号。

综合而言，本函数更适合命名为：

> **存档标题与系统 UI 类别状态设置函数。**

## 3. 调用者分析

### 3.1 [`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:7)

调用序列为：

```lua
S0 = 1
S0 = -S0
S1 = "　"
__ret = f_0004B21B(S0, S1)
```

因此实际调用为：

```lua
f_0004B21B(-1, "　")
```

产生的全局状态是：

```lua
G[1257] = -1
G[1256] = "　"
```

这里的两个值分别有不同用途：

- `-1` 不是 `f_00071272()` 中列出的 `0..17` 系统 UI 图标类别，因此更像“无特殊系统 UI 类别/默认类别”标志；
- 全角空格 `"　"` 很可能是存档标题显示时使用的占位标题、空白标题或默认标题值。

这说明该调用并不是简单的普通文本窗口初始化，而是在进入剧情场景前，给存档和系统 UI 相关状态设置默认值。

## 4. 下游追踪：`G[1256]`

### 4.1 [`f_0003793C()`](Sakura_hcb_ir/Sakura/f_0003793C.lua:1)

该函数在循环中执行：

```lua
S0 = 0
S1 = G[1256]
__ret = __syscall("SaveCreate", S0, S1)
```

对应 syscall：

```text
SaveCreate(0, G[1256])
```

根据 [`SaveCreate()`](../syscalls/22_Save.md:85) 的已知参数语义：

- 第 1 参数 `fnid = 0`：设置存档标题；
- 第 2 参数 `value`：标题字符串。

因此这条链可以还原为：

```text
f_0004B21B(a0, a1)
    -> if a1 ~= nil then G[1256] = a1 end
    -> f_0003793C()
    -> SaveCreate(0, G[1256])
    -> 设置当前存档标题
```

### 4.2 `G[1256]` 的实际用途

在当前证据下，`G[1256]` 至少不是“普通对话文本槽”：

- 它没有在 [`f_0004B21B()`](Sakura_hcb_ir/Sakura/f_0004B21B.lua:1) 中直接进入 Text syscall；
- 它被存档准备函数读取；
- 它被作为 `SaveCreate` 的标题值使用。

所以目前应将 `G[1256]` 命名为：

> **当前存档标题/存档显示标题缓存。**

“作品标题”与“当前场景标题”在 FVP 的 SaveCreate 多路复用中是不同 `fnid`，这里使用的是 `fnid = 0`，所以更接近作品/游戏标题，而不是场景标题。

## 5. 下游追踪：`G[1257]`

### 5.1 [`f_00071272()`](Sakura_hcb_ir/Sakura/f_00071272.lua:298)

该函数先准备 prim `171`，然后读取 `G[1257]`：

```lua
S0 = G[1257]
S1 = 0
S0 = (S0 == S1)
```

随后按值选择资源：

| `G[1257]` | 资源名 | 目标 prim |
|---:|---|---:|
| `0` | `sys_cap_000` | `171` |
| `1` | `sys_cap_001` | `171` |
| `2` | `sys_cap_002` | `171` |
| `...` | `...` | `171` |
| `17` | `sys_cap_017` | `171` |

每个分支都调用类似：

```lua
f_000373A5(171, "sys_cap_000", nil, nil)
```

随后统一执行：

```lua
PrimSetAlpha(171, 0)
PrimSetOP(171, nil, 56)
f_00037476(171, 18)
```

这里可以继续追到 syscall 层：

- [`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1) 负责图像资源装载，最终会涉及 `GraphLoad`/prim 绑定链；
- `PrimSetAlpha(171, 0)` 把该系统图标初始设为完全透明；
- `PrimSetOP(171, nil, 56)` 设置图元操作属性；
- [`f_00037476()`](Sakura_hcb_ir/Sakura/f_00037476.lua:1) 将 prim `171` 纳入指定组。

因此，`G[1257]` 的功能可以高置信度描述为：

> **决定系统 UI 中 prim 171 应装载哪一张 `sys_cap_NNN` 类功能图标的类别编号。**

### 5.2 `-1` 的含义

[`f_000A2981()`](Sakura_hcb_ir/Sakura/f_000A2981.lua:7) 传入 `-1`。而 [`f_00071272()`](Sakura_hcb_ir/Sakura/f_00071272.lua:298) 的已见分支覆盖 `0..17`，没有 `-1` 分支。

因此有两种可能：

1. `-1` 表示“不显示任何 `sys_cap` 图标”，函数最终不进入资源选择分支；
2. `-1` 是一个默认/未选择状态，其他函数在显示系统 UI 前会改写为 `0..17`。

从 [`f_00071272()`](Sakura_hcb_ir/Sakura/f_00071272.lua:500) 的统一收尾看，它最终还会将 prim `171` 设为 alpha `0`，因此“`-1` 表示不显示特殊系统图标”是目前较合理的解释，但仍建议通过运行时观察确认。

## 7. 等价伪代码

```lua
function f_0004B21B(a0, a1)
    if a0 ~= nil then
        G[1257] = a0
    end

    if a1 ~= nil then
        G[1256] = a1
    end
end
```

调用示例：

```lua
f_0004B21B(-1, "　")
```

等价于：

```lua
G[1257] = -1
G[1256] = "　"
```

但如果参数为 `nil`：

```lua

```

则只会执行：

```lua

```

`G[1257]` 保持原值。

## 8. 最终作用判断

### 高置信度结论

1. [`f_0004B21B()`](Sakura_hcb_ir/Sakura/f_0004B21B.lua:1) 是无下游调用的叶子函数。
2. 它有两个显式入参，且两个参数均采用“非 `nil` 才写入”的策略。
3. 第一个参数 `a0` 写入 `G[1257]`。
4. 第二个参数 `a1` 写入 `G[1256]`。
5. `G[1256]` 下游进入 `SaveCreate(0, G[1256])`，属于存档标题/作品标题元数据链。
6. `G[1257]` 下游决定 `sys_cap_000`–`sys_cap_017` 的系统 UI 图标选择。

### 中等置信度结论

- `a0` 是系统 UI/功能类别编号；原作剧情入口使用 `-1`，很可能代表不选择特殊系统图标。
- `a1` 是存档标题缓存；原作传入全角空格，可能用于保持默认空白标题或避免标题字段为空。

### 尚待验证

- `G[1256]` 的 `fnid=0` 在 Sakura 中最终呈现为何种存档标题文本；
- `G[1257] = -1` 是否会在某处被转换为默认类别，还是始终表示隐藏系统图标；
- `sys_cap_000`–`sys_cap_017` 各编号具体对应哪个系统功能。

## 9. 后续验证建议

1. 统计 `f_0004B21B()` 的全部非 `-1` 调用，确认 `G[1257]` 是否在剧情中被设置为 `0..17`。
2. 跟踪 [`f_00071272()`](Sakura_hcb_ir/Sakura/f_00071272.lua:298) 的完整调用者，确认其显示时机和 UI 入口。
3. 在存档流程中记录 `SaveCreate(0, G[1256])` 的实际标题展示结果，确认全角空格的用户可见效果。
4. 对 `G[1257]` 分别设置 `-1、0、1、17`，观察 prim `171` 是否显示、显示哪张 `sys_cap_NNN` 资源。

> 综上，原先“文本窗口相关全局状态或属性设置包装函数”的判断过于宽泛。更准确的名称是：**存档标题与系统 UI 类别状态设置函数**。
