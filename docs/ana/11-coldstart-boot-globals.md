# 11 · 冷启动与 boot 全局量：CG 门案（`global1950`）

> **前置阅读**：[03 · VM 与指令集](./03-vm-and-opcodes.md)
>
> 置信度：**[已验证]**——`--set-global 1950 0` 前后对照，`graph_vis/*` 从 0 次加载变为全系加载；回放终态 `diffs=0`。

## 1. 症状

从场景函数直接冷启动（`--entry-pc`），剧本台词、音效、BG、立绘、motion 全对，但**事件 CG（`graph_vis/*`）一次都不加载**，对应行全黑。而真机同一句台词配整张 CG。

## 2. 定位过程（略写，详见 [13 · 方法篇](./13-methods-calltrace-stack.md)）

`calltrace` 证实 CG 加载链 `9611 → 332832 → 333826 → 334016 → 225940` 前两跳执行了，第三跳之后无声返回。用 `--break-pc` 二分到 `332832` 内的变体选择树，发现它读启动全局量做路由。

## 3. 根因：`global1950` 的四连判等

`332832` 在进入卸载/加载主体前检查（伪码，还原自字节码）：

```text
if global[1950]==0 or global[1950]==1 or global[1950]==2 or global[1950]==3:
    → 继续（CG 变体选择）
else:
    → jmp 333779（直接返回，CG 永不加载）
```

- 冷启动：`Global` 未初始化位全是 **`Nil`**（`init_with` 填 `Nil`），四个判等全灭 → 死路。
- 真机 boot/title 流程会把它置成 `Int`（0~3 之一，含义待考，疑似与画质/演出等级相关）→ 正常继续。

修复（采样用）：`--set-global 1950 0`。注意是“门”不是“值语义”——0~3 任意都行，关键是从 Nil 变成 Int。

## 4. 同类：前缀选择器 `global8`

`225940`（动态路径组装 `prefix + name → GraphLoad`）按 `global8` 选前缀：

| `global8` | 前缀 |
|---|---|
| `1` | `graph_vish/`（HD，**注意不是 `graph_vis/`**，包不一定存在） |
| `2` | `graph_sd/` |
| 其它（含 Nil/0） | `graph_vis/`（默认） |

冷启动保持默认恰好是对的（`graph_vis.bin` 存在）；若有人预置 `global8=1` 反而会加载失败。这个“默认即正确、新人别手贱”的坑值得单独记一笔。

## 5. 一般教训：冷启动状态差清单

| 类别 | 例子 | 症状 | 补法 |
|---|---|---|---|
| 守卫全局量 | `global[1]==True`（场景函数入口） | 函数直接 `ret`，零 syscall | `--set-global 1 true`（注意是 `True` 不是 `Int(1)`，`set_e` 按 variant 判等） |
| 路由全局量 | `global[1950]`（CG 变体门） | 链条走一半返回 | `--set-global 1950 0` |
| 标志全局量 | `global[103/2111]`（章节路由） | 进错场景 | 按分发链预置 |
| 帧时钟 | timer/input/motion/dissolve | 等待永不到期（见 [10](./10-motion-interp-semantics.md) §2） | 每 tick 手动推进 |

另：`set_e`/`set_ne` 跨 variant 一律不等（`Int(1) != True`，`Nil != 0`），冷启动读到的 Nil 在任何相等判断里都是“否”，在不等判断里都是“是”——这是推演分支走向时的第一性原理。
