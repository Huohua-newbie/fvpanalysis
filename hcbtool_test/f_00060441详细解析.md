# [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 详细解析

## 1. 函数定位

- 原始函数地址：`0x00060441`
- IR/Lua-like 文件：[`f_00060441.lua`](Sakura_hcb_ir/Sakura/f_00060441.lua:1)
- 函数序言：`init_stack args=4, locals=0`
- 直接调用：
  - [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)
  - [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1)
- 直接 syscall：无

当前可以将它命名为：

> **立绘/部件运动批量刷新入口，兼带刷新后异步状态收束。**

它不是一个直接执行单个 `MotionAlpha` 或 `MotionMove` 的底层 syscall 包装器，而是一个很薄的二级调度入口：先把部分参数交给大型立绘运动控制器 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)，再调用 [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 对当前立绘槽位的 alpha motion 状态进行统一检查和必要的后续刷新。

function f_00060441(a0, a1, a2, a3)

  S1 = a2
  S2 = a3

对应的逐条行为只有两步：

2. 以这三个值调用 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)，随后无条件调用 [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1)。

函数没有条件跳转、循环、返回值处理或直接图元操作。

## 3. 参数映射：`a0` 当前没有被使用

### 3.1 不能按“声明了四个参数”推断四个参数都有作用

Lua-like 导出结果把函数显示成：

```lua
function f_00060441(a0, a1, a2, a3)
```

但函数主体只读取：

```lua
S0 = a1
S1 = a2
S2 = a3
```

没有任何 `a0` 的读取、比较、写回或转发。因此在当前反编译结果和原始控制流一致的前提下：

| 导出参数 | 是否被本函数读取 | 当前结论 |
|---|---:|---|
| `a0` | 否 | 未使用/保留槽位；不能据此赋予业务含义 |
| `a1` | 是 | 转发给 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 的第 1 个参数 |
| `a2` | 是 | 转发给 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 的第 2 个参数 |
| `a3` | 是 | 转发给 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 的第 3 个参数 |

因此更可靠的抽象写法是：

```lua
function f_00060441(_unused, p1, p2, p3)
    f_00060795(p1, p2, p3)
    f_00066CB2()
end
```

这里的 `_unused` 只是分析命名，不应直接写回 HCB；HCB 仍然保持原有四参数栈布局。

### 3.2 与调用点的对应关系

常见调用形式如下：

```lua

```

例如在 [`f_0004770E()`](Sakura_hcb_ir/Sakura/f_0004770E.lua:1) 中可以看到：

```lua

S1 = nil
S2 = nil
S3 = nil

```

按本函数的真实读取关系，实际传给 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 的是：

```lua

```

前面的 `1` 落在 `a0`，在 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 内部被丢弃。因此不能把这个 `1` 解释为立绘运动类型、alpha 方向或等待开关。

同理，在 [`f_00055D3D()`](Sakura_hcb_ir/Sakura/f_00055D3D.lua:1) 的调用路径中，看到的调用参数也必须先经过这一层的参数筛选，不能直接把四个调用实参全部当成 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 的输入。

## 4. 下游一：[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)

### 4.1 入口参数的直接归一化

[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 是一个大型立绘/部件运动控制器。它首先对几个全局状态做检查，然后在正式进入运动逻辑前处理三个入口参数。

从其开头可确认：

- 第 1 个参数写入或参与计算 `G[1173]`；
- 第 2 个参数写入或参与计算 `G[1174]`；
- 第 3 个参数缺省时会回填为 `150`，并继续作为本轮控制参数使用；
- 函数还会根据 `G[1986]`、`G[1949]` 以及 `G[250]` 对前两个数值做比例修正或强制压缩。

关键片段的语义可整理为：

```lua
if p1 == nil then
    G[1173] = default_or_derived_value
else
    G[1173] = p1
end

if p2 == nil then
    G[1174] = 200
else
    G[1174] = p2
end

if p3 == nil then
    p3 = 150
end
```

这里的 `G[1173]`、`G[1174]` 不是 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 自己解释的，而是 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 内部的运动/alpha 参数缓存。

### 4.2 主要操作对象是成组立绘槽位

[`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 在后半段反复读取：

- `G[946]`
- `G[948]`
- `G[950]`
- ……
- `G[994]`

这些全局槽位被用作立绘或部件 prim 的基准编号。对于每个槽位，函数会组合执行：

- `MotionAlpha`
- `MotionAlphaStop`
- `MotionMove`
- `MotionMoveZ`

例如在 `G[988]` 和 `G[990]` 对应的分支中，可以看到运动目标坐标、Z 坐标以及 `1500` 时长被分别送入 `MotionMove` 和 `MotionMoveZ`。这说明 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 的职责不是单纯设置一对全局参数，而是根据角色/部件状态对整组立绘对象进行批量刷新。

### 4.3 `G[1173]` 的控制性质

[`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 会读取 `G[1173]`，并在 `G[1173] >= 2` 等条件下进入 alpha motion 检查循环。因此 `G[1173]` 至少承担以下一类控制作用：

> **当前立绘批处理的模式/阶段/有效范围控制值。**

它不能简单命名为“alpha 时长”，因为在 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 中，它还影响多个部件运动分支和若干强制归一化路径。其精确业务名称仍需要结合更多调用样本和实机画面确认。

### 4.4 `G[1174]` 的控制性质

`G[1174]` 在 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 中有独立的默认值 `200`，并可能根据特殊状态按 `2/3` 比例修正。它与 `G[1173]` 同时构成一组运动/alpha 控制缓存。

当前更稳妥的命名是：

> **立绘批处理的第二个时序或阶段控制参数。**

不宜在缺乏实机验证时直接断言为“透明度”“延迟”或“动画速度”。

## 5. 下游二：[`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1)

### 5.1 它不是简单的无条件等待

[`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 的入口首先检查：

```lua
if G[26] == 0 then
    return
end
```

因此 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 虽然无条件调用它，但 [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 自己会根据全局状态决定是否真正工作。

### 5.2 alpha motion 检查范围

在进入工作路径后，[`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 依次对以下全局槽位指定的 prim 执行 `MotionAlphaTest`：

```text
G[946], G[948], G[950], ..., G[994]
```

这些测试结果被合并为“是否仍有任意 alpha motion 正在进行”。如果仍在运动，并且 `G[1173] > 1`，函数会：

1. 设置 `G[90] = true`；
2. 调用 [`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1) 让出一帧；
3. 回到 alpha motion 检查点继续轮询。

这是一种典型的异步动画推进结构：`MotionAlphaTest` 只负责查询，真正让动画向前推进的是帧让渡 [`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1)。

### 5.3 完成后的统一状态重建

当 alpha motion 检查结束后，[`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 会把 `G[311]..G[334]` 中仍处于初始值 `1` 的槽位推进到 `2`，并继续执行大量 `PrimSetNull`、`PartsLoad`、`GraphLoad`、`MotionAlphaStop` 和 `MotionMoveStop` 操作。

因此它不应只命名为“等待 alpha 完成”。更完整的描述是：

> **立绘批量 alpha motion 的同步检查、槽位阶段推进与部件资源/运动状态重建函数。**

[`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 调用它的意义，是在 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 提交或刷新一批立绘运动后，立即触发一次统一的后处理。

## 6. 调用链中的位置

### 6.1 普通立绘/界面路径

部分界面或演出函数会采用如下结构：

```text
设置角色/部件状态
    ↓
调用 f_00060441(...)
    ↓
调用 f_00060795(p1, p2, p3)
    ↓
刷新多个立绘 prim 的 alpha / XY / Z motion
    ↓
调用 f_00066CB2()
    ↓
检查批量 alpha motion，并推进部件槽位状态
```

例如 [`f_0004770E()`](Sakura_hcb_ir/Sakura/f_0004770E.lua:1) 在若干界面切换分支中会先清理或显示一组 prim，再调用 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1)，随后继续处理过渡层和其它演出对象。这种位置关系与“立绘批处理刷新入口”的解释一致。

### 6.2 dissolve 路径中的位置

[`f_0005599D()`](Sakura_hcb_ir/Sakura/f_0005599D.lua:1) 在设置 `prim 190/191` alpha 后，必要时也会调用 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1)。这说明 dissolve 过程并不只操作全局 mask 或 `prim 190/191`，还可能需要同步刷新立绘/部件系统。

在 [`f_00055D3D()`](Sakura_hcb_ir/Sakura/f_00055D3D.lua:1) 中，`f_00060441` 位于转场分支的状态收束位置。这里它更像：

> **转场过程中立绘 alpha 状态与部件显示状态的附加同步器。**

但它本身不是 dissolve 执行器；真正的 dissolve 逻辑仍在 [`f_00055D3D()`](Sakura_hcb_ir/Sakura/f_00055D3D.lua:1) 的 mask 选择、`Dissolve` 调用和等待分支中。

## 9. 结论与待验证项

### 9.1 已确认结论

1. [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 没有直接 syscall。
2. 它只把 `a1`、`a2`、`a3` 转发给 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1)。
3. `a0` 在本函数中没有任何读取，是未使用/保留参数槽位。
4. [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 是实际的多立绘/部件运动控制核心。
5. [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 是运动后的批量 alpha 状态检查与部件槽位后处理函数。
6. [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 因此属于“运动提交 + 状态收束”的薄包装器。

### 9.2 尚待验证项

1. `G[1173]` 的正式业务名称：当前只能确定它是批处理阶段/模式控制量，不能直接等同于时长或 alpha。
2. `G[1174]` 的正式业务名称：当前只能确定它是与 `G[1173]` 配套的第二控制量。
3. `G[1173]`、`G[1174]` 的具体数值如何改变实机中的立绘进入、退出、缩放或透明度效果。
4. `G[946]..G[994]` 每个槽位分别对应哪一个角色、部件或立绘层。
5. [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 在不同 `G[1173]`、`G[1221]` 和 `G[26]` 组合下，究竟是等待当前 alpha 动画，还是启动下一批部件状态重建。

## 10. 对后续 Sakura 分析的建议

后续遇到 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 的调用时，建议采用以下记录格式：

```text
调用方：f_xxxxxxxx
四个实参：A0, A1, A2, A3
实际转发：f_00060795(A1, A2, A3)
A0：当前忽略
随后：f_00066CB2()
```

这样可以避免两个常见误判：

- 把 `a0` 错当成实际运动参数；
- 把 [`f_00060441()`](Sakura_hcb_ir/Sakura/f_00060441.lua:1) 本身误认为直接执行 dissolve 或单个 prim alpha 的函数。

当前最值得继续深入的是 [`f_00060795()`](Sakura_hcb_ir/Sakura/f_00060795.lua:1) 中 `G[1173]`、`G[1174]` 与 `G[863]..G[886]` 等 alpha/坐标缓存之间的对应关系，以及 [`f_00066CB2()`](Sakura_hcb_ir/Sakura/f_00066CB2.lua:1) 对 `G[311]..G[334]` 的阶段推进是否对应具体的立绘显示层切换。
