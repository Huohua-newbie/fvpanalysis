# [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 逐条反汇编与详细解析

## 1. 核心结论

[`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 是一个**固定播放/切换 BGM 编号 3 的包装函数**。

它本身只有两项有效操作：

```lua
G[2030] = true
f_0005511C(3, nil, nil, P1, nil)
```

其中 `P1` 是 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 的唯一真实入参，经参数转发后成为 [`f_0005511C()`](Sakura_hcb_test/Sakura_hcb_ir/Sakura.lua:171632) 的第 4 个真实参数，并最终作为 `AudioVol` 的音量值使用。

所以推荐的等价表示是：

```lua
function f_00036514(volume)
    G[2030] = true
    f_0005511C(
        3,       -- BGM 编号固定为 3
        nil,     -- 使用默认切换等待参数
        nil,     -- 使用普通播放模式
        volume,  -- 音量；nil 时由下游默认 100
        nil      -- 使用 BGM/目录，而不是 BGM2/
    )
end
```

最准确的功能标签是：

> **BGM 3 播放/切换包装器，并设置 BGM 相关全局状态。**

如果调用 `f_00036514(nil)`，则下游默认音量为 `100`。

## 3. 参数槽位说明

导出函数头为：

```lua
function f_00036514(a0)
```

但函数体读取的是导出变量 `a1`，对应原始唯一参数栈槽 `-2`。因此使用 `P1` 表示真实入参：

| 真实参数 | 原始栈槽 | 导出中名称 | 作用 |
|---|---:|---|---|
| `P1` | `-2` | `a1` | 传给 `f_0005511C()` 的第 4 个真实参数；实际为音量值，nil 时默认 100 |

重要区别：

- 固定的音乐编号 `3` 不是 `P1`；
- `P1` 不是 BGM 编号；
- `P1` 也不是播放时长；
- `P1` 最终进入下游 `AudioVol(channel, P1, nil)`。

## 5. 第一条业务指令：设置 `G[2030]`

```lua
G[2030] = true
```

该状态写入发生在调用 [`f_0005511C()`](Sakura_hcb_ir/Sakura.lua:171632) 之前。

在 [`f_000452A0()`](Sakura_hcb_ir/Sakura/f_000452A0.lua:1) 中可以看到它被读取：

```lua
S2 = G[2030]
```

这说明 `G[2030]` 是音乐/场景状态的一部分，而不是临时无关变量。

但仅凭 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 本身，尚不能把它严格命名为“BGM 已播放”或“BGM 类型”。高置信度只能说：

> `G[2030]=true` 是调用固定 BGM 3 播放流程时同步建立的一个场景/音乐状态标志。

## 6. 第二项业务：固定调用 `f_0005511C(3,nil,nil,P1,nil)`

[`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 的核心转发为：

```lua
f_0005511C(3, nil, nil, P1, nil)
```

需要结合 [`f_0005511C()`](Sakura_hcb_ir/Sakura.lua:171632) 的真实参数槽解释：

| `f_0005511C()` 真实参数 | 传入值 | 作用 |
|---|---|---|
| 第 1 参数 | `3` | BGM 编号，参与路径 `BGM/003` 的构造 |
| 第 2 参数 | `nil` | 等待/旧通道停止时长参数；nil 时默认约 `1000`，随后转为旧通道停止时长 `2000` |
| 第 3 参数 | `nil` | 播放模式；nil 走普通 `AudioPlay(channel,nil)` 路径 |
| 第 4 参数 | `P1` | 音量；nil 时默认 `100` |
| 第 5 参数 | `nil` | 资源目录选择；nil/非 `2` 时使用 `BGM/` |

因此本函数的参数不是“选择播放哪一首 BGM”，而是：

> **固定切换到 BGM 编号 3，唯一外部可调的是音量。**

## 7. 下游 `f_0005511C()` 的 BGM 处理流程

### 7.1 音乐编号状态比较

下游首先比较：

```lua
if G[215] == track_id then
    return
end
G[215] = track_id
```

见 [`Sakura.lua`](Sakura_hcb_ir/Sakura.lua:171644-171651)。

这意味着：

- `G[215]` 保存当前已记录的 BGM 编号；
- 如果当前已经是编号 `3`，再次调用 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 可能直接返回；
- 如果不是编号 `3`，才继续切换流程。

所以 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 不是无条件重复播放，而是受当前 BGM 编号状态抑制重复切换。

### 7.2 构造 BGM 路径

下游根据第 5 参数选择目录：

```lua
if directory_mode ~= 2 then
    path_prefix = "BGM/"
else
    path_prefix = "BGM2/"
end

path = path_prefix .. IntToText(track_id, 3)
```

本函数固定传入第 5 参数 `nil`，因此进入：

```text
BGM/ + 三位格式的编号 3
```

即逻辑上接近：

```text
BGM/003
```

实际文件扩展名和资源解析由引擎音频层完成。

### 7.3 音频通道交替

下游根据 `G[213]` 选择新的音频通道：

```lua
if G[213] == 0 then
    G[213] = 1
    G[214] = 0
else
    G[213] = 0
    G[214] = 1
end
```

这表明 BGM 切换采用双通道交替机制：

- `G[213]`：本次新 BGM 使用的通道；
- `G[214]`：上一条 BGM 所在的旧通道。

这样做可以让新旧 BGM 在切换期间分别存在于不同通道，便于停止旧通道、建立新通道。

### 7.4 停止、设类型、加载和播放

新通道依次执行：

```lua
AudioStop(new_channel, 100)
AudioType(new_channel, 1)
AudioLoad(new_channel, "BGM/003")
AudioVol(new_channel, volume, nil)
AudioPlay(new_channel, nil)
```

对应 [`Sakura.lua`](Sakura_hcb_ir/Sakura.lua:171686-171724)。

其中：

- `AudioType(...,1)`：设置 BGM 类音频类型；
- `AudioLoad`：加载编号 3 的 BGM 资源；
- `AudioVol`：使用本函数唯一参数决定音量；
- `AudioPlay(...,nil)`：本函数固定的第 3 参数为 nil，因此走普通播放模式。

### 7.5 停止旧音频通道

本函数把下游第 2 参数固定为 `nil`。下游将其默认化为 `1000`，再调用：

```lua
f_00055202(1000)
```

[`f_00055202()`](Sakura_hcb_ir/Sakura/f_00055202.lua:1) 把时长加 `1000` 后停止旧通道：

```lua
AudioStop(G[214], 2000)
```

因此一次固定 BGM 3 切换的大致流程是：

```text
新通道停止旧内容
→ 加载 BGM/003
→ 设置音量
→ 播放新 BGM
→ 约 2000 ms 后停止旧通道
```

这里的 `2000` 是旧通道停止时序参数，不是 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 的外部参数。

## 8. 唯一入参 `P1` 的实际含义

### 8.1 `P1 == nil`

在 [`f_0005511C()`](Sakura_hcb_ir/Sakura.lua:171632) 的入口：

```lua
if volume == nil then
    volume = 100
end
```

因此：

```lua
f_00036514(nil)
```

等价于固定以音量 `100` 播放/切换 BGM 3。

这是当前剧情代码中最常见的调用形式，例如：

```lua
f_00036514(nil)
f_0004CEFD("学園に到着。", ...)
```

### 8.2 `P1` 为数值

如果传入 `0..100` 范围内的数值，则该值会直接进入：

```lua
AudioVol(new_channel, P1, nil)
```

因此可用于指定 BGM 音量。

调用者样本中经常看到：

```lua
f_00036514(nil)
```

而调用后的 `0、1、12、14、100...` 等数字通常是后续剧情函数的参数或局部赋值，不应误认为是 `f_00036514()` 的参数。判断时必须只看调用前压入的那个值。

### 8.3 P1 不是 BGM 编号

BGM 编号在本函数内被固定压入：

```lua
push_i8 3
```

所以：

```lua
f_00036514(7)
```

并不是播放 BGM 7，而是尝试播放 BGM 3、音量设为 7。

## 9. 与同族包装函数的关系

从总反编译文件可以看到一系列结构相同的包装器：

```lua
function f_00036500(volume)
    G[2029] = true
    f_0005511C(2, nil, nil, volume, nil)
end

function f_00036514(volume)
    G[2030] = true
    f_0005511C(3, nil, nil, volume, nil)
end

function f_00036528(volume)
    G[2031] = true
    f_0005511C(4, nil, nil, volume, nil)
end

function f_0003653C(volume)
    G[2032] = true
    f_0005511C(5, nil, nil, volume, nil)
end
```

这些函数的差异主要是：

1. 设置的全局状态槽不同：`G[2029]`、`G[2030]`、`G[2031]`……；
2. 固定传给 [`f_0005511C()`](Sakura_hcb_ir/Sakura.lua:171632) 的音乐编号不同：`2`、`3`、`4`、`5`……。

因此 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 明确属于“按 BGM 编号拆开的便捷入口”。

## 11. 完整伪代码

### 11.1 [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 本体

```lua
function f_00036514(P1)
    G[2030] = true
    f_0005511C(3, nil, nil, P1, nil)
end
```

### 11.2 结合下游后的近似语义

```lua
function play_bgm_3(volume)
    if volume == nil then
        volume = 100
    end

    G[2030] = true

    -- 如果当前已经记录为 BGM 3，切换函数可能直接返回
    if G[215] == 3 then
        return
    end

    G[215] = 3

    local new_channel
    local old_channel
    if G[213] == 0 then
        new_channel = 1
        old_channel = 0
    else
        new_channel = 0
        old_channel = 1
    end
    G[213] = new_channel
    G[214] = old_channel

    AudioStop(new_channel, 100)
    AudioType(new_channel, 1)
    AudioLoad(new_channel, "BGM/003")
    AudioVol(new_channel, volume, nil)
    AudioPlay(new_channel, nil)

    -- 第 2 参数为 nil，下游默认约 1000，再加 1000
    AudioStop(old_channel, 2000)
end
```

这里的 `AudioStop(old_channel,2000)` 是对下游流程的近似表达；实际音频切换由 [`f_0005511C()`](Sakura_hcb_ir/Sakura.lua:171632) 和 [`f_00055202()`](Sakura_hcb_ir/Sakura.lua:171748) 协同完成。

## 12. 最终结论

1. [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 只有一个真实参数。
2. 它固定将 BGM 编号 `3` 传给 [`f_0005511C()`](Sakura_hcb_ir/Sakura.lua:171632)。
3. 它的唯一参数不是音乐编号，而是下游 `AudioVol` 使用的音量参数。
4. 参数为 `nil` 时，下游默认音量为 `100`。
5. 第 5 个下游参数固定为 `nil`，因此使用 `BGM/` 目录，而不是 `BGM2/`。
6. 第 2 个下游参数固定为 `nil`，因此切换时采用默认的旧通道停止时序。
7. 第 3 个下游参数固定为 `nil`，因此使用普通 `AudioPlay` 路径。
8. 函数先设置 `G[2030]=true`，该标志与 BGM/场景状态相关，具体业务名称仍需继续追踪其读取点。
9. [`f_00036514()`](Sakura_hcb_ir/Sakura/f_00036514.lua:1) 与 [`f_00036500()`](Sakura_hcb_ir/Sakura/f_00036500.lua:1)、[`f_00036528()`](Sakura_hcb_ir/Sakura/f_00036528.lua:1) 等共同构成按音乐编号拆分的快捷播放入口。

最准确的功能标签是：

> **固定 BGM 3 的播放/切换函数；唯一入参为音量，nil 时使用默认音量 100。**
