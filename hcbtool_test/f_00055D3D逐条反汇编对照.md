# `f_00055D3D()` 逐条反汇编与参数分析

> 本文根据原始 [`Sakura.hcb`](Sakura.hcb)、IR 指令表 [`Sakura.ir.json`](Sakura_hcb_ir/Sakura.ir.json) 与拆分结果 [`f_00055D3D.lua`](Sakura_hcb_ir/Sakura/f_00055D3D.lua) 编写。地址是 HCB 代码区/文件内偏移；原始字节来自 HCB 同一偏移。

## 1. 函数边界与总体结论

> **参数编号勘误**：本文件初版沿用了 Lua-like 导出器的错误参数名。转换器 [`slot_name()`](../hcb可逆转换/hcb_ir_core.py:560) 曾把 `push_stack -N` 映射为从 `a1` 开始的参数名，实际应从 `a0` 开始。下文已按真实 VM 槽位修正；逐条字节码中的负索引才是最终可靠依据。

- 函数范围：`0x00055D3D–0x0005673E`；下一函数 [`f_0005673F()`](Sakura_hcb_ir/Sakura/f_0005673F.lua:1) 从 `0x0005673F` 开始。
- HCB 文件偏移：`351549–354110`；函数字节长度 `2562`，IR 指令数 `729`。
- 入口先设置 `G[118] = true`、`G[23] = true`，随后根据全局状态和入参选择两类路径：
  1. **已有 alpha/过渡状态路径**：驱动 `prim 190/191` 的 alpha 动画，轮询 `MotionAlphaTest`，必要时每帧 `ThreadNext`。
  2. **新 dissolve 路径**：把数值转场编号映射到 `graph/diss00`–`graph/diss55` mask，调用 `Dissolve`，再按参数等待或进行约 200 ms 的非阻塞等待。
- 因此，本函数不是单纯的“淡出函数”，而是 **Sakura 的通用全屏转场调度器**：负责准备转场状态、选择 mask、启动 dissolve、等待/让出执行权并清理状态。

## 6. 结论与验证建议

1. 该函数的核心职责可以高置信度命名为：**通用全屏 dissolve/mask 转场执行器**。它同时兼容旧的 `prim 190/191` alpha 过渡状态，并负责真正启动 mask dissolve。
2. 修正后的关键参数是：`a0 = mask 编号`、`a1 = 时长 ms`、`a4 = mask dissolve 模式存在性开关`。
