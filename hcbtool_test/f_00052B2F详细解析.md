# [`f_00052B2F()`](Sakura_hcb_ir/Sakura/f_00052B2F.lua:1) 详细解析

## 1. 核心结论

[`f_00052B2F()`](Sakura_hcb_ir/Sakura/f_00052B2F.lua:1) 是 Sakura.hcb 中的**多 prim 舞台抖动演出调度器**。

它本身主要负责：

1. 接收 7 个演出参数；
2. 将参数缓存到 `G[1179]..G[1185]`；
3. 根据 `G[22]` 决定启动后台线程还是直接执行；
4. 等待 worker [`f_00052B90()`](Sakura_hcb_ir/Sakura/f_00052B90.lua:1) 完成。

真正的图元动画逻辑在 [`f_00052B90()`](Sakura_hcb_ir/Sakura/f_00052B90.lua:1) 中。该 worker 会对以下 6 个 prim 执行成组 [`MotionMove`](../syscall语义数据库/syscall含义详解/18_Motion.md:214)：

```text
767、768、769、773、777、776
```

这些图元会按照指定方向和幅度快速平移，循环若干次并逐步减弱，最后统一恢复到 `(0,0)`。因此它适合实现：

- 舞台震动；
- 屏幕抖动；
- 列车、爆炸、撞击等冲击效果；
- 物体突然晃动；
- 角色或场景辅助图层的同步偏移。

最准确的功能标签是：

> **支持多方向、多幅度、多轮渐弱和线程等待的六 prim 舞台抖动控制器。**

它不是全局 V3D 镜头运动函数，也不是单个图元的普通移动包装器。

## 3. `f_00052B2F()` 本体

原始反编译主体如下：

```lua
function f_00052B2F(a0, a1, a2, a3, a4, a5, a6)
  -- init_stack args=7 locals=0
  G[1179] = a1
  G[1180] = a2
  G[1181] = a3
  G[1182] = a4
  G[1183] = a5
  G[1184] = a6
  G[1185] = a7

  if G[22] == 1 then
      ThreadStart(5, 338832)
  else
      f_00052B90()
  end

  while G[20] == 1 do
      ThreadNext()
  end

  G[22] = 1
end
```

对应 [`f_00052B2F.lua`](Sakura_hcb_ir/Sakura/f_00052B2F.lua:5-40)。

### 3.1 参数缓存

真实参数到全局槽的对应关系是：

```text
P0 -> G[1179]
P1 -> G[1180]
P2 -> G[1181]
P3 -> G[1182]
P4 -> G[1183]
P5 -> G[1184]
P6 -> G[1185]
```

这些槽主要承担“有参数的外层函数”向“无参数 worker”传递数据的作用。

### 3.2 `G[20]`

worker 开始时设置：

```lua
G[20] = 1
```

worker 完成时设置：

```lua
G[20] = 0
```

所以 `G[20]` 是明确的 worker 活动标志：

| 值 | 含义 |
|---:|---|
| `1` | 抖动 worker 仍在执行 |
| `0` | worker 已结束 |

外层函数通过 [`f_0003769F()`](Sakura_hcb_ir/Sakura/f_0003769F.lua:1) 调用 `ThreadNext`，逐帧等待 `G[20]` 变为 0。

### 3.3 `G[22]`

入口根据 `G[22]` 选择线程执行方式：

```lua
if G[22] == 1 then
    ThreadStart(5, 338832)
else
    f_00052B90()
end
```

函数结束时无条件执行：

```lua
G[22] = 1
```

因此它是一个线程调度/执行状态变量。当前可以确认其控制“后台线程启动或当前线程执行”的分支，但其更完整的业务名称尚未恢复。

| `P1` | `-7` | `a2` | `G[1180]` |
| `P2` | `-6` | `a3` | `G[1181]` |
| `P3` | `-5` | `a4` | `G[1182]` |
| `P4` | `-4` | `a5` | `G[1183]` |

相关说明见 [`HCB Lua-like参数编号偏移错误说明.md`](HCB%20Lua-like参数编号偏移错误说明.md:1)。

## 5. worker 的参数默认值

[`f_00052B90()`](Sakura_hcb_ir/Sakura/f_00052B90.lua:1) 开头把缓存槽读入局部变量：

```lua
l6  = G[1179]
l7  = G[1180]
l8  = G[1181]
l9  = G[1182]
l10 = G[1183]
l11 = G[1184]
l12 = G[1185]
```

随后进行默认值处理：

```lua
if l6 == nil then l6 = 4 end
if l7 == nil then l7 = 1 end
if l8 == nil then l8 = 0 end
if l9 == nil then l9 = true end
if l10 == nil then l10 = 1 end
if l11 == nil then l11 = 1 end
if l12 == nil then l12 = 20 end
```

推荐语义表：

| 参数 | 默认值 | 推荐含义 |
|---|---:|---|
| `P0` | `4` | 抖动循环上限；实际循环次数为 `P0+1` |
| `P1` | `1` | 方向/轴向组合模式，取 `0..3` |
| `P2` | `0` | 抖动幅度档位，取 `-1..3` |
| `P3` | `true` | 每轮结束后是否将幅度乘以 `3/4` |
| `P4` | `1` | 是否让 prim 767 参加运动 |
| `P5` | `1` | 是否让 prim 773、777、776 参加运动 |
| `P6` | `20` | 每轮 MotionMove 的时长，单位毫秒 |

`P4/P5` 的命名是根据 worker 中对 `l10/l11` 的判断位置得到的语义化命名，不一定是原脚本的正式符号名。

## 6. 六个目标 prim

worker 使用以下 prim：

```text
767、768、769、773、777、776
```

### 6.1 基本组

`768` 和 `769` 在主要运动路径中始终执行。

### 6.2 可选 prim 767

当：

```lua
P4 == 1
```

才对 prim 767 调用 [`MotionMove()`](../syscall语义数据库/syscall含义详解/18_Motion.md:214)。

### 6.3 可选附加组

当：

```lua
P5 == 1
```

才对 prim `773、777、776` 调用 `MotionMove`。

### 6.4 最终复位

无论哪些 prim 参与运动，结束时都会执行：

```lua
PrimSetXY(767, 0, 0)
PrimSetXY(768, 0, 0)
PrimSetXY(769, 0, 0)
PrimSetXY(777, 0, 0)
PrimSetXY(773, 0, 0)
PrimSetXY(776, 0, 0)
```

见 [`f_00052B90.lua`](Sakura_hcb_ir/Sakura/f_00052B90.lua:1014-1040)。

这说明抖动偏移是临时的：

```text
原位置 -> 临时偏移 -> 等待 -> XY=(0,0)
```

复位只改 XY，不清理 z、alpha、RS、纹理或 prim 资源。

## 7. `P1`：方向/轴向模式

worker 将 `P1` 映射为四种位移方向。

### 7.1 `P1 == 0`

```text
正向：(+A, nil)
反向：(-A, nil)
```

主要沿 X 轴运动。

### 7.2 `P1 == 1`

```text
正向：(nil, +A)
反向：(nil, -A)
```

主要沿 Y 轴运动。

### 7.3 `P1 == 2`

```text
正向：(+A, +A)
反向：(-A, -A)
```

形成一种对角线运动。

### 7.4 `P1 == 3`

```text
正向：(-A, +A)
反向：(+A, -A)
```

形成另一种对角线运动。

### 7.5 总表

| `P1` | 正向位移 | 反向位移 | 推荐解释 |
|---:|---|---|---|
| `0` | `(+A,0)` | `(-A,0)` | 水平抖动 |
| `1` | `(0,+A)` | `(0,-A)` | 垂直抖动 |
| `2` | `(+A,+A)` | `(-A,-A)` | 右下/左上对角抖动 |
| `3` | `(-A,+A)` | `(+A,-A)` | 左下/右上对角抖动 |

“正向”是脚本坐标系中的描述；实际屏幕方向仍要结合父节点和渲染坐标系判断。

## 8. `P2`：离散幅度档位

`P2` 不是直接的距离值，而是映射到实际位移幅度 `A` 的档位：

| `P2` | 实际幅度 `A` |
|---:|---:|
| `-1` | `16` |
| `0` | `32` |
| `1` | `64` |
| `2` | `96` |
| `3` | `164` |

因此推荐称为：

```text
shake_amplitude_level
```

而不是直接称为 `shake_distance`。

默认 `P2=0`，所以默认实际幅度为 `32`。

这些数值是 prim 局部 XY 位移量，不能与主舞台的全局 V3D z 或屏幕像素大小混淆。

---

## 9. `P3`：幅度渐弱

每轮运动完成后，如果 `P3` 为真，worker 执行：

```lua
A = A * 3 / 4
```

对应 [`f_00052B90.lua`](Sakura_hcb_ir/Sakura/f_00052B90.lua:938-967)。

例如初始幅度为 `64`：

| 轮次 | 幅度 |
|---:|---:|
| 第 1 轮 | 64 |
| 第 2 轮 | 48 |
| 第 3 轮 | 36 |
| 第 4 轮 | 27 |
| 第 5 轮 | 20 |

所以默认情况下，视觉效果是：

```text
强烈偏移 -> 较弱偏移 -> 更弱偏移 -> 停止
```

`P3` 不控制：

- 是否等待；
- 是否检测输入；
- 是否启动线程；
- MotionMove 的 easing 类型。

它只控制每轮后的幅度衰减。

## 10. `P4/P5`：目标 prim 组开关

### 10.1 `P4`

```lua
if P4 == 1 then
    MotionMove(767, ...)
end
```

| `P4` | 结果 |
|---:|---|
| `1` | prim 767 参加抖动 |
| 其它值 | 跳过 prim 767 |

### 10.2 `P5`

```lua
if P5 == 1 then
    MotionMove(773, ...)
    MotionMove(777, ...)
    MotionMove(776, ...)
end
```

| `P5` | 结果 |
|---:|---|
| `1` | prim 773、777、776 参加抖动 |
| 其它值 | 跳过这三个 prim |

两者默认都是 `1`，因此普通调用默认让全部 6 个 prim 参与。

## 11. `P6`：单轮运动时长

`P6` 被作为每次 `MotionMove` 的 duration：

```lua
MotionMove(id, nil, nil, dst_x, dst_y, P6, 3, nil)
```

根据 [`18_Motion.md`](../syscall语义数据库/syscall含义详解/18_Motion.md:73-89)，duration 单位为毫秒。

因此：

| `P6` | 含义 |
|---:|---|
| `20` | 每轮 20 ms，默认快速抖动 |
| `50` | 每轮 50 ms |
| `100` | 每轮 100 ms |
| `200` | 每轮 200 ms，偏移更明显 |

所有 MotionMove 调用固定使用类型 `3`，即当前 Motion 体系中的减速型插值；reverse 固定为 `nil`。

### 11.1 总时长

由于实际循环次数为 `P0+1`，理论总时长近似为：

```text
(P0 + 1) * P6
```

默认情况下：

```text
P0 = 4
P6 = 20 ms
实际循环次数 = 5
理论总时长 ≈ 100 ms
```

实际总时长还会受到帧调度、MotionMoveTest 和 ThreadNext 的影响。

## 12. 循环和等待

### 12.1 循环次数

worker 初始化：

```lua
l0 = 0
```

每轮结束：

```lua
l0 = l0 + 1
```

循环条件：

```lua
l0 <= P0
```

因此实际循环次数是：

```text
P0 + 1
```

| `P0` | 实际轮数 |
|---:|---:|
| `0` | 1 |
| `1` | 2 |
| `4` | 5 |
| `9` | 10 |

### 12.2 `MotionMoveTest`

worker 会检查参与运动的 prim：

```lua
MotionMoveTest(767)
MotionMoveTest(768)
MotionMoveTest(769)
MotionMoveTest(773)
MotionMoveTest(777)
MotionMoveTest(776)
```

结果按逻辑或合并：

```text
任意一个 prim 仍在运动 -> 继续等待
全部 prim 运动结束     -> 进入下一轮或最终收尾
```

### 12.3 `ThreadNext`

等待过程中调用：

```lua
f_0003769F()
```

它只是 [`ThreadNext`](../syscall语义数据库/syscall含义详解/27_Thread.md:1) 的包装器，用于让出当前帧，使引擎继续推进 MotionMove。

## 13. 输入跳过和全局门控

### 13.1 输入位 `1`

worker 在开始和每轮等待中都调用：

```lua
InputGetState()
```

并检查：

```lua
(input_state & 1) ~= 0
```

如果成立，跳过后续抖动循环。

### 13.2 `G[1964] == 1`

该状态也会跳过后续循环：

```lua
if G[1964] == 1 then
    goto final_wait
end
```

### 13.3 `G[1949] == 0 and G[250] == nil`

该组合状态会抑制继续提交抖动 MotionMove：

```lua
if G[1949] == 0 and G[250] == nil then
    goto final_wait
end
```

这些全局变量的正式业务名称尚未完全恢复，但可以确定它们用于特殊场景/过渡状态下的抖动抑制。

### 13.4 跳过不是立即强停

跳过后 worker 仍会进入最终等待：

```lua
while any_motion_is_running() do
    ThreadNext()
end
```

所以准确语义是：

```text
不再提交新的抖动轮次
但等待当前已经提交的运动结束
随后统一复位
```

不是立即将当前运动强制停止。

### 14.1 默认调用

```lua
f_00052B2F(nil, nil, nil, nil, nil, nil, nil)
```

按默认值展开：


这一类调用位于场景对象或动作描述附近，符合物体突然震动的用途。

## 15. 与相关函数的区别

### 15.1 与 [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1)

| 函数 | 操作对象 | 主要效果 |
|---|---|---|
| [`f_000526A3()`](Sakura_hcb_ir/Sakura/f_000526A3.lua:1) | 全局 V3D 状态 | 镜头/三维投影运动 |
| [`f_00052B2F()`](Sakura_hcb_ir/Sakura/f_00052B2F.lua:1) | 6 个固定 prim | 局部 XY 舞台抖动 |

前者调用 [`V3DMotion()`](../syscall语义数据库/syscall含义详解/31_V3D.md:108)，后者调用多个 [`MotionMove()`](../syscall语义数据库/syscall含义详解/18_Motion.md:214)。

### 15.2 与 [`f_000523A8()`](Sakura_hcb_ir/Sakura/f_000523A8.lua:1)

`f_000523A8` 更接近单个 prim 的 MotionMove 启动/等待包装器；`f_00052B2F` 则固定管理 6 个 prim，并额外实现循环、渐弱、方向和跳过逻辑。

### 15.3 与 [`f_0005423F()`](Sakura_hcb_ir/Sakura/f_0005423F.lua:1)

Sakura 中存在多组类似的线程 worker 模板：

```text
外层函数缓存参数
    -> ThreadStart 或直接执行 worker
    -> G[20] 等待
    -> worker 清理状态
```

`f_00052B2F` 的特殊之处在于它使用固定 prim 组和离散抖动参数。

## 16. 注入和复用建议

### 16.1 推荐直接调用入口

如果新剧情需要原作式舞台抖动，应直接复用：

```lua
f_00052B2F(P0, P1, P2, P3, P4, P5, P6)
```

不要只复制一条 MotionMove，因为入口还负责：

- 六个 prim 的同步；
- 多轮循环；
- 幅度渐弱；
- 输入跳过；
- 特殊全局状态抑制；
- 运动结束等待；
- XY 统一复位。

### 16.2 推荐参数范围

```text
P0 = 0..9
P1 = 0..3
P2 = -1..3
P3 = true 或 false/0
P4 = 0 或 1
P5 = 0 或 1
P6 = 10..300
```

### 16.3 复用前的前置条件

必须确认：

1. 目标 prim 已经创建；
2. 目标 prim 已加入正确父组；
3. 目标 prim 当前没有被其它 MotionMove 占用；
4. `G[20]` 和 `G[22]` 没有被其它并发演出错误复用；
5. 如果只想震动某个图层，应正确设置 `P4/P5`，而不是事后手动清理。

## 17. 最终结论

1. [`f_00052B2F()`](Sakura_hcb_ir/Sakura/f_00052B2F.lua:1) 是多 prim 舞台抖动演出的外层调度入口。
2. 它有 7 个真实入参，并通过 `G[1179]..G[1185]` 传给无参数 worker。
3. `P0` 控制循环上限，实际次数为 `P0+1`。
4. `P1` 控制四种方向/轴向组合模式。
5. `P2` 是离散幅度档位：`-1/0/1/2/3` 对应 `16/32/64/96/164`。
6. `P3` 控制每轮后是否按 `3/4` 比例减弱幅度。
7. `P4` 控制 prim 767 是否参与。
8. `P5` 控制 prim 773、777、776 是否参与。
9. `P6` 是每轮 MotionMove 的毫秒级时长，默认 20 ms。
10. worker 实际操作 prim `767/768/769/773/777/776`。
11. 运动类型固定为 `3`，reverse 固定为 `nil`。
12. worker 使用 `MotionMoveTest` 和 `ThreadNext` 等待每轮完成。
13. 输入位 `1`、`G[1964]==1` 或 `G[1949]==0 && G[250]==nil` 可以跳过后续抖动轮次。
14. 跳过通常不会强制停止当前已提交运动，而是等待其结束后统一复位。
15. 最终通过 `PrimSetXY(id,0,0)` 清除所有临时偏移。
16. 该函数主要控制 prim 局部 XY，不是全局 V3D z，也不是三维镜头推进。

> **一句话概括：`f_00052B2F` 负责把一组方向、幅度、循环和渐弱参数交给 worker，由 worker 对六个固定舞台 prim 执行可跳过、可等待、最终自动复位的局部 XY 抖动。**
