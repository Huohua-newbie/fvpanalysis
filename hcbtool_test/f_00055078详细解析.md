# [`f_00055078()`](Sakura_hcb_ir/Sakura/f_00055078.lua:1) 详细解析

## 1. 核心结论

[`f_00055078()`](Sakura_hcb_ir/Sakura/f_00055078.lua:1) 是 Sakura.hcb 中的一个**四路环境声统一刷新/初始化包装器**。

它自身不直接调用 Sound syscall，而是把同一个参数依次传给 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1)，分别处理环境声通道 `0、1、2、3`：

```lua
function refresh_environment_sound(value)
    if value == nil then
        value = 2000
    end

    f_00054EB1(nil, 0, value, 0, nil)
    f_00054EB1(nil, 1, value, 0, nil)
    f_00054EB1(nil, 2, value, 0, nil)
    f_00054EB1(nil, 3, value, 0, nil)
end
```

最准确的功能标签是：

> **将同一环境声控制参数同步应用到四路环境声通道的公共函数。**

它不是：

- BGM 播放函数；
- 单个音效播放函数；
- 单纯设置音量的函数；
- 单纯停止全部声音的函数。

其真正的通道资源选择、状态判断、SoundStop/SoundLoad/SoundVol/SoundPlay 操作，均由下游 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 完成。

## 4. 参数编号勘误

函数序言为：

```text
init_stack args=1 locals=0
```

所以它只有一个真实外部参数。

但导出器函数头显示 `a0`，函数体读取 `a1`。实际原始访问对应 `push_stack -2`，按照项目已有的 Lua-like 参数偏移勘误：

```text
push_stack -2 -> 唯一真实参数
```

因此本文使用 `P1` 或 `value` 表示该参数。

| 真实参数 | 原始栈槽 | 导出器旧名称 | 推荐名称 |
|---|---:|---|---|
| `P1` | `-2` | `a1` | `value` |

相关规则见 [`HCB Lua-like参数编号偏移错误说明.md`](HCB%20Lua-like参数编号偏移错误说明.md:1)。

## 5. 默认值：`nil -> 2000`

函数入口执行：

```lua
if value == nil then
    value = 2000
end
```

对应 [`f_00055078.lua`](Sakura_hcb_ir/Sakura/f_00055078.lua:5-11)。

所以：

```lua
f_00055078(nil)
```

等价于：

```lua
f_00055078(2000)
```

随后四路调用全部使用 `2000`：

```lua
f_00054EB1(nil, 0, 2000, 0, nil)
f_00054EB1(nil, 1, 2000, 0, nil)
f_00054EB1(nil, 2, 2000, 0, nil)
f_00054EB1(nil, 3, 2000, 0, nil)
```

这里的 `2000` 是该包装器的统一默认控制值，但不能仅凭包装器本身将其绝对命名成“2000 ms 播放时长”。它进入下游的第三真实参数，后续还会经历通道状态归一化和 `+20` 等处理。

更准确的称呼是：

> **四路环境声共用的控制值，默认 `2000`。**

## 6. 四次下游调用的参数布局

每次调用的形式都相同：

```lua
f_00054EB1(nil, channel, value, 0, nil)
```

| 下游参数 | 固定/变化值 | 作用 |
|---:|---|---|
| 第 1 参数 | `nil` | 不直接指定新的 `se_env/NNN` 资源编号，走状态型环境声路径 |
| 第 2 参数 | `0/1/2/3` | 当前处理的环境声通道编号 |
| 第 3 参数 | `value` | 四路共用的环境声控制值；`nil` 时为 `2000` |
| 第 4 参数 | `0` | 固定的环境声更新模式/分支参数 |
| 第 5 参数 | `nil` | 让下游使用默认音量 `100` |

四次调用分别为：

```lua
f_00054EB1(nil, 0, value, 0, nil)
f_00054EB1(nil, 1, value, 0, nil)
f_00054EB1(nil, 2, value, 0, nil)
f_00054EB1(nil, 3, value, 0, nil)
```

因此，本函数真正控制的不是某一首声音资源，而是：

```text
对 4 路环境声通道执行同一种更新策略
```

## 7. 下游 `f_00054EB1()` 的参数语义

### 7.1 第 2 参数：环境声通道编号

[`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:31-47) 会将第二参数限制到 `0..3`，然后加 `20`：

```lua
if channel < 0 or channel > 3 then
    channel = 0
end
channel = channel + 20
```

因此 `f_00055078()` 的四次调用实际对应：

| 外层传入 | 下游内部通道状态值 |
|---:|---:|
| `0` | `20` |
| `1` | `21` |
| `2` | `22` |
| `3` | `23` |

这四个值不是 Audio syscall 的槽位号，而是环境声系统内部用于保存状态的逻辑编号。

### 7.2 第 3 参数：统一环境声控制值

外层 `value` 作为下游第三参数传入。下游首先把它限制到 `0..3` 的内部控制范围，再加 `20`：

```lua
if value < 0 or value > 3 then
    value = 0
end
value = value + 20
```

因此，如果外层使用默认值 `2000`，按当前反编译逻辑它会进入下游的范围判断。

这里需要特别谨慎：由于 `f_00055078()` 的调用者经常传 `nil`、`3000` 等值，而 `f_00054EB1()` 的参数槽位又受到 Lua-like 导出器编号偏移影响，不能只看导出变量名就断言“第三参数等于最终音量”或“第三参数等于最终播放时长”。

目前最稳妥的结论是：

> `f_00055078()` 将一个统一值送入四路环境声处理函数的第三参数；该值参与环境声通道状态、资源和播放模板选择，具体最终作用由 `f_00054EB1()` 的分支共同决定。

### 7.3 第 4 参数固定为 `0`

第四参数固定为：

```lua
0
```

在 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:156-186) 中，它参与环境声更新模式判断。外层函数固定传 0，说明它选择的是标准环境声更新路径，而不是特殊的其它模式。

### 7.4 第 5 参数固定为 `nil`

[`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:22-30) 会在第五参数为 `nil` 时默认：

```lua
volume = 100
```

随后在实际资源播放分支中使用：

```lua
SoundVol(channel, 100, nil)
```

所以 `f_00055078()` 本身不提供音量调节参数；四路环境声都使用下游默认音量。

## 8. 下游 Sound 操作

当环境声状态判断决定需要实际刷新某一路时，[`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:164-186) 会执行类似：

```lua
SoundStop(channel, 0)
SoundType(channel, 3)
SoundLoad(channel, path)
SoundVol(channel, volume, nil)
SoundPlay(channel, play_mode, nil)
```

其中：

- `SoundStop`：停止当前通道旧内容；
- `SoundType(channel,3)`：设置环境声/SE 类型桶；
- `SoundLoad`：加载选定的 `se_env/NNN` 资源；
- `SoundVol`：设置默认音量或状态参数得到的音量；
- `SoundPlay`：按模式播放。

但是在 `f_00055078()` 的固定调用形式中，第一个下游参数是 `nil`，因此并不是直接指定一个新的 `se_env/NNN` 文件名。它更多是在请求：

> **依据已经保存的环境声状态，重新检查/刷新四路环境声。**

## 9. 与 `f_000550BF()` 的关系

[`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1) 也是四路环境声统一处理函数，结构与 `f_00055078()` 很相似：

```lua
function f_000550BF(value)
    if value == nil then
        value = 2000
    end

    f_00054EB1(nil, 0, value, 0, nil)
    f_00054EB1(nil, 1, value, 0, nil)
    f_00054EB1(nil, 2, value, 0, nil)
    f_00054EB1(nil, 3, value, 0, nil)

    G[273] = true
end
```

两者的主要差异是：

| 函数 | 四路调用 | 额外状态 |
|---|---|---|
| `f_00055078` | 有 | 无 |
| `f_000550BF` | 有 | 最后设置 `G[273]=true` |

因此：

- [`f_00055078()`](Sakura_hcb_ir/Sakura/f_00055078.lua:1) 是纯四路刷新包装器；
- [`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1) 是带“环境声状态已完成/有效”标记的四路刷新包装器。

这说明 `f_00055078()` 更适合作为局部或临时刷新入口，而 `f_000550BF()` 更像正式的环境声状态建立入口。

## 10. 与 `f_000172A9()` 的关系

已有分析表明 [`f_000172A9()`](Sakura_hcb_ir/Sakura/f_000172A9.lua:1) 也会处理 4 路环境声通道，并受 `G[274]` 等状态控制。

三者可暂时区分为：

```text
f_00055078 -> 四路环境声参数化刷新，无额外完成标志
f_000550BF -> 四路环境声参数化刷新，并设置 G[273]=true
f_000172A9 -> 场景清场/重置链中的四路环境声刷新
```

它们底层都可能汇聚到 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1)，但所处的上层状态机阶段不同。

## 11. 调用上下文分析

### 11.1 `f_00037BF7()` 中的调用

[`f_00037BF7()`](Sakura_hcb_ir/Sakura/f_00037BF7.lua:21-33) 的片段是：

```lua
f_00037B23()
f_00055078(nil)
f_000553AA(nil, 1000)
f_0005522A(3000)
f_00055078(3000)
f_00054E2E(3000)
```

这是一段标题/菜单退出或场景收尾初始化链：

1. 先进行场景/界面准备；
2. 用默认 `2000` 刷新四路环境声；
3. 处理另一类音频/语音；
4. 停止主 BGM；
5. 再用 `3000` 刷新四路环境声；
6. 进入 dissolve/过渡控制。

这说明 `f_00055078()` 可以在场景退出或切换期间被多次调用，并且调用参数可能不同。

### 11.2 `nil` 调用

大量剧情调用使用：

```lua
f_00055078(nil)
```

这通常表示：

```text
使用统一默认环境声控制值 2000，刷新四路通道
```

### 11.3 `3000` 调用

在 [`f_00037BF7()`](Sakura_hcb_ir/Sakura/f_00037BF7.lua:28-33) 中，函数随后又被调用：

```lua
f_00055078(3000)
```

这说明参数是由调用方根据当前演出阶段选择的统一控制值，而不是固定只允许 `2000`。

由于下游还会继续归一化该值，`3000` 不应直接理解为“播放 3000 ms”。更准确的是：

> **以 3000 作为本轮环境声刷新模板的输入值。**

### 11.4 与 `BGS010a` 等资源的关系

[`f_0009C609()`](Sakura_hcb_ir/Sakura/f_0009C609.lua:1) 的上下文中可看到：

```lua
f_00055078(nil)
...
BGS010a
```

但 `f_00055078()` 本身不读取 `BGS010a` 字符串，也不直接装载该资源。因此不能把 `f_00055078` 命名为 `load_BGS010a`。

它更可能是在 BGS/环境声状态切换链中，先统一刷新四路环境声，然后由后续逻辑装载或处理其它 BGS 资源。

## 12. 为什么它不是普通“全局音量设置器”

虽然四次调用都使用同一个 `value`，但它并没有把该值直接传给 AudioVol 的音量位置：

```text
f_00055078(value)
    -> f_00054EB1(nil, channel, value, 0, nil)
    -> 下游多重状态判断
    -> 可能 SoundStop / SoundLoad / SoundVol / SoundPlay
```

如果它是简单的全局音量设置器，预期结构应更接近：

```lua
SoundVol(0, value, nil)
SoundVol(1, value, nil)
SoundVol(2, value, nil)
SoundVol(3, value, nil)
```

但实际不是这样。因此正确定位应是：

> **环境声状态刷新器，而不是简单的四通道音量赋值器。**

## 13. 与 BGM 函数的区别

| 特征 | `f_00055078` | `f_000365C8` 等 BGM 包装器 |
|---|---|---|
| 处理通道数 | 4 路环境声通道 | 主 BGM 双槽体系 |
| 资源路径 | 下游根据环境声状态决定 | 固定 `BGM/编号` |
| 是否固定曲目编号 | 否 | 是 |
| 是否设置当前 BGM 编号 `G[215]` | 否 | 间接由 BGM 核心设置 |
| 下游核心 | `f_00054EB1` | `f_0005511C` |
| 典型默认值 | `2000` | 音量默认 `100` |
| 主要用途 | 场景环境声/BGS 同步刷新 | 播放或切换 BGM |

因此不能把 `f_00055078()` 与 [`f_000365C8()`](Sakura_hcb_ir/Sakura/f_000365C8.lua:1) 等固定 BGM 函数归为同一类。

## 14. 语义化伪代码

### 14.1 本函数自身

```lua
function refresh_environment_audio(value)
    if value == nil then
        value = 2000
    end

    for channel = 0, 3 do
        f_00054EB1(nil, channel, value, 0, nil)
    end
end
```

### 14.2 展开下游后的近似流程

```lua
function refresh_environment_audio(value)
    if value == nil then
        value = 2000
    end

    for channel = 0, 3 do
        -- 下游根据 channel 和当前环境声状态决定具体路径
        f_00054EB1(
            nil,       -- 不直接指定新的 se_env 编号
            channel,   -- 0..3
            value,     -- 统一环境声控制值
            0,         -- 标准刷新模式
            nil        -- 默认音量 100
        )
    end
end
```

不能进一步把它简化为四次固定 `SoundLoad`，因为 `f_00054EB1()` 内部会根据 `G[269]..G[272]`、`G[273]`、模式参数和当前资源状态决定是否真正加载或停止。

## 15. 对新剧情注入的意义

### 15.1 保持原作环境声刷新行为

如果新剧情希望沿用 Sakura 的环境声状态机，推荐调用：

```lua
f_00055078(nil)
```

这会使用默认值 `2000`，并依次刷新四路通道。

### 15.2 使用自定义刷新值

可以调用：

```lua
f_00055078(3000)
```

但应把 `3000` 视为下游环境声处理的输入模板值，而不是未经验证的毫秒数或音量百分比。

### 15.3 与 `G[273]` 的注意事项

`f_00055078()` 本身不会设置 `G[273]`。

如果新剧情需要同时建立“环境声已经刷新”的状态标志，应考虑原作对应场景使用的是 [`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1)，而不是仅调用 `f_00055078()`。

### 15.4 不要与主 BGM 停止混淆

环境声刷新不会代替：

```lua
f_0005525F(nil)
```

后者负责停止主 BGM 双槽并清除 `G[215]`；前者负责四路环境声处理。若场景需要完整音频清场，可能需要分别处理主 BGM 和环境声。

## 16. 最终结论

1. [`f_00055078()`](Sakura_hcb_ir/Sakura/f_00055078.lua:1) 是四路环境声统一刷新函数。
2. 它只有一个真实参数，原始栈槽为 `-2`；导出器中的 `a1` 是第一个真实参数的偏移名称。
3. 参数 `nil` 时默认改为 `2000`。
4. 它将同一个值分别传给 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 的通道 `0、1、2、3`。
5. 四次调用固定使用：

   ```lua
   f_00054EB1(nil, channel, value, 0, nil)
   ```

6. 第一个下游参数固定为 `nil`，表示不直接指定新的环境声资源编号，而是走状态刷新路径。
7. 第二个下游参数是环境声通道编号 `0..3`。
8. 第三个下游参数是四路共用的环境声控制值，默认 `2000`；不能仅凭该包装器把它绝对命名为音量或播放时长。
9. 第四个下游参数固定为 `0`，选择标准环境声更新模式。
10. 第五个下游参数固定为 `nil`，因此下游使用默认音量 `100`。
11. 真正的 SoundStop、SoundType、SoundLoad、SoundVol、SoundPlay 操作由 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 根据环境声状态决定。
12. 它与 [`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1) 共享四路刷新骨架，但不设置 `G[273]=true`。
13. 它与 [`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 的主 BGM 双槽停止职责不同。
14. 最准确的功能标签是：

> **以默认值 2000 或调用方给定值，统一刷新四路环境声通道状态的公共包装器。**
