# [`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:1) 逐条反汇编与详细作用解析

## 1. 核心结论

[`f_00097A34()`](Sakura_hcb_ir/Sakura/f_00097A34.lua:1) 是 Sakura 中一套**开场标题/演出字样动画的初始化与播放函数**。

它不是普通的背景加载函数，也不是单纯的淡入函数，而是将以下多个步骤串成一条固定演出流程：

1. 判断模式参数；
2. 停止当前 V3D 运动；
3. 调用 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1) 做一次重型画面过渡状态复位；
4. 停止 `prim 450–464` 范围内的一组运动；
5. 设置开场演出状态 `G[93]`、`G[94]`；
6. 再次停止 V3D 运动并重置过渡状态；
7. 初始化 `prim 480–486` 的 `startmoji_*` 图像；
8. 将这些字样图元设置为透明、可混合，并放到画面中心附近；
9. 通过 [`MotionMoveS2`](../syscall语义数据库/syscall含义详解/18_Motion.md:313) 让字样图元在一段较长时间内进行缩放/变换演出；
10. 通过 [`MotionAlpha`](../syscall语义数据库/syscall含义详解/18_Motion.md:148) 控制字样淡入/淡出；
11. 等待约 `500 ms`；
12. 清理字样图元和相关演出状态；
13. 最后关闭 `G[93]` 并清除 `G[94]`。

最准确的功能标签是：

> **开场标题字样（startmoji）演出初始化、播放与收尾函数。**

## 5. 第一阶段：停止旧 V3D/画面运动并做过渡复位

### 5.1 停止 V3D 运动

当 `P1==1` 后，函数首先准备：

```lua
f_000525B7(0, 0, 0, nil)
```

对应 [`f_00097A34.lua`](Sakura_hcb_ir/Sakura/f_00097A34.lua:9-14)。

[`f_000525B7()`](Sakura_hcb_ir/Sakura/f_000525B7.lua:1) 的第一条有效操作是：

```lua
V3DMotionStop()
```

随后它默认化 V3D 的相关参数，并执行 [`V3DSet`](../syscall语义数据库/syscall含义详解/31_V3D.md:1)。在此调用点，主要作用是先停止上一阶段可能残留的 V3D 运镜。

### 5.2 调用 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1)

随后执行：

```lua
f_000104E8()
```

[`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1) 会完成一轮重型过渡准备：

- 设置 `G[1255]=1`；
- 清理旧 overlay/过渡图层；
- 复位消息框及附加 UI；
- 让出一帧；
- 重置主舞台运动/过渡缓存；
- 刷新环境声；
- 重建画面特效槽位；
- 清理后台演出线程；
- 调用 `f_00050EDB(nil,1,-1,...)`，准备黑色过渡层。

因此本函数不是从任意画面状态直接开始，而是先要求整个 FVP 画面环境回到可控基线。

## 6. 第二阶段：停止 450–464 范围的图元运动

接下来调用：

```lua
f_0006A515(nil)
```

见 [`f_00097A34.lua`](Sakura_hcb_ir/Sakura/f_00097A34.lua:15-17)。

[`f_0006A515()`](Sakura_hcb_ir/Sakura/f_0006A515.lua:1) 会遍历并处理 prim `450` 到 `464`，对每个图元依次执行：

- [`MotionMoveStop`](../syscall语义数据库/syscall含义详解/18_Motion.md:214)；
- [`MotionMoveZStop`](../syscall语义数据库/syscall含义详解/18_Motion.md:365)；
- [`MotionMoveRStop`](../syscall语义数据库/syscall含义详解/18_Motion.md:270)；
- [`MotionMoveS2Stop`](../syscall语义数据库/syscall含义详解/18_Motion.md:313)；
- [`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1)，清理资源、移出父组并置空。

这里的 `450–464` 与后面使用的 `480–486` 并不是同一批图元：

- `450–464`：旧演出/旧标题图层的批量停止和清理范围；
- `480–486`：本次新 startmoji 开场字样演出的图元范围。

### 6.1 设置开场状态

随后：

```lua
G[93] = true
G[94] = true
```

见 [`f_00097A34.lua`](Sakura_hcb_ir/Sakura/f_00097A34.lua:18-21)。

这两个全局值属于开场字样演出状态标记。其精确业务命名无法仅靠本函数完全恢复，但从设置时机可确定：

- `G[93]`：本轮特殊标题/字样演出正在启用；
- `G[94]`：相关开场状态或显示阶段已经建立。

### 6.2 再次停止 V3D 与过渡状态复位

函数随后又执行：

```lua
f_000525B7(0, 0, 0, nil)
f_000104E8()
```

见 [`f_00097A34.lua`](Sakura_hcb_ir/Sakura/f_00097A34.lua:22-27)。

这两个调用与前面同类，但作用是确保在 `G[93]/G[94]` 状态设置之后，旧 V3D/过渡状态再次被清干净。该重复结构说明 startmoji 演出对初始画面基线要求较严格。

## 7. 第三阶段：处理 prim 495 的演出资源

接下来执行：

```lua
f_0009D283(1, -2)
```

见 [`f_00097A34.lua`](Sakura_hcb_ir/Sakura/f_00097A34.lua:28-31)。

[`f_0009D283()`](Sakura_hcb_ir/Sakura/f_0009D283.lua:1) 处理 prim `495`，并同步设置全局状态 `G[117]`：

- 在通常启用模式下装载资源 `EF_e17_1`；
- 设置 alpha `220`；
- 设置 blend；
- 将 prim `495` 加入 group `11`；
- 在关闭模式下将 prim `495` 清理掉；
- 启用路径最终设置 `G[117] = 1`，关闭路径设置 `G[117] = 0`；`G[117]` 会影响后续特殊文本/UI 的布局与时序分支。

本调用第二参数为 `-2`，因此会清理旧 prim `495` 后跳过 `EF_e17_1` 的重新装载；但第一个参数仍为 `1`，所以函数最终仍设置 `G[117] = 1`。准确地说，这是“**特殊文本/UI 状态启用、EF_e17_1 图像层关闭**”的预设，而不是普通图层加载。

## 8. 第四阶段：初始化 7 个 startmoji 图元

### 8.1 图元与资源对应关系

本函数实际初始化以下 7 个 prim：

| Prim | 资源名 | 语义标签 |
|---:|---|---|
| `480` | `startmoji_t10` | startmoji 第一组/第一层 |
| `484` | `startmoji_t10` | startmoji 第一组/第二层 |
| `481` | `startmoji_t11` | startmoji 第二组/第一层 |
| `485` | `startmoji_t11` | startmoji 第二组/第二层 |
| `482` | `startmoji_t20` | startmoji 第三组/第一层 |
| `486` | `startmoji_t20` | startmoji 第三组/第二层 |
| `483` | `startmoji_t40` 或同类补充层 | 当前函数中出现的额外字样层/资源层 |

当前导出片段中 `483` 的资源名称部分需要结合完整文档/原始字符串表进一步核对；核心演出明确围绕 `480–486` 这一连续 prim 区间展开。

### 8.2 每个图元的共同初始化模板

对 `480`、`484`、`481`、`485`、`482`、`486` 以及对应的补充图元，函数重复执行：

```lua
f_000373A5(prim, resource_name, 5, nil)
PrimSetAlpha(prim, 0)
PrimSetBlend(prim, 1)
PrimSetOP(prim, 640, 350)
```

实际 `PrimSetOP` 的计算是：

```lua
x = 1280 / 2 = 640
y = 720 / 2 - 10 = 350
```

对应代码见 [`f_00097A34.lua`](Sakura_hcb_ir/Sakura/f_00097A34.lua:42-167)。

### 8.3 [`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1) 的作用

[`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1) 会：

1. 根据资源类别选择资源目录；
2. 调用 [`f_00037294()`](Sakura_hcb_ir/Sakura/f_00037294.lua:1) 设置图元资源；
3. 调用 [`f_00037345()`](Sakura_hcb_ir/Sakura/f_00037345.lua:1) 设置附加属性；
4. 在第三参数有效时设置图元属性编号。

本函数每次传入第三参数 `5`，因此这些 startmoji 图元都使用同一套资源类别/属性模式。

### 8.4 初始透明度

每个 startmoji prim 随后都执行：

```lua
PrimSetAlpha(prim, 0)
```

这说明标题字样在刚初始化时完全不可见，后面需要靠 [`MotionAlpha`](../syscall语义数据库/syscall含义详解/18_Motion.md:148) 淡入。

### 8.5 初始 blend

每个图元执行：

```lua
PrimSetBlend(prim, 1)
```

说明这些字样图元使用混合显示，而不是不透明覆盖。对于文字/透明 PNG 类资源，这是正常的透明合成设置。

### 8.6 初始 OP

每个图元都执行：

```lua
PrimSetOP(prim, 640, 350)
```

在 1280×720 虚拟画布下，中心点通常是 `(640,360)`；这里 Y 为 `350`，即略微上移约 10 像素。因此这些字样图元的变换参考点位于画面中心偏上位置。

## 9. 第五阶段：startmoji 图元的 MotionMoveS2 运动

### 9.1 对象

随后函数对多组图元调用 [`f_000524BB()`](Sakura_hcb_ir/Sakura/f_000524BB.lua:1)，例如：

```lua
f_000524BB(
    480,
    1200, 900,
    1200, 900,
    duration,
    1,
    nil,
    nil,
    nil
)
```

以及：

```lua
f_000524BB(
    484,
    1200, 900,
    1200, 900,
    duration,
    1,
    nil,
    nil,
    nil
)
```

同类调用还作用于 `481/485` 和 `482/486`。

### 9.2 下游 syscall

[`f_000524BB()`](Sakura_hcb_ir/Sakura/f_000524BB.lua:1) 最终调用：

```text
MotionMoveS2(prim, src_x, src_y, dst_x, dst_y, duration, typ, reverse)
```

并根据等待标志决定是否轮询：

```text
MotionMoveS2Test(prim)
ThreadNext()
```

见 [`f_000524BB.lua`](Sakura_hcb_ir/Sakura/f_000524BB.lua:42-69)。

### 9.3 运动参数

这些调用中的位置参数大体为：

```text
起点：(1200,900)
终点：(1200,900)
```

表面上 XY 起点和终点相同，因此这里不应简单解释为普通 XY 平移。`MotionMoveS2` 的 `S2` 是缩放/比例变换类运动接口，传入的坐标/数值更多地参与图元的缩放中心和变换参数计算。

结合后续持续时间计算和 alpha 动画，可判断这里是在为 startmoji 建立：

> **以画面中心附近为参考点的缩放/变换型标题字样演出。**

### 9.4 持续时间

第一组 `480/484` 的 duration 由多项常量累加而成：

```text
4500 + 2500 + 3000/2 + 15 + 100 + 15 + 1500
= 10130 ms
```

第二组 `481/485` 使用相同的约 `10130 ms` 时长。

第三组 `482/486` 的 duration 为：

```text
3500 + 2500 + 2000 + 4000/2 + 15 + 100 + 15 + 2000
= 12130 ms
```

这些值都远大于普通短动画，因此它们更像一套持续约 10–12 秒的开场标题演出，而不是一次瞬时 UI 淡入。

## 10. 第六阶段：startmoji 图元 alpha 动画

在 MotionMoveS2 运动准备后，函数调用 [`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 设置 alpha。

### 10.1 第一组淡入

```lua
f_000520EE(480, 0, 255, 4500, nil, nil, nil, nil)
f_000520EE(484, 0, 255/6, 4500, 1, nil, nil, nil)
```

[`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 最终调用：

```text
MotionAlpha(prim, src_alpha, dst_alpha, duration, typ, reverse)
```

因此：

- prim `480`：在 `4500 ms` 内从 alpha `0` 淡入到 `255`；
- prim `484`：在 `4500 ms` 内从 alpha `0` 淡入到约 `42`；
- 后者可能是叠加的低强度辅助层。

### 10.2 第二组淡入

同样对 `481/485` 执行：

```text
481：0 -> 255，4500 ms
485：0 -> 255/6，4500 ms
```

### 10.3 第三组淡入

对 `482/486` 执行：

```text
482：0 -> 255，3500 ms
486：0 -> 255/6，3500 ms
```

因此 480/481/482 更像主字样层，484/485/486 更像低 alpha 的叠加/阴影/特效层。

### 10.4 MotionAlpha 的等待方式

[`f_000520EE()`](Sakura_hcb_ir/Sakura/f_000520EE.lua:1) 会根据参数决定是否执行 `MotionAlphaTest` 轮询。当前 startmoji 调用中多数尾部参数为 `nil`，因此这些 alpha 动画通常并行启动，而不是每一次调用都阻塞等待。

## 11. 第七阶段：500 ms 等待与淡出

完成第一轮 alpha 设置后，函数调用：

```lua
f_000376B4(500, nil)
```

见 [`f_00097A34.lua`](Sakura_hcb_tool_test/Sakura/f_00097A34.lua:304-306)。

[`f_000376B4()`](Sakura_hcb_tool_test/Sakura/f_000376B4.lua:1) 是一个定时等待函数，默认允许输入提前结束。它在没有输入时执行约 `500 ms` 的等待。

之后对 `480/484/481/485` 执行：

```lua
MotionAlpha(prim, current_or_nil, 0, 4500, ...)
```

也就是在 `4500 ms` 内逐渐淡出。

随后又对 `482/486` 执行 `3500 ms` 的淡出。

因此开场字样演出的可见阶段大致是：

```text
初始透明
→ 4.5 秒主字样淡入
→ 保持/叠加演出
→ 500 ms 节奏点
→ 4.5 秒淡出
→ 第三组以 3.5 秒淡出
```

注意：`f_000376B4(500,nil)` 是一处明确的短等待，但完整可见时序还叠加了前面并行启动的 MotionMoveS2 和 MotionAlpha 动画。

## 12. 第八阶段：音频/过渡同步

在字样淡出后，函数计算：

```lua
2950 + 6000 + 1500 = 10450
```

随后调用：

```lua
f_0005525F(10450)
f_00055A57(8950, nil, nil, nil, nil, nil, nil)
```

[`f_0005525F()`](Sakura_hcb_ir/Sakura/f_0005525F.lua:1) 是 [`f_0005522A()`](Sakura_hcb_ir/Sakura/f_0005522A.lua:1) 的包装器，属于音频停止/淡出相关链。

[`f_00055A57()`](Sakura_hcb_ir/Sakura/f_00055A57.lua:1) 则是 dissolve/过渡控制包装器，会：

- 设置 `G[23]`；
- 调用下游 dissolve；
- 等待 dissolve；
- 清理 prim `186/187/190/191` 等过渡图层。

因此，startmoji 字样淡出之后，函数还会将声音和画面过渡状态一起收束。

## 13. 第九阶段：最终场景收尾

函数最后执行：

```lua
f_000520EE(481, nil, 0, 4500, nil, nil, nil, nil)
f_000520EE(485, nil, 0, 4500, 1, nil, nil, nil)
f_000104E8()
f_000529CD()
f_000525B7(nil, nil, nil, nil)
f_000376B4(5000, nil)
f_0009CF45(0, nil, nil, nil, nil)
f_0009D283(0, nil)
f_0006A76F(nil)
G[93] = true
G[94] = nil
```

### 13.1 再次淡出 481/485

`481` 和 `485` 的 alpha 被设为 `0`，时间为 `4500 ms`，用于清除第二组字样层。

### 13.2 再次执行 [`f_000104E8()`](Sakura_hcb_ir/Sakura/f_000104E8.lua:1)

这会再次执行重型过渡复位，并准备黑色过渡层。它的作用是把 startmoji 演出结束后的画面环境恢复到普通剧情继续所需的状态。

### 13.3 [`f_000529CD()`](Sakura_hcb_ir/Sakura/f_000529CD.lua:1)

执行：

```lua
MotionAlphaStop(187)
V3DMotionStop()
```

作用是停止 prim 187 的 alpha 动画，并确保 V3D 运动彻底停止。

### 13.4 再停止 V3D

```lua
f_000525B7(nil,nil,nil,nil)
```

再次停止 V3D 并写入默认 V3D 状态。

### 13.5 5 秒等待

```lua
f_000376B4(5000, nil)
```

这是一个较长的、允许输入跳过的等待，通常意味着演出结束后还要保留一段时间让玩家观看或等待背景音乐/画面状态完成。

### 13.6 清理 prim 493

```lua
f_0009CF45(0,nil,nil,nil,nil)
```

该调用转发给 [`f_0009CAC2()`](Sakura_hcb_ir/Sakura/f_0009CAC2.lua:1)，处理固定特效图元 `493` 的清理/状态切换。prim `495` 并不是该函数当前反编译结果中的操作对象。

### 13.7 清理 prim 495 的特殊显示

```lua
f_0009D283(0,nil)
```

第二次使用模式 `0`，走 prim 495 的清理路径，确保辅助演出图层不残留。

### 13.8 清理 480–492 图元运动

```lua
f_0006A76F(nil)
```

[`f_0006A76F()`](Sakura_hcb_ir/Sakura/f_0006A76F.lua:1) 会遍历：

- prim `480–492`：停止 `MotionMove`、`MotionMoveZ`、`MotionMoveR`、`MotionMoveS2`，并通过 [`f_00037421()`](Sakura_hcb_ir/Sakura/f_00037421.lua:1) 清理图元；
- 具体范围依据入参是否为 `0` 分成 `480–492` 或 `480–488` 的路径。

这里传入 `nil`，下游默认进入完整的 `480–492` 清理范围。

### 13.9 最终全局状态

最后：

```lua
G[93] = true
G[94] = nil
```

`G[94]` 被清除，表示 startmoji 演出阶段结束；`G[93]` 仍为 `true`，可能代表更高层的开场/标题环境仍保持启用，或者是原作故意保留的全局标题状态。

## 16. 最终判断

### 16.1 它不是普通的背景加载函数

虽然它使用 [`f_000373A5()`](Sakura_hcb_ir/Sakura/f_000373A5.lua:1) 装载图像，但资源名是：

```text
startmoji_t10
startmoji_t11
startmoji_t20
```

这些显然是标题/开场字样资源，而不是普通场景背景。

### 16.2 它不是单一的文字显示函数

它没有调用 [`TextPrint`](../syscall语义数据库/syscall含义详解/26_Text.md:139)，而是把字样作为图像 prim 载入，再使用：

- `PrimSetAlpha`；
- `PrimSetBlend`；
- `PrimSetOP`；
- `MotionMoveS2`；
- `MotionAlpha`。

因此这是**图像化标题字样动画**，不是正文文本系统。

### 16.3 它是演出控制器

它同时控制：

- V3D 运动；
- dissolve/过渡层；
- 标题字样图元；
- alpha 淡入淡出；
- 缩放/变换运动；
- 音频收束；
- 辅助 prim `495`；
- 后台图元运动停止；
- 全局演出状态。

因此它应被理解为：

> **一次完整的开场标题字样演出控制器，而不是某个单一 prim 的动画函数。**
