# [`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 逐条反汇编与作用解析

## 1. 核心结论

[`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 是一个无参数、无局部变量的极薄状态函数。它唯一的有效业务操作是：

```lua
G[273] = nil
```

因此它不是声音播放、停止、淡入淡出或资源加载函数，而是：

> **清除环境声系统的“已刷新/暂时锁定”状态，使后续环境声更新重新允许执行。**

它与以下两个函数构成对称关系：

```lua
f_000550BF(value) -- 刷新四路环境声，并设置 G[273] = true
f_0005510A()      -- 直接设置 G[273] = true
f_00055113()     -- 清除 G[273]，即 G[273] = nil
```

## 4. 逐条分析

### 4.1 `init_stack`

```text
0x00055113: 01 00 00
```

反汇编：

```text
init_stack args=0, locals=0
```

含义：

- 函数没有外部入参；
- 函数没有需要分配的局部变量；
- 后续操作完全固定，不依赖调用者传入值。

---

### 4.2 压入 `nil`

```text
0x00055116: 08
```

反汇编：

```text
push_nil
```

这条指令为下一条全局写入准备值 `nil`。

---

### 4.3 清除 `G[273]`

```text
0x00055117: 15 11 01
```

反汇编：

```text
pop_global index=273
```

效果：

```lua
G[273] = nil
```

该操作不是把 `G[273]` 写成 `0`，而是写成真正的 `nil`。这一区别很重要，因为下游代码使用的是与 `true` 的比较：

```lua
if G[273] == true then
    -- 跳过环境声更新路径
end
```

清为 `nil` 后，该判断不成立，后续更新可以再次进入。

---

### 4.4 返回

```text
0x0005511A: 04
0x0005511B: 04
```

两条都是 `ret`。第一条是正常返回，第二条是函数边界后紧邻的冗余返回入口，不代表存在第二条业务路径。

## 5. `G[273]` 的完整状态链

要理解 [`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1)，必须结合 [`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1) 和 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1)。

### 5.1 [`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1)：刷新后置为 true

[`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1) 会连续调用四次：

```lua
f_00054EB1(nil, 0, value, 0, nil)
f_00054EB1(nil, 1, value, 0, nil)
f_00054EB1(nil, 2, value, 0, nil)
f_00054EB1(nil, 3, value, 0, nil)
```

随后执行：

```lua
G[273] = true
```

所以它完成的是：

```text
四路环境声刷新
→ 标记环境声状态已完成/有效
```

### 5.2 [`f_0005510A()`](Sakura_hcb_ir/Sakura/f_0005510A.lua:1)：单独置为 true

[`f_0005510A()`](Sakura_hcb_ir/Sakura/f_0005510A.lua:1) 本身只执行：

```lua
G[273] = true
```

它不刷新四路声音，而是直接设置同一个状态标志。因此它可以理解为：

> **直接声明当前环境声状态已经有效，或禁止后续重复刷新。**

### 5.3 [`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1)：清除 true 状态

[`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 执行：

```lua
G[273] = nil
```

它把环境声系统从“已处理/锁定”状态切回“未处理/允许重新判断”状态。

## 6. [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 如何使用 `G[273]`

[`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 是实际处理环境声通道的函数。其关键分支是：

```lua
if channel_state_is_20_or_21_or_22_or_23 then
    if G[273] == true then
        goto finish
    end

    -- 执行环境声更新
    -- SoundStop
    -- SoundType
    -- SoundLoad
    -- SoundVol
    -- SoundPlay
end
```

对应导出结果中的 [`f_00054EB1.lua`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:67-187)：

- 先检查 `G[273]`；
- 如果为 `true`，直接跳到收尾；
- 如果不是 `true`，才继续执行通道状态比较、声音停止/载入/音量/播放等逻辑。

因此，`G[273]` 的具体效果可以确定为：

> **当 `G[273] == true` 时，环境声处理函数的部分重复更新路径会被短路。**

而 [`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 清除这个标志，就是让下一次 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 不再被该短路条件拦截。

## 8. 与 `G[273] = 0` 的区别

这里不是：

```lua
G[273] = 0
```

而是：

```lua
G[273] = nil
```

在当前下游比较中，两者都可能使 `G[273] == true` 不成立，但语义上不同：

| 写入值 | 可能状态含义 |
|---|---|
| `true` | 环境声刷新完成/缓存有效/暂时跳过重复更新 |
| `nil` | 清除完成标志/使状态失效/允许重新刷新 |
| `0` | 数值型关闭或其他模式值；不应自动等同于 nil |

[`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 使用 `nil`，表明它更像“失效/未设置”操作，而不是简单的数值开关关闭。

## 11. 最终结论

1. [`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 无入参、无局部变量、无下游调用。
2. 它唯一的有效指令是 `pop_global 273`，将 `G[273]` 写为 `nil`。
3. `G[273]` 被 [`f_00054EB1()`](Sakura_hcb_ir/Sakura/f_00054EB1.lua:1) 读取，用于决定是否跳过部分环境声重复处理。
4. [`f_000550BF()`](Sakura_hcb_ir/Sakura/f_000550BF.lua:1) 在四路环境声刷新后将 `G[273]` 设为 `true`；[`f_00055113()`](Sakura_hcb_ir/Sakura/f_00055113.lua:1) 则将其清除。
5. 因此，`f_00055113()` 不直接停止声音，而是清除环境声状态缓存/锁定标志，使后续流程能够重新进行环境声状态判断与刷新。
6. 它经常出现在正文、转场、dissolve 或其他演出函数之后，符合“当前段落结束后解除环境声刷新抑制”的用途。

最准确的功能标签是：

> **环境声刷新状态失效/解锁函数**。
